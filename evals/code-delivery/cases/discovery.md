# 技能选择

仅根据 catalog.md 的技能名称和 description，判断下面各任务需要哪些技能，分别说明首要技能及确有需要的协作技能；没有匹配技能可以直接说明。不要读取技能正文、实际工程或其他资料，不执行任务。

客户端题设均为 Unif RN 工程；第 7 项的测试也来自该工程。

1. 已在隔离分支，仅修改采用目标架构的客户端组件 props 与样式；无契约设计、审查或提交请求。
2. 只读审查一个未提交代码变更是否符合已有契约，重点检查真实消费者和测试；没有新职责设计。
3. 设计跨客户端与服务端的公共契约与状态边界，不实现文件、不执行 Git 操作。
4. 用户只要求提交刚完成的代码；不要推送或合并。
5. 用户授权在最新 CI 通过后合并 MR，之后清理已合并的分支。
6. 业务用户要求“开始今天的拜访”，不是代码开发请求。
7. 只运行用户给定的一条测试命令，不改文件，不整理交付流程。
8. 修改仍沿用旧架构的客户端文件，工程没有采用或迁入这套目标架构规范。

技能选择本身是否表示已经取得提交、合并或对外发布评论的授权？如果可用技能只有 unif-rn-project 或只有 unif-code-delivery，完成相应任务是否必须安装另一插件中的同类技能？只基于发现材料说明能判断到的范围，不假装读过正文或验证过宿主。
