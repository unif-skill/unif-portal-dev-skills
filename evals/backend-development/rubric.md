# 后端开发评测依据

依据最终候选技能、规范来源和实际输出核对，不按关键词数量评分。案例见 [职责组织](cases/module-boundaries.md) 与 [触发范围](cases/scope.md)。

- 目录方案基于已存在的职责；提示词、任务选择、模型技术协议和运行协调各自清楚。
- 公共入口精简，底层不导入应用入口；原有注入边界能用于真实消费者及测试替身。
- 单一生命周期与事务保持所有权，未为行数引入多个状态持有者、隐式重试或额外模型调用。
- 纯拆分核对最终文本、生成资源、子进程导入、原事务与现有回归；语义修正有单独依据。
- 后端实现任务取得后端规范；状态查询与 Portal 排版不触发无关开发。
- 静态校验、离线执行、真实模型/业务、发布和安装按实际证据表达。

记录所用版本、输入、可用工具与实际执行结果。只有真实基线与候选执行才能比较行为变化；本案例文件不声称已完成该对照。
