# RN 与 Python 评测判据

本文件只供评测者使用，不提供给被测上下文。[独立行为题](rn-python-behavior-cases.md)检查六项技能各自取得规则并应用到任务的能力；[自动触发题](rn-python-trigger-cases.md)与[合成素材](rn-python-trigger-fixtures.json)检查宿主面对自然请求时实际加载的入口。两组证据分别记录，不用目录格式或最终答案代替实际读取。

## 独立行为组

按组装说明为每题提供公共规范、所选业务技能和单题 `TASK.md`，在全新上下文运行。六题只读判断，表中验证项检查回答是否提出正确对象和验收方案，不要求实际运行工程。判据复用[独立消费判据](rubric.md)与[状态归属判据](../architecture-design/rubric.md)，下表列出本组六个实例的适用重点；不按关键词或固定实现写法评分。

| 题号 | 判据来源 | 必须核对的判断与边界 |
|---|---|---|
| B1 | state-identity U1、U2 及实际影响对应的验证要求 | 区分正文恢复与默认记录身份；本地映射缺失不证明服务端不存在。默认唯一性由所属服务端原子取得及数据库约束保护，两个入口核对实际接线；普通台账不受该唯一性限制，失败不创建替代记录。保留历史数据并说明缺失工程依据。 |
| B2 | 独立消费 A | 按技能指引取得状态及测试规则，执行真实查询、状态所有者和消费者，仅替换外部边界；同 `ownerId` 重新登录不恢复旧操作。覆盖迟到结果不写入新会话和当前有效响应正常工作，区分替身、服务、平台与设备证据。 |
| B3 | 独立消费 E | 识别取消接保存违背未变契约及取消测试保护缺失；真实页面接线和副作用断言不能被组件渲染替代。缺源码时不虚构位置或已落库事实，审查不扩大为修复、执行或发布评论。 |
| B4 | state-identity U2、U4 | 进程内锁不能保护双进程业务唯一性，默认记录的所有创建入口共用原子契约与数据库约束；不能限制普通记录或覆盖已有内容。历史冲突不擅自删并，真实数据库、进程、重试和事务证据与书面方案分开。 |
| B5 | 独立消费 G | 不接受整体替换创建函数、单字典或固定成功值作为持久化证明。运行真实创建、冲突处理和消费者，分别核对数据库约束、两进程并发、事务、重启与失败语义；不删除已有记录或扩展业务。 |
| B6 | 独立消费 H | 指出原 SQL、参数和异常文本日志以及取消跳过事务收尾的问题；具体泄露后果和资源状态需工程证据。异常包装本身不必然错误，应检查原因链和安全诊断是否丢失；RN Jest 不证明后端事务或数据库验收。 |

六题均提供业务技能及 unif-platform-rules。必要的平台依据应可从指定主题取得；确实缺失的业务或 SDK 事实仅限制依赖部分。记录真正读取的正文与重复读取，分别判断规则可达、决策正确和验证边界；未运行实现不得声称业务已通过。

## 自动触发组

固定技能版本、目录摘要、模型与推理设置、宿主和外部技能条件。先核对六项当前名称、description 与可访问路径已被宿主提供；未发现、被禁用或正文不可访问属于环境缺口，不直接算模型漏触发。每题新建上下文，只发送本题自然请求与通用执行边界，不预读正文、不附判据，不为得到预期结果隐藏其他技能或追加加载提示。

触发须有实际读取当前技能正文并成功返回的工具记录，或等价的宿主加载事件。shell 和文件读取 API 均可提供证据；仅提到名称、自称使用、列目录或最终答案正确都不足以证明加载。读取失败、截断、权限歧义和补读分别保留，无法确认正文进入上下文时标为证据不足。

下表目标仅指六个 RN／Python 开发、测试与审查技能。正例应加载对应入口，另五项不因同一项目或共同规则而自动加入；负例不进入这六项。额外读取需人工区分工作入口与确有缺口的资料提供者，不能按总技能数机械判错。其他平台及通用技能按任务实际需要选择。

| 题号 | 目标入口 | 任务边界与必要判断 |
|---|---|---|
| P1 | `unif-rn-dev` | 定位无登录生命周期校验的写回；账号相同不恢复旧资格。只排查，不启动变更审查或测试计划。 |
| P2 | `unif-rn-test` | 固定成功替身不覆盖真实查询；验证同账号不同生命周期、迟到结果及正常响应，保留实际消费者。只给测试评估。 |
| P3 | `unif-rn-review` | 指出页面 `onCancel` 接到 `save` 违反取消契约及行为保护缺失；不把调用保存等同已证实落库，不执行修复。 |
| P4 | `unif-rn-test` | 仅运行指定 Node 用例，报告真实结果和纯逻辑覆盖范围；不推广为 RN 渲染、原生或设备通过。 |
| P5 | `unif-python-dev` | 根据给定事务契约定位异常／取消跳过收尾；未确认提交时尝试回滚，保证必要关闭有机会执行，保留原失败及业务写入次数。只排查说明。 |
| P6 | `unif-python-test` | 固定创建替身、进程内锁和单字典不证明双进程唯一性；核对真实对象、数据库约束、事务与记录数，保护普通记录及已有数据。并发响应未定义时不自行要求两次均成功。 |
| P7 | `unif-python-review` | 明确日志 diff 的 `sql`、`params` 违反给定白名单；合成占位值不证明真实泄露。不审查客户端或执行修复。 |
| P8 | `unif-python-test` | 仅运行指定 unittest 命令并如实报告，区分纯逻辑与服务、数据库和业务验证。 |
| N1 | 无 | 仅回答 RN 包版本与已提供 API 语义，不转为开发、测试或实现审查。 |
| N2 | 无 | 仅解释 Python 配置与接口事实，不查询线上状态或启动研发阶段。 |
| N3 | 无 | 只润色 RN 使用文案，保留公开名称、授权输入和释放语义。 |
| N4 | 无 | 只润色 Python 使用说明，保留参数、取消等待和结果未确认的含义。 |
| N5 | 无 | 排查未采用 Unif 规范的 RN 应用，不强加 Unif 企业入口。 |
| N6 | 无 | 排查未采用 Unif 规范的 Python 服务，不因语言相同加载企业入口。 |
| N7 | 无 | 只审查原生鸿蒙变更，可采用鸿蒙审查入口，不进入 RN 或 Python 阶段。 |
| N8 | 无 | 按业务请求说明账号、客户和任务缺口，不启动工程阶段或写入业务数据。 |
| N9 | 无 | 只设计共同契约，可采用 `unif-architecture-design`；不将职责和输入输出设计扩大为源码实现、测试或变更审查。 |

P4 在本题素材目录运行 `node --test tests/counter.test.mjs`，需要支持 `node:test` 的 Node.js。P8 运行 `python3 -B -m unittest discover -s tests -v`，只用 Python 标准库，`-B` 避免字节码写入。两题无需安装依赖、联网或连接数据库，均只验证一个纯逻辑用例。运行环境不可用时保留入口加载证据，将命令执行另记为未完成；其他题不运行工程命令。

## 证据与回归

- 输入、素材、技能与外部指令在执行前冻结；记录实际模型、宿主、目录暴露、工具调用与返回、原始回答及未取得依据。任务判断与触发分别评阅：正确答案没有加载记录不算触发，选对技能但越权或误判也不算整题满足。
- 全新子代理不得继承作者讨论、判据或历史答案；记录仍存在的宿主规则和工具，不把访问范围约束描述为操作系统级隔离。显式独立消费、仅描述选择和隐式加载分别报告。
- 出现权限歧义、工具错误或疑似漏触发时，先核对环境和完整记录。需要澄清执行边界则另建运行版本，保留首次结果；外部条件改变不能称为严格同条件的技能改善。对可复现偏差再提出最小候选，已满足项只作回归要求。
- 只使用套餐内额度，不例行查询。出现额度或积分提示时做必要核查；不能确认可用套餐额度则停止，不通过付费 API、其他会话或自动化绕过限制。
- 原始输入输出、日志和个人运行环境留在仓库外或忽略的本地 `runs`，不回写历史。少量样本不证明生产准确率、长期自动触发、跨模型稳定性或 Token 收益；脚本、模型、服务、设备和业务验收分层记录。
