# 架构、交付与六库能力评测判据

范围版本说明：本组 N10 保留原 RN 能力范围下的排除预期，用于复现旧基线。库能力扩展原生鸿蒙后，该排除预期不再适用于双平台候选；改用[鸿蒙库 HN1](../library-skills/harmony-library-cases.md)及其独立判据检查真实原生 API 查询。原题、素材和历史结果不回写，不能将授权范围变化计为旧版模型错误或技能收益。

本文件只供评测者使用，不交给作答上下文。[独立行为题](capability-behavior-cases.md)检查指定技能的资料应用，[自动触发题](capability-trigger-cases.md)及[素材清单](capability-fixtures.json)检查自然请求下的实际入口；两组分别记录，不以目录格式、名称提及或最终答案替代加载证据。

## 独立行为组

每题提供对应业务技能、平台规范技能与题内素材，按现行来源判据逐项核对。表中验证要求检查回答是否选择了正确对象与方法；本组未授权实际运行工程。

| 题号 | 判据来源 | 本题必要判断 |
|---|---|---|
| B1 | [架构 review A1–A3/B1–B2/C1](../architecture-design/rubric.md) | 完成前只读定位不能用可能创建的接口代替；覆盖无记录、多候选及查询范围不足，不猜日期或制造引用。禁访／配置未知不要求假坐标。保持业务成功码与字段映射，不顺带重试；验证真实适配与必要消费者，公共语义变化时扩大范围。私有提取沿用已有授权，不重启设计或重复测试。 |
| B2 | [交付 D1–D5](../code-delivery/rubric.md) | 保留混合工作区和同事修改，只暂存授权内容；使用当前工程门禁，定向结果不替代完整检查。合并等待当前 head 的 required，复用有效条件授权，不顺带发布。squash 清理按内容及服务端记录判断，核对 tip 和占用，保留 active；书面命令不算执行。 |
| B3 | [独立消费 C](rubric.md) | 实际取得 organization.json、包命名、GitHub 和发布资料；准备工程内配置，组织值、Pages 与三项停用文件范围准确。凭据不入文件，工具不依赖技能缓存路径，RN 资产不直接套到鸿蒙或 Python；准备不扩大为远端操作。 |
| B4 | [库能力 A](../library-skills/rubric.md) | 从固定版本确认主题和字体公开出口；应用倍率只在所属出口缩放一次，区分屏幕适配与系统字号。追踪真实文字消费者的最终属性，不凭同时使用两个 hook 判定重复；保留大字号与布局验证。 |
| B5 | [库能力 B](../library-skills/rubric.md) | 核对 Composer/Attachments 实际类型、回调参数和状态范围；草稿、附件集合、上传、发送及文件清理由应用既有能力持有。不能虚构上传／重试接口、自动清草稿或把回调返回当业务成功；缺少消费应用时限定接线结论。 |
| B6 | [库能力 C](../library-skills/rubric.md) | 公开组件、属性与 SVG 源／清单／生成流程分开；普通消费不运行生成器。新增图形维护唯一源、公开出口与真实消费者，保留 SVG 校验和无障碍；鸿蒙目标缺失或未授权时明确待同步，不能宣称双端完成。 |
| B7 | [库能力 D](../library-skills/rubric.md) | 核对 useCamera、holder 与 open；success 只交付已选临时媒体，不表示上传成功。交付前取消／卸载／替换与交付后责任分开；上传仍在读取时不能删除，迟到或不采用的成功结果也需明确归属。 |
| B8 | [库能力 E](../library-skills/rubric.md) | 区分 Scanner、HmsScanView 与 decodeImage；图片识别不申请相机权限，借用文件到 Promise 结算或释放回调。空数组不掩盖技术错误；手电请求与实际状态分开，平台文档／Mock 不替代原生与设备验证。 |
| B9 | [库能力 F](../library-skills/rubric.md) | 真实同意后初始化，核对配置保护与原生接线；controller/host 同实例同窗口。SDK 开始后关闭呈现不等于撤销，success 限有效回执；埋点交接、SDK 结果和业务完成不混同。 |

先核对实际读取与公开符号，再评阅决策，不按关键词或固定代码形状判分。需要的规则应能按业务技能指引从平台规范或专项材料中取得；外部业务或 SDK 事实由题内版本材料支持，缺失只限制依赖部分。保留重复读取、工具失败及证据边界，不将显式给出技能的作答称为隐式触发。

## 自动触发组

固定技能版本、模型与推理档位、宿主目录及外部指令、工具权限和素材摘要。先确认八项目标的当前名称、description 与可读路径已被宿主提供；未发现、被禁用或正文不可读属于环境缺口。每题新上下文，只发送该题请求与通用边界，不追加加载提示或隐藏其他技能来迎合预期。

加载证据须是实际成功返回的技能正文或等价宿主事件，shell 和文件读取 API 均可。列目录、提及名字、自称使用或回答正确均不足以证明加载。读取失败、截断及补读分别保留；无法确认正文进入上下文时标为证据不足。当前上下文已具备所需正文时，不要求为了留痕重复加载。

下表只约束架构、交付及六库能力这八项。额外技能按真实任务需要人工判断；共同资料的必要读取与新增工作入口分开，不能按总加载数机械判错。题设只读说明不扩大为开发、测试执行或交付操作。

## 记录与回归

- 输入和源修订先冻结。保存原始请求、实际目录暴露、读取回执、回答和逐项判断；正确答案未加载不算触发，加载正确但越权或判断错误也不算整题满足。
- 全新上下文不继承作者讨论、判据或此前回答。宿主规则和工具仍属外部条件；读取范围约束不等于操作系统隔离。没有控制组的单次作答不能证明某条技能的因果收益。
- 工具失败、材料缺口或疑似漏／过度触发先核对完整记录。需要调整题面边界时另记输入版本；同条件复现后再提出候选，首次异常不得删除。候选比较保持同题、模型、版本资料及权限，既有满足项只算回归保持。
- 本组全部为只读模型任务；Git 命令建议、阅读测试源码、Mock 或文档支持声明均不代表实际提交、测试、构建、设备或业务通过。脚本校验、模型行为、宿主加载和真实工程结果分层报告，不编造通过率或 Token 收益。
- 使用套餐内额度，不例行查询；出现额度或积分提示时核查，不能确认可继续使用套餐额度则停止，不通过其他会话、代理或付费 API 绕过。
- 原始运行记录、个人路径与账号环境保存在仓库外或忽略的本地 runs；现行题干与判据纳入版本管理，历史 runs 不回写。题库只在显式评测时使用，不加入技能默认加载资料。
