# 助手接入独立行为题

仅提供题干与指定技能的完整目录；不提供判据、历史回答或其他工程。书面设计与实际工程运行分别记录。

## A：开发

Unif Agent 现有 api、core、db、services、schemas、utils。services/agent 负责小U路由，services/execution 负责租约和任务状态，services/attachments 负责文件准备，services/clients/marketing.py 负责营销 HTTP 通信。Host 直接判断订单入口并处理营销响应。现在希望每个助手的能力说明、资料交接和通信独立维护，未来还会接入财务与人资。Agent 只对接助手及提供已有内容，不处理报销、订单、拜访业务。按本技能给出目录、依赖方向和必要迁移范围；当前只整理 Marketing，不预建未来助手。

## B：测试

一项助手接入重构将 Marketing 的声明、原消息装配、HTTP/SSE 和结果校验移到独立接入单元，通用执行层只持有装配后的助手对象。团队已运行导入检查，拟据此宣称以后任何助手都可以安全接入。请使用本技能设计必要验证：已有附件、暂停恢复、取消、未知助手、不同助手结果和身份隔离均须保持；允许使用第二个助手替身，但没有真实财务服务。说明能取得的证据和不能宣称的结论。

## C：审查

同事把营销代码搬到助手目录，并提出三项实现：接入适配器发现商品只有一个候选就自动选中；通用 Host 继续读取营销 action 字段来决定是否完成拜访；将每个助手的公开输入 Schema 复制为本地 DTO，避免依赖生成物。另有同事要求删除所有 marketing 字符串，认为出现领域名称就违反通用性。请使用本技能审查这四个观点，区分助手接入职责、协议校验、业务决策和同源契约，不改代码。
