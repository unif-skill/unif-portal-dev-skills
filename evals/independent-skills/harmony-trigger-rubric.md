# 鸿蒙技能自动触发判据

本文件只供评测者使用，不提供给被测上下文。题干见[自然请求](harmony-trigger-cases.md)，素材见[合成工程文件](harmony-trigger-fixtures.json)。本组检查宿主按请求隐式加载技能，与[独立消费题](cases.md)中显式提供单个技能、仅看描述选择入口的 I 题分别记录。

## 执行条件

1. 固定技能目录摘要、模型、推理设置、宿主和外部技能。核对宿主实际提供了 `unif-harmony-project` 的描述和可读取路径。禁用、缺失或读取失败时，单独记录环境缺口。
2. 每题使用全新上下文。按素材 JSON 的题号，将该组相对路径及内容原样写入新的临时目录；只向模型发送本题请求和替换了目录参数的通用执行边界。不要暴露题号、正负例标签、判据、历史答案或其他题目，也不预先加载技能正文或强制调用某个入口。
3. 保留宿主正常的技能选择机制；不得为获得预期结果添加加载提示、隐藏竞争技能或按题改变外部指令。使用子代理时不继承父任务对话，并记录其实际技能目录与外部规则；有访问范围限制不等于操作系统级隔离。
4. P4 在本题素材目录执行 `node --test tests/counter.test.mjs`，需已有支持 `node:test` 的 Node.js；无需安装依赖。该命令不修改源码、不联网、不构建 HAR 或操作设备。其他题只允许读取和回答，不运行测试、构建、发布或真实业务。环境缺少 Node 时保留技能加载观察，将命令执行单独标为未完成。
5. 使用套餐内额度；出现额度或积分警告时核查，不能确认可用套餐额度则停止。不得改用付费 API 或其他会话绕过限制。原始输入、输出、命令与摘要保存于仓库外或忽略的本地 `runs`，历史档案不回写。

## 触发证据

分别记录目录可发现、模型选择、正文实际加载和任务执行。自动触发须有当前技能正文被读取并成功返回的工具记录，或宿主等价的正文加载事件；只提到名称、自称使用、列目录或输出正确答案均不足以证明触发。读取失败、返回截断和重读原样保留；不能确认正文进入上下文时标为证据不足。

下表核对鸿蒙工程技能是否被正确选择。P1—P3 的原生宿主、HAR 和资源契约需要该技能。P4 是执行指定命令的对照。其他平台和通用方法按题设实际需要选用，单独记录。

| 题号 | 目标入口 | 同时核对的任务边界 |
|---|---|---|
| P1 | `unif-harmony-project` | 定位上传完成后无生命周期校验的写回；账号相同不能使旧操作重新有效。仅排查说明，不转为变更审查或测试设计。 |
| P2 | `unif-harmony-project` | 识别自造成功对象没有运行真实模块；补强方案保留同一模块中的关闭重开、旧回调与旧收尾，检查新宿主不受影响。不给出已执行的测试结论。 |
| P3 | `unif-harmony-project` | 按给定契约指出删除等待 `released` 使取消提前返回，消费者可能提前删文件；不把提出取消或 `result` 结束等同资源释放，不执行修复。 |
| P4 | 无必选 | 执行指定命令并报告退出码和实际用例结果。该用例仅断言 `nextRevision(2) === 3`，验收范围限于这段共享逻辑。 |
| N1 | 无 | 只回答配置声明的两个版本，不升级、评估兼容性或启动研发阶段。 |
| N2 | 无 | 按已提供文档解释 `close(): void` 立即返回、已排队回调可能继续；事实解释不转为实现审查。 |
| N3 | 无 | 仅润色两句文档，保留授权图片输入、`decodeImage` 和 `released` 的语义，不安排实现或测试。 |
| N4 | 无 | 仅排查 RN 实现及登录生命周期；工作区存在鸿蒙目录不扩大平台范围。可按实际请求采用 RN 入口。 |
| N5 | 无 | 只审查 Python 日志变更，识别 `sql`、`params` 违反给定日志契约；合成值不证明真实泄露。可按实际请求采用 Python 审查入口。 |
| N6 | 无 | 作为业务请求处理账号和任务缺口，不启动代码开发、测试或审查，也不执行真实业务写入。 |
| N7 | 无 | 仅排查未采用 Unif 规范的原生鸿蒙应用；可采用适用的通用鸿蒙规则，不因平台相同强加 Unif 企业入口。 |
| N8 | 无 | 只设计共同契约，可采用 `unif-architecture-design`；区分取消等待、远端结果和附件采用，不把设计请求变成源码实现、测试执行或代码变更审查。 |

任务判断与触发结果分开记录：选对入口但越权执行或给出错误结论，不能写成整题通过；正确答案没有加载记录，也不能补称已触发。判断依据是题设和采用契约，不要求复述表格措辞。

## 记录与比较

- 每题记录请求、素材、技能与外部指令摘要，实际模型、宿主、可用技能描述、真实读取路径、工具返回、原始回答及未验证范围。新名称须能解析到该次采用版本，不用作者机器路径或历史缓存替代当前安装证据。
- 对照使用相同题干、素材、模型和外部条件。只改变候选技能或明确评估的变量；已有正确触发及任务判断是回归要求，不计新增收益。
- 出现漏触发或疑似误触发时，先核对实际目录、授权、工具错误和来源，再用相同输入的新上下文复测；完整保留首次结果，不补提示后将第二次当作同一基线。未复现的单次现象不直接判为技能缺陷。
- 少量样本只支持本轮条件下的观察，不推断生产触发率、跨模型稳定性或 Token 收益。显式加载、仅描述选择、隐式读取、工程验证和设备验收分别报告。

记录方法参见[技能加载说明](https://developers.openai.com/plugins/concepts/skills)与[技能评测方法](https://developers.openai.com/blog/eval-skills)。具体命令能力和加载事件以本次宿主为准；文档示例不授予额外执行权限。
