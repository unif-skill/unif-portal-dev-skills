## 材料组装

1. 为每题建立新的临时目录，将 `cases[题号].files` 按“相对路径 → UTF-8 内容”原样写入。只展开本题素材；这些文件是合成契约或局部实现，没有真实账号、凭据、服务或用户数据。
2. 仅为本题 `sources` 中的来源准备快照。先取得对该库有权限的 Git 仓库或等价归档，核对清单的完整提交；不使用移动中的 HEAD、官网最新版本或当前未提交修改替代。读取源仓是只读操作，素材展开仅写新的临时目录。
3. 对指定提交使用 `git ls-tree -r --name-only <COMMIT>` 列出路径。选择 `selection.paths` 中的精确路径，以及 `selection.trees` 中同时满足 `prefix` 前缀和 `suffixes` 扩展名的路径，取并集。精确路径缺失即记录材料缺口，不能静默跳过。用 `git show <COMMIT>:<PATH>` 取得原始文件字节，保存到本题 `project/<directory>/<PATH>`，不经过格式化或换行转换。
4. 核对 `fileCount` 与 `snapshotSha256`。摘要算法：为每个已选文件计算小写十六进制 SHA-256；按相对路径字典序排序，将每条拼成 `路径 + TAB + 摘要 + LF`，UTF-8 编码后再计算 SHA-256。文件集合、内容或版本不一致时，不能宣称复现同一基线。
5. N10 只提供原生 Icons 清单中的四个文件；P10 提供 Chat 与 Camera 两份素材；其余按单题清单取得。独立行为 B4–B9 复用同一来源，放入对应 `inputs/project/` 下。完整源码可供按需查询，不要求事先全量阅读。

外部仓库或指定修订不可访问时，保留已取得材料和缺口；不靠猜测补齐、不把未完成样本计为通过，也不自动放宽联网或操作权限。若提供给被测模型的材料变化，应另记新输入版本，不能与旧基线作严格同条件比较。

本组全部只读作答，不运行测试、构建、生成、安装、Git 写操作或真实业务；交付题中的提交、删除授权仅是题设条件。素材中出现的脚本或测试文件仅供查询，阅读不代表已经执行。
