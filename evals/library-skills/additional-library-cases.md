# 新增库能力题

本组覆盖 AMap、Files、Logger、OSS、Speech，以及 Logger 的原生鸿蒙消费。只读案例用于核对入口发现、资料使用和边界判断，不执行真实定位、录音、上传、文件删除、安装或发布。判据在[单独文件](additional-library-rubric.md)，不交给作答者。

## 冻结素材

[来源清单](additional-library-fixtures.json) 固定六个库的 Git 修订、文件选择和摘要。使用 Git 对象组装 project/<directory>，不读取库工作区未提交内容。源包含公开实现、文档和实际 example 消费者，未提供完整原生运行环境或业务应用；不得据此声称 Portal 已迁移或真实服务已验收。

选择规则沿用既有 capability-fixtures：paths 精确选择文件，trees 按 prefix 和 suffixes 选择受版本管理的文件。文档按真实来源选择：AMap 使用 website/docs，其余 RN 库使用 docs，不把 website/docs 符号链接当成已经包含目标目录。为每个选中文件计算 SHA-256，按相对路径排序，将 `路径 + TAB + 小写摘要 + LF` 编为 UTF-8 后再计算 snapshotSha256；文件数与摘要必须一致。原始源副本、模型回答、命令与读取轨迹放在仓库外，不进入技能正文或本组清单。

每题在独立上下文中仅提供对应请求、素材目录、采用版本与修订。显式技能组另提供该完整技能目录；控制组保留相同模型、宿主、全局规则和素材权限。若比较描述发现，只提供同一候选目录的 name/description 和请求，不提供正文。记录实际加载，不能从回答提及名称推断加载成功。

## 仅描述发现

逐题选择实际适用入口或指出缺口，不读正文。平台工程技能按实际消费者和验收需要判断，不以总加载数机械计错。

1. RN 工程已采用 @unif/react-native-amap，排查选点取消后上一轮地点结果覆盖新选择。
2. 采用 @unif/react-native-files，查询预览与上传共同持有文件时的删除条件和本地 HTTP 访问资料。
3. 采用 @unif/react-native-logger，查询诊断快照交付后切换账号的文件释放契约。
4. 采用 @unif/react-native-oss，查验上传取消、未确认回执与源文件释放契约。
5. 采用 @unif/react-native-speech，排查重开输入后旧识别结果与麦克风收尾。
6. 原生鸿蒙采用 @unif/harmony-logger，查询实际采用包的文件入口和 RN 行为对照依据。
7. 普通 Python 服务配置标准 logging 的日志滚动，未使用 Unif 库。
8. 项目只使用其他地图 SDK，查询其定位方法。
9. 用户希望把一段文字转换为语音，没有采用 Unif 库。

接口说明与排障不授权源码变更或交付。描述发现、显式正文应用、实际宿主加载和真实消费者执行分开记录；新建技能目录与正确复述文档不等于修复正确率或成本改善。
