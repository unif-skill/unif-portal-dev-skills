# 库能力技能评测

覆盖六个自有库的公开消费、源码维护、必要组合与排除场景。共用研发规范和库能力属于同一次任务，不按加载技能的数量判断好坏。

## 输入与记录

“固定请求”是本轮回归中冻结的比较输入，不是技能允许处理的场景清单，也不代表覆盖所有未来任务。技能依据库的公开契约和通用研发规则处理其他请求；出现新的能力、平台、组合方式或真实失误时，新增代表性与边界案例，保留已有案例以检查回归。

题目见 [cases.md](cases.md)，判据见 [rubric.md](rubric.md)。Icons 的双端源维护、单端授权、普通消费与原生行为核对见 J 组。先固定基线包和候选包，再分别在独立上下文提供相同用户请求、允许的资料范围和代码修订；不把预期答案、基线结论或作者解释交给执行者。仅发现测试只提供名称、description 和用户请求。

记录所用包摘要、代码版本、原始回答、实际读取文件、未取得依据和工具失败。每题只进行题设授权的行为。仅使用套餐内额度，不例行查询，也不因额度未知自行停止。出现额度耗尽或积分提示时做必要核查；无法确认可用套餐额度，或确认需要消耗积分时停止，不调用付费 API 补评测。

六库 A–F 的单项独立消费，以及与架构、交付一起执行的正向／排除加载场景，见[专项行为组](../independent-skills/capability-behavior-cases.md)、[触发题](../independent-skills/capability-trigger-cases.md)及[判据](../independent-skills/capability-rubric.md)。版本化源码只按清单取得必要快照，原始运行证据不进入题库或技能默认上下文。

## 检查层次

- 格式与独立分发：使用现有包校验、标准技能格式和隔离目录测试；证明单个目录的包内引用完整，不证明外部服务可用。
- 资料定位：核对选中的公开文档、实际版本、导出和必要契约；无本地库源码时核对公开索引及其版本，不要求消费者先克隆全部工作区。
- 行为：人工检查结果、状态、资源与消费者建议是否符合实际契约；记录基线已满足的条目，不把新增入口当行为改善。
- 宿主与成本：模型被显式给出技能目录不等于已安装宿主自动发现。只有实际测量才能报告稳定触发、上下文节省或耗时改善。

历史运行保持原文。候选升级后新建 runs，不回写旧版本结果。runs 仅本地保存，manifest 按仓库已有格式记录每个冻结文件的 SHA-256，可用 validate_repository.py --include-evals 检查。
