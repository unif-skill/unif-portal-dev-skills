## H：Chat 的键盘、焦点与列表组合

使用本次提供的 Unif 技能与资料，给出足够实施的核查、修改范围及验证方案。仅作书面判断，不修改产品源码、不运行应用或设备、不安装和发布。

现有 React Native 聊天页由标题操作区、消息列表和浮动输入区组成，草稿及发送由应用持有。用户只要求“点击标题或消息空白处收起键盘”。布局、历史阅读、子按钮和原输入行为保持。

环境固定为 React Native 0.88.0、React 19.3.1、react-native-gesture-handler 3.4.0，采用 @unif/react-native-chat 4.5.8。消息列表 followOutput="never"；原契约中，新消息不自动跟随，但更新前位于末尾时，键盘等视口变化仍保持末尾可见。阅读历史或手动拖动保留原定位。

目前有两种备选实现：
1. 用 React Native 的 TouchableWithoutFeedback 包住整页，onPress 调用 Keyboard.dismiss。
2. 改为 react-native-gesture-handler 的 Pressable 包住相同整页，onPress 同样调用 Keyboard.dismiss。

现有检查只有 onPress 被调用、dismiss 被调用、组件渲染通过。iOS 候选包 A 的一次设备记录只确认标题点击收键盘；之后更改了整页包装并生成最终包 B，尚无 B 的设备记录。组件库类型检查与打包通过。

请判断应如何处理两种备选方案，还需核对哪些已存在的能力、输入与列表事件，以及什么证据才能支持完成结论。另请说明以下交错应如何验证：输入区先增高、键盘再缩小视口；浏览历史时新消息到达；迟到滚动结束回调；在附件/发送等子按钮上点击。区分已知事实、需从源码确认的机制及缺少的设备证据，不预设必须新增组件或修改库。
