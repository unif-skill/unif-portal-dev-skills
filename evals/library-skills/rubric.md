| B | Composer/Attachments 的实际类型和事件；草稿、上传、发送与文件归属在应用，展示库不接管这些业务状态；按需复用 Design/Camera |

| D | 宿主与 open 的公开调用；成功只交付已选临时媒体，取消/卸载/替换与已交付文件分开；上传与释放按实际使用者生命周期 |
| E | Scanner/HmsScanView/decodeImage 的真实选择；图片不申请相机权限，借用到结算/释放回调；空数组不掩盖错误，手电请求与实际状态分开 |
| F | 真正同意后初始化，配置保护及原生接线；controller/host 同实例同窗口；SDK 开始后的取消呈现不等于撤销，成功限有效回执 |
| G | 先核对 Snack 实际 SDK、库 peer 和原生模块；只开放 Android／iOS，不为原生文档继续做 Web 兼容；不兼容时指向原生 example／开发构建，不以 iframe 加载、Mock 或改成 Expo 同类库冒充真实能力 |
| H | 现有收键盘接线、事件范围、列表与输入交互以及版本对应的组合验收；详细判据见下方 H 场景 |

各题先核对实际读取与公开符号，再核对方案。新能力技能应使对应资料可直接发现；基线已找到正确资料和边界时记为保持，不计新增改善。源码查询不证明设备能力。

发现题 1/6 可只选择对应库能力；2/4/5 的实际开发同时取得 code-development；3 涉及扫码能力、公共契约设计及明确审查；9 使用 code-delivery，不能从“准备提交”推出发布；11 按实际组合取得 Chat/Camera 和开发规则。7/8/10 不因“拍照/扫码/分享”触发 Unif 库技能；12 按后端变更审查取得适用规范，不加载客户端能力。接受等价且依据充分的组合，不机械限制入口个数。

独立安装场景应能从对应包公开类型、可访问的版本文档或已核实发布修订继续；不能引用作者机器路径、其他技能私有文件或把官网最新声明当已安装事实。外部文档不可达时如实说明，仅限制需要这些事实的部分。

所有结果分别注明静态、资料使用、模型样本、宿主加载与真实工程验证范围。没有实测不能声明自动触发率、Token 收益或业务正确率。

## H：Chat 组合交互

本文件只供评估者使用，不提供给作答上下文。手工核对回答中的具体判断，不按关键词给通过率。

| 项 | 验收依据 |
|---|---|
| H1 范围与已有能力 | 核对现有标题、列表、输入及空白区域的交互接线；草稿、布局、子按钮与业务请求保持。不能仅为收键盘新建整页组件或额外业务状态。 |
| H2 事件归属 | 识别两种整页包装可能影响滚动、输入焦点和子控件；从采用版本源码或实际验证确认响应者/手势机制，不能凭组件名称或 dismiss 单测判定第二种方案安全。接受任何有依据且保持交互的实现，不机械指定某种组件。 |
| H3 视口与列表语义 | 区分新增消息、输入区留白和键盘视口变化；保留 never 不追随新内容、原来在末尾时对视口变化保持末尾，以及历史阅读/用户拖动/显式锚点的优先级。 |
| H4 组合与时序验证 | 覆盖收键盘与再次聚焦、输入区先增高再缩视口、迟到滚动回调、键盘开启时滚动历史、新消息到达及附件/发送按钮；断言焦点、可见位置、实际滚动和原事件次数，避免只检查 handler 被调用。 |
| H5 完成边界 | 区分类型/Mock/库构建、候选A设备记录和最终B设备验收；A仅验证收键盘，不得证明组合完成或替代B验证。未运行的检查明确列为待验证，不伪造完成。 |

固定相同请求、技能摘要、依赖和原生宿主条件。基线已经满足的判断只记录为基线能力；本次新增用例不意味着技能行为获得提升。
