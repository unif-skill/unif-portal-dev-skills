# 鸿蒙库能力覆盖题

本组只检查既有库能力技能的鸿蒙资料路由、接口核实与目标契约边界，不启动产品实现、生成、构建、安装或发布。判据见[人工核对](harmony-library-rubric.md)，不交给作答者。

## 素材与执行

[来源清单](harmony-library-fixtures.json) 固定六个原生库和规范源修订，仅选取各题所需公开入口、文档与真实消费者。按 Git 对象组装到 project/<directory>，不读取源仓工作区未提交内容；paths 精确选择文件且每项必须存在，trees 按 prefix 与 suffixes 选择文件。snapshotSha256 按相对路径排序，将每个文件的 `路径 + TAB + 小写 SHA-256 + LF` 编为 UTF-8 后再计算 SHA-256，核对 fileCount。

每题给执行者请求、对应源目录、版本和修订；显式技能组另提供对应技能完整目录。仅名称／描述发现与正文应用分别执行。控制组保持相同题面、材料和宿主条件，不把作者结论或判据交给执行者。原始输出、素材副本和日志在仓库外保存。

| 题号 | 来源键 | 只读请求 |
|---|---|---|
| HN1 | icons | 查看原生 Icons 的公开入口、参数和 example，说明通用图标与命名图标的尺寸、颜色和读屏应如何使用。只消费已有图标，不维护 SVG、运行生成器或修改组件。 |
| HN2 | design、contracts | 对照当前原生 Design 工程与目标规范，说明应用现在能否直接接入主题和字体能力，已有依据与缺口分别是什么。只读，不实现组件。 |
| HN3 | chat、contracts | 核对当前原生 Chat 公开入口和输入区目标契约，说明草稿、发送、附件及组件的职责。只读，不创建聊天实现或声明业务接入完成。 |
| HN4 | camera、contracts | 核对原生 Camera 工程是否已有可调用拍照入口，并解释选用媒体与文件交付的既有目标要求。只读，不拍摄或实现代码。 |
| HN5 | scan、contracts | 核对原生 Scan 的当前工程与图片识别目标契约，说明取消与文件借用需要保留什么。只读，不运行扫码或实施组件。 |
| HN6 | umeng、contracts | 核对原生 Umeng 的当前入口、隐私同意、分享回执与宿主目标责任。只读，不安装 SDK、配置凭据或执行分享。 |

空包题与已实现 Icons 分开记录。源码存在、设计可读、实际 HAR 消费、设备与发布状态不能互相替代。规范源中的 RN 对照链接可作为后续资料定位，不把未提供的 RN 源码或厂商资料当作已读取事实。

## 发现与排除

发现题可使用上表请求，只提供 name 与 description；另外核对普通 RN Camera API 查询仍可选择 unif-camera，未采用 @unif 库的系统 ArkUI Button 事实查询不因平台相同加载这些能力技能。纯查询不自动选择开发、测试、审查或交付阶段。

旧专项 N10 的原题与排除判据属于 RN 范围基线。HN1 使用真实原生公开参数与当前双平台范围，不将两者输入或授权差异当作技能增益。历史运行保留，新增入口的单次正确选择不证明稳定触发或成本改善。
