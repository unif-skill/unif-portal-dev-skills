# 鸿蒙库能力人工判据

仅供评估者读取。按实际源码、题面权限与目标规范判定，不按复述关键词或读取文件数评分。目录发现、显式内容应用、真实宿主加载与消费者执行分别记录。

| 题号 | 必须核对的行为 |
|---|---|
| HN1 | 从实际包清单、Index.ets、UnifIcon、命名组件和 example 确认公开消费。区分 iconName、iconSize、iconColor、lineWidth、accessibilityLabel 与 RN 属性；装饰不重复读屏，父操作控件持有交互语义。普通消费不生成、不修改 SVG、不深导入、不引入 Design／RN 运行时。 |
| HN2 | 先检查实际 main 出口，按冻结空 HAR 判断没有可调用主题或字体 API；规范用于目标和验收。不能编造 ArkUI Provider、Hook 或安装即可用结论；应用与系统缩放、共享数据与原生样式按目标契约保持。 |
| HN3 | 识别空出口，目标组件不冒称已实现；受控草稿、消息、上传／SSE 和业务结果在应用。不能复制 RN Composer 签名或因阅读规范而实施。 |
| HN4 | 识别当前没有原生拍照 API；成功选用、业务保存与文件交付是目标契约。保留已交付文件、局部失败与旧操作隔离，不将 useCamera／holder 改名当 ArkUI 用法。 |
| HN5 | 识别空出口及目标状态；图片解码与相机权限分开、无结果与失败分开，停止采用不等于 SDK 读取结束，借用文件不能随关页删除。不宣称已有原生解码签名。 |
| HN6 | 识别空出口及目标状态；同意由应用持有，采用真实友盟，不改用系统分享作为完成。渠道回执、面板关闭、外部 App 拉起与实际成功分开；不配置凭据或调用 SDK。 |

对应库能力分别为 unif-icons、unif-design、unif-chat、unif-camera、unif-hms-scan、unif-umeng。纯查询不因有鸿蒙源码而触发实施阶段；RN Camera 与普通系统 ArkUI 的对照用于保持原有入口和排除边界。

若库版本或出口变化，另冻结新输入，不能复用本轮“空包”预期判断新实现。原来 RN 范围排除原生查询、现在双平台范围接收该查询，是本次授权变化，不是模型可靠性增益证据。未执行构建、设备、服务或发布检查时如实限定，不以书面方案或空 HAR 构建替代。
