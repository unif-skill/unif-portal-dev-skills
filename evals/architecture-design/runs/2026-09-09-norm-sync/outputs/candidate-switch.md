**入口、功能与状态契约**

| 边界 | 必要输入、输出与责任 |
|---|---|
| Portal 自然语言入口 → 服务端统一入口 | 本轮原文、任务线索、必要实体引用及相关上下文。任务线索是提示，本轮表达优先；不发送业务认证信息、全部查询列表或无关草稿。 |
| 领域运行代码 → Portal | 互斥的类型化结果：已理解的意图及参数、必要澄清、受限数据需求。结果必须校验结构及引用，不能直接转换为业务提交或业务事实。 |
| 客户查询功能 | 接收类型化查询条件，只读查询并输出可展示的查询结果或明确错误。普通查询框直接消费；自然语言入口提取条件后消费同一个功能。不选择客户、不写入、不自动决定后续场景。 |
| 商品查询功能 | 接收明确的查询条件；Portal 页面、订单场景及续推理投影复用同一查询核心。给模型的投影只包含本次必要字段和有限条目，并说明范围有限。 |
| 订单场景 | 接收显式客户引用与订单意图片段，维护所属草稿、准备输入、确认依据及提交交互；调用订单业务操作并展示回执。 |
| 拜访完成场景 | 手动按钮和 AI 入口进入同一协调链路。经确认属于该目标的资产差异处理、准备、确认及提交均由该场景承担。AI 不越过场景直接调用最终写操作。 |
| 业务操作及适配器 | 接收完整类型化请求，适配原始协议并解释业务码。最终权限、规则、事务及事实由业务系统负责。功能消费者只使用映射后的结果语义。 |

查询适配器按所属接口的明确业务 `code` 解释成功、业务拒绝及其他状态，不能按 HTTP 成功或数据是否非空推断。客户列表保留返回数组的条目与顺序，缺少展示字段按空展示，不剔除缺值行；真实空数组表示本页无记录，根本没有可读取列表数据只表示暂无列表数据。展示空值不充当客户身份；后续操作所需身份必须来自实际数据。具体码表尚待接口契约确认，不指定统一成功码。

字段整理、结果投影、请求归属检查和任务选择优先使用普通函数与局部状态。当前需求不需要全任务公共状态对象、通用流程引擎或另建查询核心。

**客户 A 的订单交接**

1. 用户正在拜访 A，说“给这家店下两箱商品甲”。Portal 在发起这一轮时，从当前明确引用取得 A 的业务身份，保存本次调用所属交互及 A 引用的独立值；输入包含原文和该引用。此时没有订单草稿，不读取或构造一份虚假的既有草稿。
2. 本轮下单意图已明确，营销运行代码选择下单任务内容；无需先调用模型判断是否仍是拜访。模型理解“这家店”为交接中的 A，提取商品甲、数量 2、单位“箱”。商品身份及单位等提交条件按当前业务契约准备，不凭简称或常识补造商品 ID、包装换算。
3. 列表页面随后选中 B，只改变列表所属选择状态。B 不能经全局 `selectedCustomer` 反向改写本轮 A 引用、拜访客户或订单草稿。
4. 模型返回后，Portal 将其接回发起时的交互，校验其客户引用与本轮 A 一致。不能在回调时重新读取列表当前客户。通过校验的意图显式传入订单场景，创建或更新本次 A 的订单草稿；若需要商品查询或澄清，则保留同一归属继续处理。
5. 拜访状态仍归拜访场景，下单不会隐含完成拜访。不同入口对同一份所属订单草稿进行输入转换，而非各自维护订单副本。
6. 场景核实提交所需内容与确认依据。原始发话可表达下单目标，但模型补出的商品、规格或变更后的提交内容不能被当作用户已确认。已有动作确已确认同一目标、内容与副作用时直接复用，内容改变或未确认时才补交互，不固定增加重复确认。

本轮调用关联可通过请求返回值、闭包及所属交互的局部状态保持；不要求为普通调用新增公共关联 ID。若实际采用异步事件流或续交接协议，则沿用或明确该协议必要的请求归属和续接标识，不能靠全局当前任务推断。

准备或确认取消后停止后续业务步骤，迟到的模型结果不得重新打开已取消流程、修改 B 或触发提交。若订单仍有效而页面仅切换，结果继续属于 A 的订单交互。写请求发出后取消等待不代表撤销：回执仍归原请求；超时、缺码或未知码导致无法确认时，按实际业务系统能力核实，没有核实能力则展示结果未确认，不能自动重提。已知成功码下缺少展示字段也不改判失败。

**实际服务端交接路径**

下图表达必须经过的运行组件及模型调用点。Portal 与服务端统一入口之间是客户端网络交接；超级智能体运行代码与领域运行代码之间，可能为同宿主调用，也可能为服务间网络调用，部署尚未确定，不能把这段擅自画成已确认的独立服务连接。

首轮请求：

```text
Portal：原文 + 本轮 A 引用 + 下单线索
  ──客户端网络请求──> 超级智能体服务端运行代码：校验、领域路由
  ──公开契约，普通代码转交──> 营销运行代码：选择下单任务、按需装配
  ──实际模型调用──> 营销模型
```

营销领域已由入口明确，首轮不调用超级智能体模型。营销模型只加载通用指令、下单任务指令、必要契约、原文和 A 引用等必要上下文。没有草稿就不加载草稿，不每轮加载全部任务、历史、工具和查询列表。

必要数据续交接：

```text
营销模型：类型化的受限商品数据需求
  → 营销运行代码：校验输出
  → 超级智能体服务端路由代码：普通转交
  ──客户端响应──> Portal：校验需求和所属请求
  → 商品查询功能 → Portal 业务适配器
  ──业务网络请求──> 业务系统
  ──业务响应──> Portal 业务适配器：按业务码解释
  → 商品查询功能结果 → Portal：生成必要字段和有限条目的投影
  ──客户端续交接──> 超级智能体服务端路由代码
  ──普通转交──> 营销运行代码
  ──确需继续理解时实际模型调用──> 营销模型
```

数据需求必须表达要解决的商品理解问题和必要查询条件；允许的数据种类、字段、数量上限由交接契约约束，不能由模型任意扩大。数据投影需表达有限范围；不能据有限候选断言业务系统中不存在其他商品。查询失败交接明确失败，不伪造候选或无匹配。若查询后只剩确定性展示、用户选择或提交准备，由 Portal 继续，不为确认或总结追加模型轮次。Agent 不直接访问业务系统。

类型化结果返回：

```text
营销模型：订单意图 / 澄清 / 数据需求
  → 营销运行代码：输出校验
  ──公开契约──> 超级智能体服务端路由代码：原语义转交
  ──客户端响应──> Portal：结构、引用、归属校验
  → 对应订单场景或交互 → 中文展示
```

模块图上的“Portal ↔ 营销智能体”表示内容生产与消费关系。它不授权 Portal 直连营销服务，必要商品候选同样走统一服务端路由。领域输出不交给超级智能体模型重新理解、改写或总结。普通转发只传数据，没有模型调用就没有新增模型 Token；它仍有实际传输、校验和处理开销。

超级智能体与营销智能体遵循已确认的分仓边界，通过公开契约协作。统一入口的宿主、领域调用方式、端点及版本兼容范围需要接入设计确定；分仓不能直接推出服务数量。

**后续跨领域输入与记忆**

页面仍在营销订单、`taskHint` 仍为下单，但本轮说“另外，帮我查设备报修进度”时，本轮领域指向已经改变。统一入口必须依据本轮表达选择设备运维，结合服务端领域目录转交其运行代码，按设备运维任务契约处理所需报修引用。不能因旧提示仍在而继续加载下单任务，也不能让营销模型跨过领域边界自行处理设备业务。能确定性识别时由代码路由，确需语义识别时按需调用模型，不能承诺所有跨领域判断都无模型成本。设备具体查询契约未给出，不补造设备、报修单或查询接口。

若只说“那个现在怎么样了”，且当前引用不能消歧，就先识别意图并提出必要的中文澄清，取得明确目标后再路由或查询。不能默认指订单、设备报修或某个历史实体，也不发起猜测性的写操作。识别或澄清的实际调用计入模型用量。

需要商品简称线索时，营销运行代码可直接调用现有公用记忆服务公开 API，不经过超级智能体代理。记忆调用使用公开契约及所锁定的客户端版本，由服务端执行身份、权限和适用范围校验；先过滤范围，再限制条目和字段，仅将本轮需要的、有来源和版本的片段作为参考上下文。无需缓存整个领域记忆、每轮检索全部记忆，亦不把记忆放入系统指令。

历史简称只能帮助理解，仍须按当前商品业务契约核实实体；记忆中的旧客户不能覆盖本轮明确的 A。Portal 草稿与当前选择仍归所属交互，记忆服务不保存另一份权威业务状态。无匹配、服务失败或无权限按已有公开契约处理；缺少线索时继续使用明确输入和可用查询，必要时澄清。本次没有记忆写入需求。

**必要验证与待确认项**

以下是实施验收范围，当前书面设计未执行测试，也没有已降低成本的测量结论。

| 验证层 | 必须证明的行为 |
|---|---|
| 真实查询功能与业务适配器 | 用网络替身验证输入映射、明确业务码、空列表、缺展示字段、缺业务身份、业务拒绝和未知结果；查询不写入，缺值条目不丢失。 |
| 场景与入口 | 手动及 AI 拜访完成进入同一场景；已确认的资产处理与提交顺序一致，确认复用和失效准确，AI 不绕过确认。普通查询直接展示，自然语言只提条件后复用查询，无无关写入及总结调用。 |
| 客户归属及异步交接 | 无草稿的拜访 A 转下单；选 B 后迟到响应仍归 A；取消后的结果不推进；引用冲突不进入提交；写入回执不更新其他客户或任务。 |
| 真实模型任务评测 | 拜访、下单分别验证语义；覆盖“这家店”的 A 引用、商品数量单位、任务切换、复合意图、设备运维跨域与“那个”的澄清。检查结构和语义，不用模拟模型输出证明理解正确。 |
| 服务端入口与接线 | 对首轮、商品需求返回、有限数据续交接、最终结果全链路追踪，确认均经过统一路由；检查公开契约在实际生产消费端的校验和兼容。用实际模型调用记录证明明确领域没有独立超级模型路由、结果没有总结调用；普通转发不能被统计成模型调用。 |
| 上下文与记忆 | 观察实际装配内容：仅当前任务及必要数据；营销运行代码直接消费记忆 API，过滤范围、来源和版本有效，旧客户不覆盖 A，无整个领域记忆系统指令。用记忆服务替身验证边界，结合对应模型样本检验线索对理解的影响。 |
| 实际集成 | 在接线确定后核对真实业务码、权限、提交副作用和最终业务事实；涉及设备能力的实际变更时再补相应真机验证。 |

单任务指令调整优先运行该任务及必要切换样本；本次包含统一路由、任务装配和状态归属设计，应覆盖 Portal 相关入口、超级智能体路由、营销拜访与下单、设备运维交接及实际记忆消费者。公共契约或通用指令变化扩大到受影响生产方、消费者与任务；影响关系不清时扩大相关领域及集成验证。系统合并、发布仍执行实际 required CI，定向验证不能替代。

待确认内容限于依赖尚未提供的契约：

- 营销正式任务、客户和商品引用、草稿及订单提交契约；商品甲如何确定身份，箱单位及提交所需参数如何校验。
- 拜访完成中资产差异处理的有效业务依据、具体副作用、顺序及确认内容。实现建议只能证明存在一种建议，不能证明后端规则；已确认的共同业务目标必须共用场景，不能保留两套入口流程。
- 客户、商品查询及业务写入的真实接口码表、数据形状，以及未确认写入的核实、幂等或撤销能力。
- 超级智能体统一入口宿主、与领域运行代码的调用方式、请求续接和失败传播约定、跨仓发布兼容范围；设备运维任务及查询所需引用。
- 沿用现有公开记忆契约所需的版本、授权范围、商品简称内容语义及有效性规则；不另建记忆协议或代理层。

实现后按相同业务行为与验收标准记录一次用户目标的累计模型调用、输入输出 Token 与端到端耗时，包括路由识别、澄清和必要续推理，并区分用户确认等待与系统处理时间。按需装配和代码转发是降低模型成本的设计手段，当前实际降幅、准确率与延迟均未知。
