# 模块设计审查结论

## A. 完成拜访：调整任务发现能力，再接入共同场景

保留“智能体提取客户查询条件 → Portal 查询并由用户选择客户 → 与手动入口共用完成场景”的设计。智能体不生成任务身份，不调用业务系统；最终完成仍由业务系统判定。

现有接口尚不能闭合该链路：`getVisitTask(ref)` 要求已知任务身份；`acquireVisitTask(customer)` 可能创建任务，不能当作完成场景的只读任务解析。保留它在开始场景的用途，复用其中已经验证的只读查询实现；完成场景不得调用其创建分支，也不能把一次空页解释为不存在任务。

必要公共接口与结果：

- 保留 `CustomerRef`、`VisitTaskRef` 和按引用查询的 `getVisitTask`。引用必须来自经过校验的业务响应，校验其客户归属；`null` 只能表示接口明确证实的不存在，不能承载查询失败。
- 增加一个按客户查询现有可完成任务的只读能力，例如 `queryCompletionVisitTasks({ customer })`。这是待外部查询契约确认的接口草案：返回候选及真实查询覆盖情况，区分可靠空结果、范围未确认或覆盖不完整、查询失败。具体日期、计划、分页参数不能凭旧实现定稿。完整范围内的唯一匹配才能直接形成任务引用；多个候选交由 Portal 选择，覆盖不足不能声称已经找到唯一任务，可靠空结果也不创建任务。
- 将 `completeVisit({ ref, ...已确认的必要提交内容 })` 的 `unknown` 返回收紧为类型化业务结果，至少区分成功、明确业务拒绝、结果未确认、成功码可信但回执异常。后端码表由完成接口适配器解释，消费者不解析原始码；具体回执字段和成功码须以该接口约定确定。
- 完成条件查询采用只读接口，由场景组合条件查询、资产差异交互、确认及提交，功能之间不相互调用。资产差异处理若包含业务写入，必须单独明确该操作的副作用和确认责任，不能藏在“取得任务”或“准备”步骤中。

`VisitStartRequirements` 也需修正：准入结论与位置配置可用性分别表达。禁访或结论未知时不能强制要求坐标与距离；准入允许但位置配置未取得时，应表达配置未就绪，不能补零值或伪造位置使类型通过。保留现有有效配置字段；这些开始条件不自动成为完成拜访的门槛。

Portal 完成场景持有选定任务、待提交内容、确认依据及提交状态。确认绑定具体任务与提交内容，内容改变使原确认失效；入口切换仍操作同一场景状态，异步响应归属原请求。提交前查询不能替代业务系统最终判定。提交后取消等待不等于撤销；超时或回执异常不能按普通失败自动重提。多步写入保留各步真实结果，不承诺客户端原子事务。

实际验证范围：

- 真实任务查询与完成适配器使用替代网络验证候选、可靠空结果、分页覆盖不足、范围未确认、引用不匹配、业务拒绝、缺码或未知码、超时以及成功码下的损坏回执；断言不会把这些情况伪装成成功或空结果。
- 共同完成场景验证唯一及多候选选择、取消、确认失效、重复提交防护、任务切换后的响应归属；无任务或查询异常时，断言既不创建任务也不提交完成。若资产处理有写入，增加部分成功与后续失败的结果交接验证。
- 手动与聊天入口验证接入同一完成链路；模型任务评测覆盖客户条件提取、指代、澄清及必要的任务切换，不能以模拟模型输出或 TypeScript 编译通过替代理解评测。
- 调整开始条件契约时，验证实际读取该契约的开始场景，覆盖仅禁访结论和位置配置缺失；无需因此新增真实设备操作测试，除非实现改动触及设备行为。联调另核实查询范围、码表与最终完成事实。

待确认业务事实：任务查询的日期与计划范围、分页完整性和候选资格；完成条件与必要提交字段；资产差异处理是否写入及确认责任；外部接口码表、回执要求与结果核实能力。前两项直接影响“按客户找到正确任务并完成”的验收，不能将链路标为已具备；其余明确部分可继续设计与验证。

## B. 照片适配：仅修改原始响应映射

保留公共结果 `{ uri }`、两个场景的现有调用方式及 `uploadBinary`。更新 `visitPhotoAdapter` 的原始响应契约和映射，从 `data.objectUrl` 取得原有语义的 `uri`；原始字段名不向消费者传播，不新增公共接口。

删除附带的两次失败重试和“缺 code 也返回 uri”的建议。仅数值业务码 `200` 且必要结果有效才返回成功；字符串 `"200"`、HTTP 200、存在 `objectUrl` 均不能代替业务成功码。缺码或未知码按结果未确认处理；数值成功码可信但必要地址损坏时保留成功证据并表达回执异常，不能诱导再次上传。已知业务失败按既有接口约定映射，用户提示沿用功能交互中的中文映射。

优先更新真实适配器的现有测试，验证新字段映射及原有公共结果，并覆盖字符串码、缺码、未知码、失败码附带地址、成功码缺少或损坏地址、传输失败，断言不会错误返回成功、不会新增上传调用。单独断言 `uri` 的测试不足以证明业务结果解释正确。

检查店头照和自拍照两个实际消费者，运行与上传结果消费相关的已有定向验证。H5 与问卷不调用本次改动的适配器，且共享 `uploadBinary` 未变，本次无需把它们纳入回归或追加真机验证。以后修改取消、资源释放或公共上传实现时，再重新确定受影响消费者；不能固化为“以后所有改动只跑一个测试”。发布仍执行现有 CI required 检查，定向测试不替代发布门禁。

## C. 普通内部调整：直接沿现有授权完成

保留将两段等价名称整理抽成模块私有函数的方案。无需新公共接口、公共模块、架构层、模型参与或额外确认，也无需为此次机械提取新增设计文档。

实现时仅替换两处重复逻辑，保持原有调用位置与数据流。检查差异确认输入输出、排序、请求次数和副作用未变，运行已覆盖两段分支的真实适配测试及适用的现有静态检查即可；无需新增镜像实现的测试或扩展到无关场景。若实际提取出现语义差异，再按真实影响扩大验证。本次仅给出审查结论，不宣称调整或测试已经执行。
