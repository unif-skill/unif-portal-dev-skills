# 模块设计审查结论

## A. 完成拜访：调整后才能交付实现

保留“营销智能体输出客户查询条件 → Portal 查询和选择客户 → 与手动入口共用完成场景”的设计。保留 `CustomerRef`、`VisitTaskRef` 与按引用读取任务的职责；最终能否完成仍由业务系统判定。类型编译通过只证明静态结构，不证明实际输入能够取得任务身份或完成业务链路。

草案缺少从客户取得**已有拜访任务引用**的只读能力。`getVisitTask` 要求先有 `VisitTaskRef`，不能填补这一缺口；`acquireVisitTask` 可能创建任务，不能直接作为完成场景的普通准备步骤。开始场景可继续使用它，但必须明确创建副作用及相应确认责任；确认“没有可复用任务”也必须有查询覆盖范围依据。

完成场景应明确为：选择客户 → 查询该客户已有任务候选 → 取得明确任务引用 → 必要时读取任务 → 查询完成条件、处理资产差异 → Portal 针对具体任务和提交内容确认 → 提交并解释业务结果。多个候选由明确规则或用户选择解决，不能默认取第一项；没有可完成的已有任务时不能偷偷创建。若资产差异处理涉及写入，应单独表达副作用与确认责任，不能隐藏在查询或准备中，也不能假定与最终完成构成原子事务。

必要公共接口调整：

- 增加小型只读查询能力，例如 `findVisitTasks({ customer })`，返回含真实 `VisitTaskRef` 的候选及实际可证明的查询覆盖信息，区分成功空结果、查询失败和覆盖不足。接口语义为草案；日期、计划、分页及候选筛选规则确认后再定稿，不能凭旧实现或默认值补齐。有限候选不能被当作全部任务。
- `getVisitTask({ ref })` 可保留；`null` 仅表示成功查询后按契约确认不存在，不能吸收传输或协议错误。客户、任务身份及二者关联需要校验，模型不得生成不存在的引用。
- `completeVisit` 的 `Promise<unknown>` 应改为功能语义结果，至少区分成功且回执有效、业务拒绝、结果未确认、成功码可信但必要回执异常；接口定义的其他状态另按契约映射。输入以真实任务引用和业务接口确认的必要字段为限。原始码由适配器解释并保留诊断关联，场景不重复解析后端码。确认绑定具体提交内容；内容或任务变更后不得沿用旧确认。超时或取消等待不表示已撤销，不自动重试。
- `VisitStartRequirements` 不能要求所有结果都有坐标和距离。可按 `admission` 区分 `blocked`、`unknown`、`allowed`，在允许分支再区分位置配置可用或不可用；禁访可不带配置，允许也不代表配置已经取得。保留已有位置字段用于配置齐备分支，禁止补零或猜测坐标。配置不足时如实表达阻断，具体恢复方式依业务约定；不将开始条件自动复用为完成条件。

待确认的业务事实：任务查询的日期、计划、分页覆盖及可完成候选规则；业务系统是否提供按客户查询真实任务引用的能力；完成条件、资产差异处理的读写性质、提交字段及接口码表；结果核实、幂等或撤销能力是否存在。若缺少按客户查询能力，应报告接口缺口，不能用创建或伪造身份补出。以上未定项阻止相关契约定稿，其余职责、状态与入口接线结论可直接采用。

实际验证范围：只读任务查询和完成适配的真实功能测试，覆盖无候选、多候选、覆盖不足、失败及身份不匹配，断言不会创建任务或误提交；补开始场景对禁访无配置、允许但配置缺失以及查询覆盖不足时不创建的验证。场景测试覆盖任务选择、资产步骤的副作用与确认、内容变更、取消、提交结果分类及异步响应归属。页面和聊天验证进入同一场景；营销任务评测验证客户条件提取、不编造任务身份。接口联调确认真实身份、覆盖范围、码表和最终完成事实。仅涉及真实设备行为变化时补对应真机验证，模拟输出和编译结果不替代上述证据。

## B. 照片适配：保留字段映射，删除附加行为

本次仅调整 `visitPhotoAdapter` 的原始成功响应校验和映射：数值 `code === 200` 且 `data.objectUrl` 符合接口要求时，产出原公共结果 `{ uri }`。后端原始契约留在适配边界，店头照和自拍照继续消费相同功能契约，无需新增公共接口。无需顺带引入旧字段兼容机制。

删除“两次失败重试”和“缺少 code 但有 objectUrl 即成功”的建议。二者超出确认范围，后者还改变业务成功依据。HTTP 200、字符串 `"200"` 或存在地址均不能代替数值业务成功码；缺码、未知码不得包装成成功，已知失败按明确失败处理。可信成功码但地址损坏应保留成功证据并表达回执异常，不能变成可直接重新上传的普通失败。保持既有上传调用次数及取消、资源释放语义。

实际验证范围：更新或补充真实适配测试，替换网络边界，验证新字段到 `uri` 的正确映射，并覆盖失败码仍带地址、缺码、字符串码、未知码以及成功码下必要地址缺失或无效；断言没有新增重试和额外上传副作用，不能只断言 `uri`。复用店头照和自拍照现有相关场景或接线测试，确认消费者仍能接收并使用公共结果。

这次未修改 `uploadBinary`，H5 和问卷不依赖 `visitPhotoAdapter`，不因共享底层上传而加入本次定向回归。未来改变共享上传的取消或资源释放语义时，再重新识别这些消费者。“以后所有修改只跑一个测试”不成立，测试选择随实际依赖和语义变化调整。发布 required 检查继续按现有 CI 配置执行。

## C. 客户显示名称整理：直接按已授权范围调整

保留模块私有函数提取，不扩大公共接口，不改变输入输出、排序、请求次数或副作用。无需新增公共模块、架构方案、设计文档或再次确认；在实现中核对两段整理逻辑及调用点的等价性即可。

运行已覆盖两段分支的现有真实适配测试，并执行该改动适用的类型或静态检查。现有断言足以验证行为时不新增测试，不为私有辅助函数建立重复的实现细节测试。无需扩大到模型评测、其他业务场景或真机验证；若进入合并发布阶段，仍执行既有 required 门禁。本次仅形成审查结论，未实施或执行测试。
