# 模块设计审查结论

## A. 完成拜访：保留共用场景，补齐只读任务定位和结果契约

保留已确认链路：营销智能体输出客户查询条件；Portal 查询并选择客户；自然语言与手动入口进入同一个完成场景。模型不选定业务任务、不推进流程、不提交，也不接收业务认证信息。

当前草案不能直接交付实现。`getVisitTask` 必须先有任务引用，不能解决从客户找到任务的问题；`acquireVisitTask` 在特定条件下会创建任务，不能作为完成场景的普通准备步骤。类型编译通过只证明类型示例自洽，没有证明任务身份可取得、查询完整或业务成功。

**必要公共接口与边界：**

- 保留 `CustomerRef`、`VisitTaskRef` 和任务快照。新增或从 `acquireVisitTask` 内部提取一个可复用的只读任务查询能力，例如 `queryVisitTasks({ customer, scope })`。`scope` 的字段及含义待业务契约确认，不能先固定为当天、某计划或第一页。返回已有任务引用及必要快照，并明确结果覆盖范围；区分完整查询无结果、有限候选、查询失败和无法确认覆盖范围。有限候选不能作为全部任务，单条候选也不自动证明唯一。缺少真实任务身份时不得补造 `visitTaskId`。
- 开始场景可以继续复用原有查询工作，但应将查询与创建的副作用界线落实到代码。`acquireVisitTask` 若继续作为公开组合能力，必须明确它可能创建任务，并由开始场景承担相应确认；不得因为开始场景已使用就让完成场景继承创建行为。没有完整查询依据时不能把“未查到”解释为“允许创建”。
- 已持有有效引用时继续使用 `getVisitTask`。其 `null` 只能表示接口明确确认该引用不存在，不能吞掉查询失败。候选选择、所属客户核对和引用传递由 Portal 完成；多候选由交互选择，不能默取第一项。
- `completeVisit` 保留明确任务引用作为必要输入，返回类型化业务结果，不能继续公开 `Promise<unknown>`。至少区分业务成功、明确业务拒绝、成功码可信但必要回执异常、结果未确认。适配器依据实际接口码表校验和映射，原始码及请求关联留在诊断侧；页面、场景和模型不重复解析原始码。提交还需要哪些业务字段、各结果所需回执，须依据真实接口补齐，当前不臆造。
- 完成条件查询仅返回该任务完成所需的条件和数据；条件展示、资产差异处理和提交由场景组合。若资产差异处理会写业务数据，必须单独表达操作、副作用和确认责任，不能隐藏在查询或准备中，也不能承诺与完成请求原子提交。

`VisitStartRequirements` 应修正为能表达真实缺项的联合类型：`blocked` 不要求位置配置；`unknown` 明确表示准入结论未取得；`allowed` 下的位置配置另分 `ready` 与 `unavailable`，只有 `ready` 才要求坐标和两个距离。不得用默认坐标或距离凑齐类型，也不能将缺少配置等同于禁访。缺少配置时如何继续开始流程，仍须按业务约定确认；完成场景不因类型已存在而继承开始准入或位置要求。

**完成场景交接：**

客户选择 → 只读定位并选择已有任务 → 按引用取得完成所需数据 → 处理必要交互 → 展示具体待提交内容并确认 → 发起完成请求 → 展示类型化结果。草稿、任务选择、确认及提交状态由该场景维护；内容或任务变化后，旧确认不得授权新的提交。请求回执归属原请求和原交互，切换入口或任务不能串写。准备阶段取消不提交；发出后取消等待不代表撤销，未确认结果不得按普通失败自动重新提交。最终能否完成由业务系统决定，查询快照和本地检查不能替代最终判定。

**待确认的业务事实：**任务查询的日期、计划、分页及完整性依据；真实只读查询是否能返回必需任务身份；哪些已有任务适用于完成场景；完成条件、资产差异处理是否写入及其确认责任；完成接口的输入、码表、必要回执和结果核实能力；开始场景在位置配置缺失时的处理约定。上述未确认部分不能宣称已经可实现，但不阻止先确定入口复用、只读定位、状态归属和适配边界。

**实际验证范围：**

- 用替代网络依赖测试真实任务查询、开始任务获取和完成适配：完整无结果、多候选、部分分页、查询失败、缺少身份、客户引用不匹配；完成链路不得调用创建能力。验证开始场景仍按明确条件复用或创建。
- 场景及入口验证覆盖手动与聊天共用链路、候选选择、内容变化使确认失效、取消不提交、迟到回执归属，以及资产处理存在写入时的调用顺序和部分成功展示。
- 完成适配覆盖实际码表、有效成功回执、明确拒绝、缺码／未知码、写入超时和成功码下回执损坏；不凭 HTTP、ID 或文案认定成功。
- 自然语言评测覆盖“完成统一便利店的拜访”、客户歧义、开始与完成的识别及切换，确认输出查询条件而非虚构任务身份。模拟输出接线测试不能替代理解评测。
- 联调核实查询覆盖范围、权限、接口码表及最终业务事实。若实际完成链路使用设备或改变设备行为，再覆盖对应设备场景和必要真机验证。以上是验收范围，本次未执行这些验证。

## B. 照片适配：只接受字段映射变更，删除附带行为

保留本次改动为 `data.objectUrl → { uri }`，公共成功结果不变。删除新增的两次重试，以及缺少 `code` 时凭 `objectUrl` 返回成功的逻辑。这两项都超出已确认需求，后者直接破坏业务成功依据。

必要公共接口不变。仅更新 `visitPhotoAdapter` 的原始成功响应契约、运行时校验和映射；类型与校验保持同源。只有数值 `200` 且必要结果有效才返回 `uri`；字符串 `"200"`、HTTP 200、存在地址均不代替业务成功码。明确失败码按失败处理；缺码或未知码不包装成功；成功码下必要地址损坏保留成功码证据并表达回执异常，不因此重新上传。沿现有结果／错误通道表达这些语义，不为字段改名另建公共机制。

实际验证范围是：

- 更新或补充真实适配器测试，替换上传外部边界，覆盖新字段正确映射、数值与字符串码的区别、失败响应即使带地址也不成功、缺码／未知码、成功响应缺少或损坏 `objectUrl`。断言异常场景不会返回成功 `uri`，且每次调用不会额外重试；仅断言一次 `uri` 不足够。
- 对直接消费该适配器的店头照、自拍照执行现有相关回归，确认继续接收 `{ uri }` 并按原有链路处理结果。
- 本次未改 `uploadBinary`，H5、问卷也不调用 `visitPhotoAdapter`，无需为这次定向验证额外扩展到它们。今后每次修改重新按实际依赖和语义影响选测试；涉及共享上传取消或资源释放语义时，应重新纳入相关消费者，不能规定以后永远只跑一个测试。
- 发布仍执行现有 CI required 检查，定向通过不能替代发布门禁。

## C. 私有函数提取：直接完成已授权调整，验证保持行为

保留将两段等价显示名称整理抽成模块私有函数的设计，不新增公共接口、模块、场景或共享抽象。继续由原适配器调用，保持输入输出、排序、请求次数及副作用不变。

实现者可直接完成已授权调整，无需重新征求确认、编写独立设计文档或另行规划。检查差异确实只包含提取及两处调用替换，运行已有覆盖两段分支的真实适配测试，并按项目现有要求执行相关类型或静态检查即可。既有测试已覆盖行为，无需为私有辅助函数增加同义测试，也不需要扩大到无关入口、模型评测或真机验证；交付门禁继续遵循现有配置。
