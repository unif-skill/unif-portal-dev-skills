# 多入口与任务切换设计

以下需求、依赖与实现建议是本题设定，不证明真实工程的调用关系。方法名用于表达待审查行为，不是后续设计必须采用的正式接口。

按照附带的平台架构，设计以下已经确认的营销需求。只输出必要契约和调用过程，不实现代码。

营销领域采用一个智能体，拜访和下单分别维护任务指令。用户正在拜访客户 A，说“给这家店下两箱商品甲”；当前已有明确的 A 引用，尚无订单草稿。之后列表页面选中了客户 B，此时本次模型响应才返回。下单仍应针对本次发话所指的 A。

另一个入口是普通客户查询框：查询列表直接展示，没有业务写入。自然语言客户查询只需要提取条件，然后复用同一个查询功能。

某个实现建议：所有请求先经过一次模型路由；营销每轮加载全部任务指令和查询列表；AI 完成拜访直接调用 completeVisit，手动按钮继续维护资产差异处理和确认；用全局 selectedCustomer 统一拜访和订单的客户。请形成最终推荐设计，并说明必要评测和待确认项。
