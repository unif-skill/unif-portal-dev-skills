# 任务入口与指令装配设计核对

这是研发设计评测题设，不是生产验收。请按所给技能包及必要引用，为下面几项需求决定最小调用链、营销任务与指令装配范围，说明上下文、取消和确认的归属。只做设计，不修改工程、查询业务或调用外部服务。不要读取评测 rubric。

题设：同一 Agent 服务负责认证、会话、附件、轮次和事件，已接入 Marketing。协议提供可选 input.skill=order，taskHint 作为来源线索；服务支持 order、visit、customer、marketing、order_match、regenerate、analysis。可用输入均已经过所属契约校验，用户已授权下面的业务需求；不把这项题设当作真实源码检查。

1. 用户从专用订单入口提交“给当前客户加两箱商品甲”。当前输入集合每项都显式 skill=order，客户、草稿、商品目录与来源已准备好，非重新生成。确定是否需要超级智能体模型及其作用；随后同一输入版本回交一次合法商品供数时如何继续。
2. 普通聊天分别收到“查看本月拜访计划”与“查一下客户甲的地址”，均无显式 skill。确定各自的模型选择步骤、营销任务和指令范围。
3. 普通聊天收到“先完成客户甲的拜访，再给这家店加两箱商品甲”。确定任务范围，说明先后关系、客户引用和业务确认由谁执行。
4. 场景 1 的原轮次正在运行，用户追加一条未设置 skill 的文字：“先不下单，我要查客户甲的地址”。旧 taskHint 仍是 order，旧结果稍后才返回。说明新输入如何影响任务和迟到结果；不能假定未标记的新输入继承 skill。
5. 固定问卷分析、对既有普通回复的重新生成、普通客户列表翻页各有什么调用边界？

给出可执行结论，并列出必要验证。模型次数只按这些路径的实际调用说明；缺少运行日志时不要声称测到了费用或时延改善。
