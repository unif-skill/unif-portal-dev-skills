## 2. 基础组件与 UI 复用

### 2.1 复用来源

| 内容 | 使用与维护位置 |
|---|---|
| 基础按钮、输入、列表原子、主题、颜色 token、图标等设计系统内容 | 通过 `@unif/react-native-design` 的公开入口使用，版本由工程依赖锁定 |
| Portal 自有、可跨场景使用的布局、列表组合、弹层、图片预览、Markdown 等 | `components/` 中的对应单元 |
| 消息气泡、附件展示、输入区、确认展示等聊天 UI | `components/chat/`；每个可独立使用的组件有自己的公开入口 |
| 键盘容器、输入区域避让和关联 hook | `components/keyboard/`；状态只服务于键盘布局与交互 |
| 账号、首页、设置等特定应用功能的表单或组件 | `app/` 下的所属功能 |
| 客户、订单、拜访等业务卡片和表单 | 所属领域模块的交互代码 |
| 相机宿主、地图视图等与设备能力直接相关的 UI | 所属 `capabilities/` 单元 |
| WebView 与 H5 协议处理 | `integrations/h5/` |

设计系统继续由组件库维护，Portal 不复制包源码，也不为统一导入路径再包一套同名 Button、Input 或主题 API。Portal 特有的组合组件、默认交互适配和测试随其所属单元迁移。

共用组件通过 props、事件回调和必要的展示类型接收数据，不读取业务 store，不查询客户、提交订单或保存会话。确认组件展示内容、收集用户动作；需要确认什么、动作是否已经表达确认以及随后执行什么，由场景维护。

导航相关的页面布局与弹层保留其视觉和交互用途，路由参数、页面注册与具体导航动作由入口适配。主题和键盘 Provider、Toast 等应用所需宿主由应用组装；单个组件测试只提供它实际需要的轻量宿主。

组件库已有同等功能时直接复用。确需新增 Portal 组件时，说明它补充的交互或组合职责；不将只被一个场景使用的卡片提前提升为全局基础组件。已有中文展示、主题和可访问性语义在迁移中保持；行为改变由对应需求与验收定义。

### 2.2 聊天 UI 与业务逻辑

聊天展示可以被不同业务领域复用，其展示契约属于组件自身。服务端流事件到展示数据的转换留在 `integrations/agent/` 与 `app/chat/` 各自负责的接入、交互代码中；领域结果的呈现由所属领域的交互代码提供。

组件名称中的 Message、Task、Tool、Confirmation 等只描述展示用途，不赋予组件发起模型、工具或业务调用的职责。可选回调只在所属场景已经定义该动作时接入，不能因为组件支持一个按钮就新增重试、提交或其他操作。
