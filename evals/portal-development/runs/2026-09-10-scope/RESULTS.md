# 职责去重后的验证

平台原则从 portal-development 分发包移除，由 architecture-design 持有；前者仅携带开发规则和工程组织。入口按业务结果、状态及确认问题路由到平台规则，不硬编码跨技能文件路径；description 去掉“新架构”等背景限定。保留的平台快照同步当前规范源，正文差异仅为三处文档入口。

输入、完整输出及摘要见 [manifest.json](manifest.json)。四次独立运行均不继承父任务对话，未向被测上下文提供评分或其他运行产出；具体允许资料见各运行记录。原先的[完整场景评测](../2026-09-10/RESULTS.md)保持原样，不把其三快照版本直接计作本版本结果。

| 运行 | 人工结果 | 证据 |
|---|---|---|
| 两份资料、初始路由的设备/适配场景 | D1、D2 满足；D3、D4 未满足 | [输出](outputs/capability.md)保持调用期资源及 SDK 注入，但过滤 null/缺 ID 行、将成功码下非数组数据改为失败，并将该行为写入测试计划。只给文件规则不足以支撑平台结果语义，初始路由遗漏普通结果映射。 |
| 独立安装 | 满足 | [输出](outputs/standalone.md)继续完成纯工具测试方案；缺少 architecture-design 和目标架构规范时，对业务事实归属及新公共能力列缺口，没有读取不存在的私有路径或自行实施迁移。此运行覆盖去重后的独立使用边界，未覆盖完整业务适配。 |
| 精简后的 description | T1 满足 | [输出](outputs/discovery.md)正确选择八类请求，并区分技能约定与工程强制门禁。只提供目录描述，不显式要求加载某个技能。 |
| 补齐读取路由、两个技能共同可用 | D1—D4 满足 | [输出](outputs/capability-shared.md)引用 architecture-design 第 6—7 节，保留缺值条目与顺序，成功缺列表不改判失败；展示与可写身份分开，设备调用期资源及定向消费者范围保持。平台资料只由 architecture-design 提供。 |

最后一次同时明确读取路由和可用共享技能，不能把差异单独归因于某句提示词。该结果证明本题下能够按职责取得必要资料，不证明所有环境都会自动发现或安装依赖技能。缺少平台依据时应报告契约缺口；独立安装不意味着可以脱离目标契约完成所有架构设计。

机械检查：29 项脚本测试通过；两种同步模式的 `--check` 通过；四文件独立技能包的格式、Markdown 引用和搬移验证通过；技能分发目录仅一份平台快照。既有冻结评测及规范源未改写。当前未执行 TS/TSX 编译、Portal 工程测试或真实宿主调用，未取得模型 Token 或延迟数据。本次未提交、推送或安装。
