# Portal 开发技能评测

样本为合成工程，检查代码组织、文件角色、Schema 来源、真实依赖和验证范围；方法名及路径不作为目标业务工程的新契约。rubric、评分和运行输出不提供给被测上下文。

触发与加载分开记录：直接选择的工作入口、补齐规范的资料提供者、实际读取的文件及同一上下文中的重复读取不是同一个指标。共同规则确实缺失时允许按需展开；不能仅按技能数判定重复，也不能把通用技能已经执行当作企业依据已经具备。

代码样本以同一组规则源作对照，再加入技能入口分别运行；触发样本只提供技能描述与项目入口约定，不显式要求使用某一技能。完整记录放在 runs 中，冻结 inputs、outputs 和 manifest 摘要，不回写历史记录。

逐项人工核对代码与语义；未执行编译、实际 SDK、模型或宿主发现时分别标明，不用书面方案或关键词命中证明工程已经接入。

`cases/`、`rubric.md` 和本文件纳入版本管理；`runs/` 中的完整输入、输出、日志和结果仅保留本地，由 `.gitignore` 排除。规范与入口同时变化时，按[分组对照方法](../architecture-design/README.md#可重复执行方式)分别验证。

[单元组织样本](cases/unit-boundaries.md)覆盖新增页面的单元划分、已有计划与检查通过时的文件组织审查，以及合理共享和局部修改。分别记录旧包、仅更新规范、规范与入口一起更新的输出；区分已有要求的执行改善与新增明确规则带来的行为变化。

[SDK 选型样本](cases/sdk-choice.md)检查是否先比较已采用的公开能力，再确定必要自有适配；不把单个库的限制或未提出的防御需求当成自写原生模块的充分依据。样本只作判断回归，不是实际 SDK 选型结论。

[复用与输入契约样本](cases/reuse-contracts.md)检查共享计算、输入拒绝、运行时校验和资源生命周期是否保持各自语义；[状态与范围样本](cases/status-scope.md)检查指定规范可用、登记滞后及局部未定时的执行判断。与[测试迁移样本](../code-testing/cases/test-migration.md)一起覆盖重构中的契约与消费者保护。

[库与 H5 样本](cases/platform-units.md)检查客户端消费与库维护的资料选择、Chat 目标接口与实际发布证据、Design 字体及组件范围、H5 文档和授权交接。记录实际读取文件，按必要依赖评价渐进加载，不以未读取任何依赖作为节省上下文的证明。

[文档站样本](cases/documentation-site.md)检查组件附带 Web 示例时的正式站点路由、展示组织、版本接线和证据边界；同时以组件内部样式及纯原生修复检查过度触发。冻结修改前后相同输入，分别记录路由、读取及具体方案；基线已满足的部分不计为新增改善。

[新库与首次发布样本](cases/library-onboarding.md)区分脚手架现状、组织标准、实际接入与发布历史；同时核对共享 example 的文档站消费者和成熟工程反例。使用固定工程片段与同一已采用组织标准，在隔离目录中按需读取；既有正确判断、模板问题、入口缺口及安装版本差异分别记录，不将模板修复或基线已满足项计为技能增益。

[任务路由](cases/task-routing.md)覆盖事实查询、实现、调试、测试、审查、设计、交付和跨阶段请求；仅提供发现目录与工程入口，不提前提供技能正文。[上下文复用](cases/context-reuse.md)在同一上下文连续执行测试、审查和依据追问，逐次记录真正读取的文件。另用[企业规则应用](cases/enterprise-rules.md)核对缺少规范正文时仍会取得必要依据，避免把少读取误当作正确。

[局部范围与交接](cases/scope-handoff.md)分别检查只改呈现效果时保留其他已确认行为，以及用户明确改变交互时直接落实新范围；核对交接消息是否区分用户决定与技术选择。旧版已满足的判断不计为候选改善。

修改前后固定相同题目、外部技能描述与源码事实；本仓入口模板可以随候选版本变化，目标工程的实际 AGENTS.md 和第三方插件保持单独的外部条件。报告未复现的现象和外部约束；明确区分题目中的已读状态与实际发生的读取，不声称发现目录验证等于所有任务的自动触发。

本地评测完成后可执行 `python scripts/validate_repository.py --include-evals` 检查档案摘要；默认分发包校验不依赖这些运行产物。
