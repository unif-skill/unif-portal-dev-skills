# 原生鸿蒙样本判据

人工检查实际资料选择与具体方案，不按关键词数评分。题设和书面方案均不算真实 SDK、编译或设备证据；规则源可支持已有契约下的开发，不能因缺少正式发布而阻止不依赖发布的本地工作。

| 样本 | 必须观察的判断 | 不支持的结论 |
|---|---|---|
| native-libraries | 原生规范与 HAR／应用分别组织；六库仅为目标，图标及数据同源，框架 UI 分别实现；有公开消费者与产物检查 | 套用 RN 脚手架、Hooks、目录或 npm 发布步骤；六个空包即迁移完成 |
| rn-only | 本次只查 RN 的字号、样式、消费者及相关验证；已有效的字体契约保持 | 因工作区有鸿蒙就同步改鸿蒙、重做页面或新增公共包 |
| shared-ts | 逐文件识别纯计算、RN 导入和 URL 全局；共享数据与平台机制分开；检查目标类型、运行环境及分发 | 无 import、无 JSX 或 Node 通过就直接认定三端可用；两端手写复制源 |
| native-scan-and-evidence | RN 技能可提供参考语义，实际 native API 另核；保留借用文件、取消语义；HAP 不等于扫码成功 | 从 RN 文档虚构鸿蒙 API；取消返回成功；构建即设备验收 |
| native-glass | 保持原布局与操作；核对 API 26 的组件支持、设备与系统设置；主题、字号、无障碍及交互对照 | 所有自定义卡片默认获得系统玻璃效果；静态截图或构建证明视觉达标 |
| identity-and-h5 | 保留身份、迟到回调、文件归属以及 H5 文档和授权边界。按采用的 RN 修订核对营销实际接线，保留原身份 HTTP 401 刷新成功后的一次重试及业务码 1003 的失效结果。常量和类型归入账号已有文件，解析仍在原职责内。聊天附件实现与配套声明归入同一子功能目录，使用 constants.ets 和 types.ets。验证来源于 RN 的行为与实际消费者 | 自行加下单重试例外、扩写 H5 业务、改用平台业务账号、提前删除已交付文件、为已有职责另建重复文件，以单端新增断言证明两端对齐 |

| 补充样本 | 必须观察的判断 | 不支持的结论 |
|---|---|---|
| native-library-docs | 鸿蒙文档与 ArkUI 示例从真实 HAR 公开入口和采用版本维护；网站、宿主、设备分别验；站点工具按本库已采用标准 | 因文档任务强制引入 React／RN Web／Expo；以 iOS／Android 示例替代鸿蒙运行，或将 RN 专题的站点选型强加给未选择工具的原生库 |
| shared-contract-change | 单一 Schema／生成产物及实际服务生产方和两端消费者；可选字节数边界、大小显示与原操作保持；鸿蒙缺实现不得标共同完成 | 复制另一份手写契约、扩大订单行为、改变上传请求／权限／成功条件、RN 完成即三端完成 |

记录每例实际读取的文件、可确定结论、缺失依据和偏差。基线已正确的判断保持，不计为候选新增收益。基线、仅更新规范与完整候选分开报告，输入和公开契约保持一致；读取边界或外部事实不同必须披露，不能宣称严格因果提升、Token 节约或准确率。

本组是书面资料应用样本。真实宿主发现、长对话压缩、生成代码编译、厂商 SDK 与设备行为应由对应任务另行验证。工作区和来源摘要随本地 runs 记录，候选更改后判断哪些样本及输入受影响再复验。
