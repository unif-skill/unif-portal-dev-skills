# 原生六库资料选择样本

每个请求是独立场景。仅作书面判断，不修改产品代码、不安装或发布。只读取评测提供的冻结规范与技能包，记录实际选读路径；没有原生源码或 SDK 时明确对应证据缺口。每例回答实施边界、采用依据、交接和必要验证，不能把规范里的建设目标当作已可调用的 API。

## L1：Icons 的首批实施

目标是 API 26 纯 ArkUI 的 @unif/harmony-icons。RN 已有 SVG 和命名清单，希望先生成可消费图标，并让 Design 按钮使用。是否可以复制 SVG 到新库后分别维护，让图标自动读取 Design 主题？请明确基础尺寸、颜色、命名、公开导出、资源和无障碍的依据及验收；目前只给了规范，没有原生库源码。

## L2：Design 的主题、玻璃与宿主

先实现 @unif/harmony-design 的字体、按钮、输入和浮动确认表面。有人打算搬用整份 RN tokens.ts、在主题和 Text 各乘一次应用字号，并对全部卡片启用玻璃。确认窗口可能被另一宿主接管，旧回调可能迟到。请依据原生规范确定边界与案例，不改变 Unif 已确认布局、交互与业务结果，也不要凭空给出 ArkUI 导出名。

## L3：Camera 拍照选用与退出

鸿蒙附件拍照支持单拍／连拍／录像、预览选用、水印与 retention clear／retain。旧拍照处理未返回时新 open 到达；新输入可能非法、也可能已经取消。用户未同意丢弃时切换模式；成功选用后立即关页，旧处理才落盘。请说明应该核对和保留的结果、状态、权限及文件责任，列出真实设备验收，不能用图片扫码测试代替。

## L4：Scan 图片借用与主题变化

原生扫码页借用相册文件解码。页面在 SDK 读文件期间关闭，随后又打开一次扫描；同时系统字号和主题变化。要求保留默认人工选用、无结果与技术错误区分、手电真实状态；不要让扫码库判断商品业务。请说明借用释放、迟到回调、结果交付和原生／RN 资料选择。

## L5：Umeng 与地图提供方

API 26 的 @unif/harmony-umeng 要保持隐私同意后初始化、统计、分享面板和真实渠道回执。有人建议先用系统分享作为完成演示，再顺便把分享位置的 POI 换成华为 Map Kit。请说明依赖、宿主、取消／失败／未知回执及验收依据；没有厂商 SDK 时哪些工作可以完成，哪些不能声称已通过。

## L6：Chat、共享 TS 与 RN 局部任务

分开回答三项互不授权扩大的工作：A. 鸿蒙 Chat 输入区在主聊天和订单抽屉复用，要求保留草稿、附件、发送／停止和键盘行为；B. 提议把无 import 但调用 URL 的 TS 校验、颜色数据和相机变焦计算一起放入 @unif/utils；C. 当前只修 RN Design 一处大字号显示，但工作区同时有鸿蒙库。说明各自需要哪些资料、依赖和消费者验证，构建／Node 断言通过可报告到哪一层。
