# 开发流程判断

以下均是合成任务，只给实施顺序、所需技能与验证范围，不写业务代码，不执行工程或外部动作。只在指定输出文件写结论。

A：工程采用目标架构，已在独立分支。用户要求将 Cell 的命名固定提示迁入所属 constants.ts；需求、类型、行为和消费者不变。现有真实组件测试、lint 与类型检查覆盖本次内容，改后已执行成功。团队说必须重新开完整架构设计，再单独启动 testing/review/delivery 三轮并全量重跑所有领域，即使用户只要求文件整理也必须提交推送。

B：用户明确授权实现一个已设计的查询小功能，本批没有提交、发布授权。契约已给全，调用每次请求指定页，无缓存，成功和异常交接明确。预计两处消费者需要接线，测试尚未编写。团队建议所有开发结束并提交后再开始测试，review 只看最终提交。后来审查发现其中一处消费者固定第一页，修复后有人建议直接交付、沿用修复前的绿色结果。

请分别给出合理的完成路径，说明是否需要全部技能依次加载，测试与审查在何时发生，以及任务只授权实现时交付在哪里结束。如果某个协作技能没有安装，能否依据工程规则继续相应工作？不要把 A 的已有测试结果用于 B。
