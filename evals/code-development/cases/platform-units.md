# 库与 H5 接入的按需阅读

以下是合成维护任务。使用提供的技能包和指定规范源，分别给出实际需要读取的资料、实现归属、允许的变化与验证范围。只做判断，不修改工程或执行安装、网络、构建及发布。不要把题目中的目标接口认定为真实 npm 包已提供的能力。

## 1. 库维护与应用消费

本次在 @unif/react-native-design 库修正一个组件内部的图片尺寸计算，公开参数不变。另一个 Portal 任务只需按现有公开 props 使用这个组件。有人建议两个任务都按 Portal 的 capabilities 目录组织，并分别读取全部 Design、Chat 与 H5 规范，收尾都运行整个 Portal 全量检查。请分别确定两项任务的依据与范围。

## 2. Chat 与目标接口

新架构已经定义独立 @unif/react-native-chat。需求是在订单抽屉使用受控 Composer、展示准备中的附件；场景持有草稿、上传与提交。当前材料只有设计契约，没有所采用 Chat 包的公开类型或发布证明。候选方案沿用旧 @/agent/components/chat 导入，并让 Composer 上传、发送成功后清空草稿、取消时删除文件。请审查当前能推进什么、还缺什么依据，以及组件和场景的交接。

## 3. Design 字体与未来扩展

需求只修正 CircularProgress 百分比文字随应用字体变化的行为，不改圆环几何。实现使用 useFontScale 先乘字号，又把相同字号交给 useThemedStyles；为解决这一问题，计划顺带实现设计文档中的 Thumbnail 尺寸扩展并重排全库目录。请判断需要读取的 Design 资料、修改边界和验证。

## 4. H5 原调用归属

H5 分享请求处理中，同 URL 页面发生真实重载，随后旧分享返回成功。另一次请求等待期间仅更新同一授权内的凭据。方案把两者都用当前 URL 和账号字符串判断，向当前 WebView 回包；通道外层 code 为 200 时直接展示分享成功。请说明契约读取顺序、需要修正的交接及验证，不新增协议字段、重发或业务确认。
