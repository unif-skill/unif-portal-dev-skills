# 工作请求与技能入口

未另标平台的客户端、测试和审查题设均来自 Unif RN 工程；后端与原生鸿蒙题设按其明确平台处理。

这些是彼此独立的合成任务。判断的是各条用户请求所需的工作，不是本评测写结论的动作。根据给定技能目录和工程入口约定，列出应进入的企业技能、为取得规范可能需要的提供者、适用的外部技能及理由；未进入的阶段不安排动作。不要执行真实工程、网络、测试、Git 或安装操作。

工程采用指定的 Unif 规范。没有单独给出的需求、交付授权或产品行为。

| 编号 | 用户请求与当前条件 |
|---|---|
| Q1 | 新 Portal 中有 expo-audio 补丁。用户问“最新发布版本有处理这个补丁的问题吗？”只要求读补丁、版本元数据与上游对应源码，回答覆盖情况。 |
| Q2 | 用户问当前安装 SDK 的一个字段是什么含义、默认值在哪里定义。只需解释已发布接口，不要求选型、升级或评审实现。 |
| Q3 | 用户问指定 CI 作业现在是排队、运行中还是完成。只读作业状态，不要求重跑或决定合并。 |
| I1 | 修改已有 Portal 组件的 props 和样式，行为及契约已确认，不改变模块职责。 |
| D1 | 定位新 Portal 切换账号后旧异步结果仍更新页面的原因，先给诊断结论，不修改。现有契约已经规定原调用归属。 |
| T1 | 在工程约定的环境运行用户给定的三个测试文件并报告结果，不改源码、不提交。 |
| T2 | 审核覆盖率很高却漏回归的原因，并补充真实行为断言；不是对整个产品做代码审查。 |
| R1 | 用户明确要求审查当前 PR 的代码变更，找出违反已确认文件规则或业务契约的缺陷，只给审查结果。 |
| A1 | 设计一个新的跨模块确认与结果交接方案，确定职责、状态及公共契约；不实现、不提交。 |
| G1 | 用户已授权推送并创建 PR。本次提交和定向验证已就绪，需核对交付证据和当前 required CI；不要求改产品代码。 |
| G2 | 用户仅要求将已确认的本地分支推送到指定远端，不创建 PR、不改源码；先按工程约定核对本次推送条件。 |
| M1 | 实现已确认的小改动、补相关测试并审查结果，同一任务内连续推进；没有提交、推送或发布授权。 |
| C1 | 当前提交、规范版本和范围未变，同一上下文已读适用技能及文件／测试规范。用户继续问审查结论的一处依据；没有新修改。 |
| C2 | 独立审查子任务只有 diff 和契约文件路径，没有父任务读过的正文。“父任务已读企业规则”是否足以省略本任务必要依据？ |
| C3 | 同一上下文已读旧规范，但任务明确改用新修订，其中只有输入约束变化。继续核对这一约束及消费者，不要求重新开展其他阶段。 |
| L1 | 在 @unif Design 库修正组件内部布局，公开 props 不变；只涉及本组件和实际使用者。 |
| L2 | 在 Portal 中按已发布的 Design props 组合界面，不维护该库源码。 |
| H1 | 按既有 H5 契约修正原文档回包映射；不是改造整个 WebView 引擎或营销流程。 |
| X1 | 业务用户说“开始今天的拜访”，不是工程开发请求。 |

输出每项的 `id`、`entries`、`providers`、`external`、`reason`。entries 是当前工作入口；providers 是尚缺必要规范时才需取得的资料来源，二者分开列。另外指出外部入口或通用技能的规定是否对结论形成约束，不自行改写它们。不要读取评分标准、另一版本或其他任务。
