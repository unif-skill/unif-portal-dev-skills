# 人工判据

判据不提供给被测上下文。评测者核对文件归属、代码、状态和实际调用，不按关键词出现次数计分。题设是合成契约，不作为真实 API；方案未执行代码或设备操作时不能声称已接入。

| 判据 | 满足条件 |
|---|---|
| C1 | ChoicePanel 复用 CellList 和设计系统；props 与条目对象放所属 types.ts，固定 EMPTY_MESSAGE 放 constants.ts，主题样式工厂放 styles.ts，运行期颜色与派生列表留组件；移除无用 ref。 |
| C2 | 不新增同名基础包装、业务 store/请求或空角色文件；公开入口只导出实际公共组件与必要类型，不把全部内部内容送进总 barrel。 |
| C3 | 验证真实组件渲染、选择回调、中文空态、主题及两个消费者；明确 Web 接入和必要宿主的证据，不复制组件库全部测试。 |
| D1 | PickInput、PickerSdk 及显式参数对象归所属 types.ts；DEFAULT_LIMIT 归 constants.ts；controller、Map、limit、files 和注入 SDK 仍保持调用或实例归属，不引入全局共享或变量文件。 |
| D2 | 保留实际 pickImage 行为、依赖由 bootstrap 正向组装，能力不反向读 app；不把 Web 替身成功当正式实现。仅整理先测真实能力及受影响接线，未来公共常量/取消/资源或宿主变化才扩大相关消费者和平台验证。 |
| D3 | 原始 DTO、码表和映射留所属适配单元；按数值业务码解释，成功缺显示字段和 null 行仍保留，读取与写入身份分开，不默认选择、保存或按页面重复实现。 |
| D4 | readReasons 测试运行真实映射、替换外部网络，验证数组顺序/缺值、码类型、无写入及原因选择交接；不因同领域或同文件重测不相关能力，也不只看类型通过。 |
| U1 | 已有 Schema 为唯一源，types.ts 按需派生/导出；不重复手写字段或为其他单元引入新框架。 |
| U2 | trimLabel 原批次保持单文件；增长批次形成 trimLabel 单元及实际 types/constants/实现，不为私有辅助单建目录或公共 utils 层。 |
| U3 | hook 实例与请求期资源保持原有隔离，固定展示映射归所属 constants.ts；不按 const 文本搬运，不建立 variables.ts 或新持久状态。 |
| U4 | env.ts、资源声明及生成器文件保留各自约定；生成文件改源重生成，公开类型/常量/配置变更追踪真实消费者与语义，不用 any 或私有类型导入掩盖问题。 |
| T1 | 文件修改 1/2/3 应使用 code-development；4 仅 architecture-design；5/6/7 不因名称相似套用 Portal 文件规则；8 同时需要开发规则和必要架构设计；9 以 code-testing 为专项入口。说明使用技能不等于静态检查已接入。 |
| B1 | call-boundaries 中 readReasons 的必需输入来自参数；缺参返回输入错误，不读当前客户、草稿或交互补齐；缓存不跳过本次调用。按实际代码依赖和调用判断。 |
| B2 | 字段映射不增加 detail 或翻页请求；读取指定页并把翻页信息交回交互。缺值行、顺序、成功码和后续真实身份要求保持有效，查询不等待选择或确认。 |
| B3 | 测试实际导出的 readReasons，替换外部 API；核对参数、调用次数、结果和消费者交接，孤立辅助算法不替代公共调用链证据。 |
| N1 | internal-coordination 的 ensureDraft 保留已确认的查询及缺失时创建；命中不创建，异常不重试；不要求两个既有消费者重建这项能力。 |
| N2 | capturePhoto 保留本次会话、选用、持久化与临时文件收尾；成功、取消和失败均释放已取得资源，状态按调用归属，不把设备资源交给 UI 或引入业务上传提交。 |
| N3 | 等价文件整理按实际内容形成类型、实现和必要出口，沿用有效设计与验证；不等待全领域重设计，不为每个内部步骤新增公共函数或角色空文件。 |
| W1 | rewrite 中旧代码与测试用于提取输入输出、取消/保存行为及外部约束；新工程自有实现和测试按目标契约编写，不以复制旧组件、逻辑、mocks 后改名修补作为重写。根据实际方案与产物判断，不按代码相似度或关键词评分。 |
| W2 | ActionButton 直接从已采用的组件库使用；两个入口经 Portal 的 capturePhoto 公共契约拍摄，由所属能力接入相机 SDK，并复用 saveAttachment 及已有公开类型。不绕过 Portal 设备契约，不复制包源码、自造 SDK、存储或同义接口，也不因旧工程使用过就引入未确认依赖。 |
| W3 | collectAttachment 的输入与依赖显式，成功、取消、异常、重复及并发调用的参数、次数和结果符合目标契约；共享实现不自动引入结果缓存或共用草稿/确认。UI 接线使用新功能，测试运行真实导出函数，不复制旧启动环境或 mock 被测对象。 |
| W4 | 巡检查询和巡检拍照附件组合按领域职责保留，设备操作按基础能力职责保留；不因多个入口使用就移到全局组件或 utils，不新增集中状态或总 barrel。 |
| P1 | protocol-boundaries 中公共函数、类型和 QueryPickerHost 不自动增加 HTTP、H5 或模型工具协议；实际对外请求仍只有已确认的 GET /catalog/items，协议清单与代码一致。 |
| P2 | queryItems 在自身链路完成内部准备再请求指定页，纯数据调用不要求消费者预调用 prepare、确认或挂载 UI；异常不转换为额外前置请求，普通代码准备与 HTTP 请求分别核对。 |
| P3 | 需要选择的入口通过 picker 使用同一 queryItems；只取数据的场景直接调用查询函数。测试运行真实导出函数并替换外部 client/picker，验证参数、次序、页码与取消/异常路径，不以宿主存在代替实际接线证据。 |
| S1 | preparation-scope 中区分已批准的目录/资源准备、技能对齐、功能实现、运行接线和安装生效；目录标记不证明能力存在，不据未执行的构建或测试宣称运行通过。 |
| S2 | 本轮只维护技能与必要验证；App/index、旧测试、CI、工程规则和原生接线等列为待确认范围，不以同步消费者或换执行路径为由绕过范围拒绝，也不把本次准备方式写成通用模板。 |
| S3 | 后续按明确功能核对契约、实际消费者和采用依据；旧自有代码用于理解后按契约重写，SDK/组件库及原生配置按已确认需要接入；公共符号不自动增加外部协议。另有充分授权与依据的小功能可以按独立批次推进，不等待全领域或全部目录就绪。 |

workflow.md 单独比较原开发入口和候选入口：A 沿用有效设计与验证，不强制依次加载全部技能或全量重跑；B 测试随实现完成，审查修复后补充受影响验证，交付止于授权范围。协作技能不可用时能依据工程规则继续，确有依据缺口时仅限制依赖该缺口的工作。

每个代码场景先给规则源形成对照，再给相同规则与技能入口形成技能组；各次使用不继承作者讨论的独立上下文。触发样本单独只提供发现阶段的描述与入口约定。保留原始输出及哈希，报告遗漏和不确定性；少量样本不证明真实自动触发、生产正确率或 Token 收益。
