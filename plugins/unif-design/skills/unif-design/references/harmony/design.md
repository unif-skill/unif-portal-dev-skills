# @unif/harmony-design 实施规范

本文是 API 26 纯 ArkTS／ArkUI Design 的实施与验收依据，不声明同名 RN 组件已经有原生导出。行为范围按 RN Design（规范源相对路径：`libraries/react-native-design.md`）、公开单元索引（规范源相对路径：`libraries/react-native-design/units.md`）及对应组件契约逐项对照；签名、宿主接线和可用性从所采用原生库确认。


## 1. 职责与依赖

Design 拥有主题、字体、基础组件、通用组合和必要 UI 宿主；业务值、持久化设置、导航、接口、草稿与业务成功仍归消费者。图形直接消费 [Icons](https://github.com/unif-design/unif-platform-architecture/blob/main/libraries/harmony-icons.md#1-职责与依赖)，不复制 SVG、生成器或图标命名入口。

共享的是有明确来源的颜色、基础尺寸等设计数据；RN `tokens.ts` 含平台选择、样式与缩放，不能整份作为共享数据。基础数据由单一源生成或打包，两端样式、字体族、单位、资源解析和系统偏好分别适配；主题基础不反向依赖具体控件或应用。公共控件复用真实组件族内部能力，不新增通用状态容器。


## 2. 公开契约与对齐

| 单元 | 输入、输出与对齐范围 |
|---|---|
| 主题／字体 | 消费应用选择和系统外观；解析后的显示值作用于明确子树；不替应用保存设置，不在每个控件再建默认主题 |
| 按钮／图标操作／选择 | 保持标签、图标槽位、disabled／loading、选择值和事件语义；点击交付动作，不能推导业务完成 |
| 单行／多行／搜索等输入 | 保持受控值、输入／提交／焦点事件、原有默认及高度边界；清空、密码可见性等按所属控件契约，不能清外部草稿 |
| 媒体／进度／布局 | 图片尺寸、失败占位、预览事件、已知与未知进度、头尾及有界内容区保持原语义；不取得业务文件所有权 |
| 确认／提示 | 只管理显示、用户选择和本次 UI 请求；显式确认不等于业务已提交；原组件已有确认不能再叠一轮 |

公开单元按 RN 索引逐项记录“对应能力、已实现／缺口、真实原生出口、消费者、证据”，不把首批按钮／输入覆盖视为整库覆盖。原生调用形态按 ArkUI 表达，不照搬 Hooks、ReactNode、ref、CSS 或 RN 样式对象。

### 字体与单位

应用字体倍数只在所属文字出口计算一次。基础值、主题派生、组件计算和最终 Text 之间明确哪一处已缩放；字号、行高和字距各自核对，不把已经缩放的 token 再乘一遍。系统字号遵循原生文字单位和系统配置，不手工重复乘系统系数，也不能为固定容器关闭无障碍字号。图标、图片、描边、控件几何不跟着应用字体整体等比放大；必要自然布局变化单独验证。非法字号按已采用语义归一化，不能让非法值污染整棵 UI。

### 玻璃与原生载体

材料选型遵循[原生 UI 规则](https://github.com/unif-design/unif-platform-architecture/blob/main/HARMONY_STRUCTURE.md#2-组件主题与玻璃材质)。保留 Unif 布局、内容、圆角、颜色角色、入口和交互；先确定实际组件及所在区域，再核对系统材质是否支持。表面是否支持玻璃，不由控件名称或透明截图判断。

Design 说明其组件需要的材质宿主接线，消费应用控制应用级材质选择。具体 SDK 入口及支持条件按所采用的平台通用标准核对，本契约只维护 Unif 的表面映射、视觉和交互要求。

不支持的位置保持可读、可操作的已确认表面并记录差异；普通模糊和透明色不是沉浸式系统材质验收。材质是装饰，不截获触摸或增加读屏动作，不改层级以获得效果。明暗、系统降低效果、键盘和嵌入窗口各自验证；材质更新不能触发业务动作或重启调用。


## 3. 状态、资源与结束

应用拥有主题／字号选择，原生宿主提供有效 Context 与系统配置，Design 负责所属显示订阅及释放。外部受控值保持单一所有者；焦点、测量、展开、图片加载和动画属于组件实例，旧图像／动画回调不能修改新内容。

确认与提示是两项局部 UI 功能，不推广为全库运行容器。按确认与提示契约（规范源相对路径：`libraries/react-native-design/hosts.md`）保留：确认只对明确选择交付确认；系统返回、无宿主、重入或宿主结束不能被当成确认，也不能一律称为用户拒绝；不增加隐式确认队列。只结算原活跃请求一次，接管／归还或旧回调不得确认、关闭新请求。

Toast 的最近提示覆盖、无宿主及计时规则沿原契约，播报与计时绑定本次显示，不变成业务重试或持久通知。原生弹窗／窗口的呈现者拥有其 UIContext 和显示资源，真实结束后释放；不能机械移植 RN Modal 生命周期。页面暂时不可见、进入后台与实例销毁分别处理。

控件保留可访问名称、焦点顺序、触摸面积、禁用和加载语义；装饰隐藏于读屏，确认呈现时焦点进入有效内容并在结束后按实际宿主恢复。错误和状态不能只用颜色表达。诊断不包含密码、输入正文、媒体地址或凭据。


## 4. 验证与采用

首批可直接按主题数据、单次字体出口、Icons 消费、按钮／输入、浮动确认表面实施；其余公开单元逐项接入同一规范。

| 层级 | 必要证据 |
|---|---|
| 源码／自动化 | 数据与平台样式分离；合法／非法字号、系统与应用系数、主题更新、受控值、确认重入／接管／旧回调和提示计时；组件族及真实消费者 |
| 产物／构建 | HAR 与独立 ArkUI 宿主从真实公开出口接线主题、图标、输入和弹窗；打包资源和依赖可用 |
| 设备 | 相同内容／窗口／主题下核对 Unif 外观、中文输入与键盘、大字号、读屏／焦点、系统材质开关及实际支持位置；不同窗口验证提示／确认确实呈现 |
| 业务消费者 | 页面／Chat 等调用方仍拥有草稿、操作许可和业务成功；确认结果回来后由原场景复核对象与身份 |

模板、静态网页或替身只证明对应层；按钮可运行不代表全部 Design 完成，原生构建不代表玻璃和无障碍验收。
