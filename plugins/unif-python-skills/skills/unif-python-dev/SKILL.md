# 后端代码开发

承诺后端改法前，按当前目标、职责契约及实际请求消费者核实前提和影响。新发现的事实偏差、事务或调用影响尚未确认时，说明证据和后果请用户决定；已知情确认的变更与无实质疑点的调整直接推进。接续时沿用最新决定，复核变化的实现与接线。优先采用目标工程指定的规范修订；同一上下文中仍适用的依据直接复用，按本次范围选择资料：

- 修改范围与现有行为：[实施范围](references/scope.md)；第三方库、框架或 SDK 的设计、接入、封装与排障：[依赖治理](references/common/verification.md#71-依赖治理)，核对官方依据与项目采用条件。
- 顶层 agent、capabilities 与 core/services 的职责、包公共入口及依赖方向：[目录与依赖](references/structure.md)。
- 新增或整理领域能力：按[目录与依赖](references/structure.md)区分智能体自身的指令与编排、可独立复用的领域能力和通用基础服务；核对能力声明、已有资料、启动装配及真实消费者，保留公共契约同源。
- 服务配置、环境变体及启动接线：[目录与依赖](references/structure.md)、[契约与验证](references/validation.md)。
- 异步执行、取消、收尾、事务及调用预算：[运行与资源](references/lifecycle.md)。
- 持久化、恢复、跨设备同步、业务记录创建，或异步处理、状态交接、资源收尾：读取[状态归属](references/common/state.md)，核对权威来源、唯一性、执行归属及对应验证；读取共同规则不重启架构设计。
- BasedPyright、同源契约、任务指令、消费者接线和验证证据：[契约与验证](references/validation.md)。
- 外部依赖、持久化、异常转换、异步收尾、降级或恢复变化：同时读取[验证与故障诊断](references/common/verification.md#721-日志与故障诊断)，核对责任边界和对应测试。

沿实际请求、任务或启动入口核对已有实现的输入输出、副作用、状态所有者、依赖库能力及消费者，优先复用或原处扩展；现有实现无法合理满足有效契约时，在授权内替换或新增并说明缺口。不同入口不另建同职责流程，保留服务、事务与运行生命周期差异；替换时完成调用迁移，清理经核实已失效且无消费者的实现。结构重构对照实际装配文本、事务和资源路径；发现行为缺陷时保留可复现条件并执行相应回归。通过所属工程现有检查验证实际改动。

公共输入输出按[交接契约](references/common/contracts.md)核对；模块职责或状态归属实质变化时先取得已确认设计。按本目录资料及目标工程采用的规范实施，不因取得规范扩大任务或重启流程。领域契约从工程采用的架构源取得，来源记录见 references/source.json。
