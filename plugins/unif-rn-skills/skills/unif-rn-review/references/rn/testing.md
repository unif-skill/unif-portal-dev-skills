环境配置验证以本次选定的环境源为准：既有入口为本机 debug、测试 beta 和正式 prod，新增独立环境按有效契约核对。检查 `ENVFILE` 与 SDK 临时选择的优先级、`.env` 加载副本与选定源的一致性及受支持的临时覆盖；核对完整变量和布局，不输出敏感值。结构检查通过不代替构建或进程实际加载。

涉及外部依赖、持久化、异常转换、异步收尾、降级或恢复时，按[日志与故障诊断](../common/verification.md#721-日志与故障诊断)核对已有记录和本次失败路径。

## 6. 分批重写与定向验证

新实现按可独立使用的单元分批完成：根据目标契约编写代码、必要类型和常量、样式、定向测试及宿主接线，并接入实际需要的资源。旧 Portal 的组件、工具、适配和测试用于理解行为、逻辑结果及依赖约束，不通过复制后局部修补形成新实现。新测试按目标契约编写，旧测试仅提供行为样本与核对线索，不整套搬入旧用例、mock 和目录依赖。

现状行为与目标职责对照用于定位证据和检查依赖，不是文件复制清单，也不替代目标契约。具体执行批次说明实现哪些单元、依赖接到哪里、相关消费者怎样验证；所需契约齐备的单元可独立推进，无需等待无关领域或服务端契约完成。

Portal 测试按 `src` 的责任归属放在 `__tests__/`；本项目的消费者关系按以下契约定位，通用测试方法与平台流程由工程采用标准维护：

| 变化对象 | Portal 消费与验收 |
|---|---|
| Design／Chat 的应用接入 | Portal 验证自身组合、主题和宿主接线；库内部行为由所属库工程验证 |
| ScreenHeader、Sheet、图片预览与键盘组合 | 按对应组件契约核对原生导航、弹层、中文内容及场景操作 |
| capabilities 设备与本地能力 | 按本能力契约核对页面、对话及实际 H5 消费者的结果与资源交接 |
| integrations/h5 | 按消息协议核对原文档、授权、来源与结果映射，不以 SDK 调用完成冒充业务成功 |
| Agent 流与聊天展示 | 核对 integrations/agent 与 app/chat 的转换、展示及领域结果交接 |
| 账号、订单、拜访等场景 | 采用所属业务契约的身份、草稿、确认及恢复用例 |

系统合并与发布执行 Portal 工程配置的完整门禁。

开发一个单元时，按本次变更选读相关代码归属规则、该单元契约、实现、直接依赖与对应测试。现状行为与目标职责对照、其他领域文档及模型评测仅在当前变化确实涉及它们时读取。目录和测试组织的收益在实际变更中按平台架构第 8 节（规范源相对路径：`ARCHITECTURE.md#8-成本与效果验证`）测量。
