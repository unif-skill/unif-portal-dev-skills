# @unif/harmony-icons 实施规范

本文定义 API 26 纯 ArkTS／ArkUI 图标库的职责与验收，不声明包已发布或原生 API 已存在。行为对照见 RN Icons 契约（规范源相对路径：`libraries/react-native-icons.md`），实际导出、参数类型和资源入口由所采用原生库的公开源码与文档确认。Unif 项目入口约定见[文件与公共入口](https://github.com/unif-design/unif-platform-architecture/blob/main/HARMONY_DEVELOPMENT.md#2-arkts-文件与公共入口)。


## 1. 职责与依赖

Icons 拥有图标图形、稳定命名及平台生成产物。Design 和其他绘制图标的消费者直接使用其公开入口；Icons 不反向依赖 Design，不读取主题、应用字号、账号或业务状态。颜色和尺寸由消费者显式交入，控件负责交互、禁用、加载与命中区域。

已有 RN Icons 的 `src/svg/` 与 `scripts/icon-manifest.json` 是首批应核对的图形及命名源，不能复制到鸿蒙库后分别维护。沿既有严格校验和生成器扩展目标产物；源归属迁移须同步真实消费者，源修订、生成规则、命名清单和产物摘要可追溯。生成器属于构建依赖，HAR 运行时不依赖 Node、React、RN 或源仓私有路径。


## 2. 公开契约与对齐

| 交接 | 原生端保持的语义 |
|---|---|
| 名称与导出 | 与同一清单的图形身份对应，由生成器产生命名公开入口；ArkUI 组件／Builder／资源形态按实际编译确定，不把 React 组件类型当原生类型 |
| 尺寸 | 默认保持 24 个逻辑布局单位的宽高；映射到原生布局单位，不能变成物理像素，也不隐式随屏宽或文字倍数缩放 |
| 颜色与描边 | 默认黑色；显式颜色保持含义；未覆盖描边时使用图形源值；保留填充、空心、透明度、裁切及坐标语义 |
| 图标槽位 | 消费方只接真实公开的原生展示入口，不深导入生成目录，不复制几何，也不由 Design 再导出一套图标 API |
| 数据边界 | 组件或资源句柄留在 UI 层；业务动作 ID、POI 类别到图标的选择由消费者持有，不把展示对象放进 HTTP、缓存或模型协议 |

资源转换需证明原 SVG 所需特性在目标渲染路径中成立。遇到无法表达的描边、遮罩、渐变或多色内容，保留失败诊断并选择可验证的转换，不悄悄删节点、统一染色或换成名字相似的系统图标。品牌 Logo、分享渠道标识和进度画布仍按各自职责维护。


## 3. 状态、资源与结束

图标本身只渲染输入；不创建业务请求、进程级注册表、设备会话或取消流程。打包资源由包拥有，消费者不删除；如所选渲染路径确需临时解码对象，创建者按原生生命周期释放，只作用于该显示实例。

图标默认是装饰，不能产生重复读屏节点；父 Button／IconButton 等实际操作控件提供名称、焦点、触摸面积和禁用语义。独立表达有意义状态的图形由消费者给出等价可访问说明，不能仅以颜色传达状态。多实例、主题或尺寸更新互不写入共享可变图形；渲染失败不能改变父控件动作或业务结果。


## 4. 验证与采用

首批 Icons 的开工依据是同源 SVG／清单、上述默认行为和公开出口边界。先对清单做集合比对，再检查代表图形：轮廓／填充、源描边／覆盖、透明区域和明确排除的品牌图形；单次生成成功不足以证明全清单没有缺失、重名或陈旧产物。

| 层级 | 必要证据 |
|---|---|
| 源码／生成 | SVG 校验、命名唯一、清单与导出及资源一一对应；重复生成无漂移；没有第二份手维源或 Design 反向依赖 |
| 自动化 | 代表图形转换与默认／显式参数、缺失或不支持源的失败；RN 原生成目标保持 |
| 产物／构建 | 从 HAR 公开入口在独立 ArkUI 宿主导入，资源随包可解析；没有依赖作者路径；实际 Design 图标槽位消费 |
| 设备／消费者 | 同尺寸、主题和倍率下对照图形、颜色与裁切；大字号不额外放大图标，父控件读屏及点击／禁用正确 |

RN 与鸿蒙各自记录修订和证据。只有规范和生成物时，不能登记为原生图标功能完成；Design 可依据本规范先确定依赖方向，但具体调用须等待可编译的原生出口。
