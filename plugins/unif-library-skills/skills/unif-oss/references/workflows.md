# OSS 接入与维护

## 应用消费

从既有上传入口追踪凭证、目标对象、源文件持有及业务采用。使用 provided 或 managed 授权的实际契约；宿主响应适配保持严格校验，库的凭证快照不替代后端协议验证。

取消或身份切换后，即使换发请求忽略信号，也应结束本地等待并拒绝迟到缓存。取消一个调用不能清除其他调用仍有效的缓存；dispose 不等于服务端撤销 STS。

发送前需要恢复信息时，按 onRequestStarted 的实际契约保留对象身份；回调异常和取消不能绕过发送保护。上传结果与源文件不再被读取是两个时点，消费者在 onSourceReleased 后释放自己的持有，不按 JS 结算提前删除。

转存复用 Files 的能力，宿主提供原有私有目录与唯一标识，保留签名 URL、下载阶段和上传阶段差异。maxBytes 的上传约束不自动构成下载大小限制，业务限制须核对实际入口。

## 维护与定向验证

从 docs/DEVELOPMENT.md、package.json、src/index.ts 和平台实现定位归属。BlobUtil 等 SDK 必要补丁由宿主维护；核对实际解析副本、独立原生终态通知和异常关闭源流，不在库复制补丁或用 JS 完成替代原生结束。

- 以真实凭证访问→上传→文件持有者验证取消、身份失效、迟到成功／拒绝和并发隔离。
- 核对明确成功／拒绝／未确认回执、发送前回调异常、原生迟到终态和只释放一次；清理失败保留原回执与安全诊断。
- 转存与批量覆盖私有文件归属、准备失败、单项失败、未开始项及已成功项保留。
- 库测试、宿主 SDK 集成、真实 tarball 消费、平台构建及真实服务分别取得证据；未经授权不获取 STS 或发起上传。
