## 5. 验证与交付

Unif 原生验收对照所属契约和实际消费者，按变更影响选取下列项目对象：

| 对象 | 项目验收重点 |
|---|---|
| Icons／Design | 既有图形清单、默认图形语义、主题与字号来源；Design 和应用的实际图标消费 |
| Chat | 主聊天与嵌入输入组合，草稿、附件、上传与停止仍由原应用场景决定 |
| Camera／Scan／Umeng | 选用与取消、图片借用、同意后初始化、真实分享回执及应用交接，按各库原生契约逐项验收 |
| RN／鸿蒙共同功能 | 共同案例、各端修订、真实消费者和已确认的平台差异 |
| 协议与业务身份 | 登录／会话变化、HTTP／SSE／上传业务结果及 H5 的来源、文档、授权和重复处理边界 |
| 项目视觉 | 有效设计规定的 RN 内容、布局、颜色角色、入口与交互；各 Unif 表面的原生载体与降效记录 |

六库规范中的能力目标、实际实现和消费者验收分别登记。同仓源码依赖以鸿蒙应用构建和实际调用验收。独立发包时用产出的 HAR 验证公开入口、资源与依赖，发布后检验指定版本的安装。产品实施、发布和业务操作分别遵循相应授权。
