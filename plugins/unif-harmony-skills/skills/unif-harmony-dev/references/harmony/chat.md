# @unif/harmony-chat 实施规范

本文是 API 26 原生聊天 UI 的规划契约与验收依据；真实 ArkUI 公开入口由采用库确认，不把 RN 的组件／Hook 当作原生 API。行为来自 RN Chat（规范源相对路径：`libraries/react-native-chat.md`）及其逐组件契约，Unif 项目采用见[原生开发](scope.md#1-适用范围与实施)。


## 1. 职责与依赖

Chat 拥有消息、列表、输入、附件及过程／来源／确认／反馈的显示和组合；应用拥有会话、草稿、上传、SSE、模型／业务调用和最终结果。依赖 [Design](design.md#1-职责与依赖) 和实际使用的 [Icons](icons.md#1-职责与依赖)，不复制主题、输入控件或媒体占位逻辑。

Markdown 采用经过核验的原生可用渲染能力，按完整依赖及平台产物决定；RN 渲染器不是 ArkUI 默认依赖。不为迁移复制解析引擎或引入 React。无合适依赖时明确缺口及其功能影响，不将纯文本演示登记为 Markdown 能力完成。


## 2. 公开契约与对齐

| 单元 | 保留的公共语义 |
|---|---|
| 消息／列表 | 外部消息快照与稳定项身份、内容扩展、初始定位、末尾跟随、前插位置保持、显式历史入口；不创建会话服务或业务已读事实 |
| Composer | 受控文字、发送／停止／等待、附件和语音状态及入口事件；发送不自行清稿，显示录音不等于执行采集 |
| 附件 | 输入区与消息区共用显示数据；名称、缩略图、已知／未知进度、处理状态及预览／移除事件；不下载、上传或删除业务文件 |
| 过程／来源／反馈 | 消费已整理的内容与事件，不解析工具协议、自动重试、执行任务或推断成功 |
| 内联确认／建议 | 交付原对象与明确动作；确认有效性、填入／发送／执行由场景决定，不自行再弹确认 |

按 RN 逐组件契约建立原生能力对照，保留完整输入和操作语义；原生 Builder／控制器只开放必要 UI 操作，不用于提交订单或改应用草稿。主聊天与订单抽屉通过公开组件组合，抽屉仅消费输入区不需要另一份完整聊天历史。


## 3. 状态、资源与结束

光标、焦点、展开、测量、滚动及展示动画属于相应组件。会话、附件集合及真实处理进度属于调用方；UI 的 loading／disabled 不替代场景防重。旧会话的测量、动画与异步展示回调只归旧实例，不改变新会话事实。

键盘抬升、安全区、滚动与手势由实际区域的拥有者各处理一次；组件交付必要尺寸和事件，不猜测导航栈。销毁 Chat 只释放自己的订阅和显示资源，不擅自停止已提交业务请求或删除附件；停止按钮交付停止意图，是否可取消由原操作契约决定。

读屏名称、发送／停止可用状态、消息顺序和进度播报按实际内容提供；累计流式文本不能导致每个字符重复抢读，不能借播报调度改变消息。大字号、中文输入法、长文和滚动聚焦保留操作可达性。


## 4. 验证与采用

源码／自动化检查受控值、事件原对象、发送不清稿、已知／未知进度、稳定项身份和迟到回调；使用真实 Design 组件核对主题／字号只计算一次，不能全用空壳替身。

HAR 通过独立 ArkUI 宿主公开入口分别组合主聊天与嵌入输入；打包及构建单独记录。设备检查前插／跟随、长文／代码／表格和流式 Markdown、图片失败、大字号、键盘及读屏。业务消费者另验会话切换、上传和停止语义；纯组件示例不证明真实 Agent 或业务链路通过。
