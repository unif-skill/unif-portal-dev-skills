## 4. 原生能力与协议接入

地图／POI 采用高德，统计与分享采用友盟。提供方依据分别为[高德鸿蒙地图 SDK](https://lbs.amap.com/api/harmonyosnext-map3d-sdk/summary)及其搜索资料、[友盟鸿蒙 U-Share](https://devs.umeng.com/docs/128606/detail/2938160)。分享位置等业务输入由应用准备，Camera／Chat／Umeng 不因此新增地图调用；未支持的渠道和未确认的厂商回执按所属库契约表达。

HTTP、SSE、上传、业务结果与 H5 字段及成功条件来自 Unif 所属协议。转换保留业务码、原输入和结果语义，不补造身份或额外流程。H5 容器保持来源、主框架、当前文档、授权及重复消息保护；既有 H5 业务由原页面负责，迁移容器不自动授权改写 H5。

共同功能按同一行为契约识别 RN、鸿蒙与相关后端消费者，可以先 RN 后鸿蒙，使用共同案例登记各端修订和差异。平台专属或局部修复只改变授权入口，不顺带改变另一端行为。


## 3. 契约与资源归属

共同输入含义、结果、事件、默认行为、取消、错误和资源所有权由所属契约定义。React 组件／Hooks 与 ArkUI 组件／控制器／Builder 分别表达，接口语法不强求一致；原生名称尚未定义时记录待定，不把 RN API 当鸿蒙 API。

Icons 的图形与命名采用 RN Icons 已有 SVG／清单来源，具体路径与校验由 Icons 契约维护；Design 共享基础设计数据，主题派生与平台资源映射分别由两端 Design 负责。

业务 Schema 由所属接口契约与生成代码提供。账号、草稿、队列、媒体、设备会话和缓存按[平台状态归属](../common/state.md#4-状态归属)由各实际单元持有，跨设备延续仅采用现有服务契约。

每次共同功能变更登记采用契约、RN 修订、对应鸿蒙库／应用入口、共同案例和两端证据。新增公共包的职责由本次有效契约确定，不搬入应用的业务流程。
