# @unif/harmony-camera 实施规范

本文规定 API 26 原生拍摄的行为与资源契约，不声明原生函数已导出。模式、结果和字段含义对齐 RN Camera（规范源相对路径：`libraries/react-native-camera.md`）；其中 React 宿主、AbortSignal 和设备类型不直接充当 ArkTS 签名，采用库须给出实际可编译的入口与取消方式。


## 1. 职责与依赖

Camera 提供单拍／连拍／录像、镜头与闪光、变焦、预览选用，以及方向／裁切／缩放／水印处理和临时媒体交付。应用提供水印内容，拥有上传、业务照片关联及业务确认；库不调用定位／POI 或翻拍识别来补数据。需位置时由应用采用已确认的高德能力准备。

原生相机、图像、文件和权限留在平台层，控件消费 [Design](https://github.com/unif-design/unif-platform-architecture/blob/main/libraries/harmony-design.md#1-职责与依赖) 与 [Icons](https://github.com/unif-design/unif-platform-architecture/blob/main/libraries/harmony-icons.md#1-职责与依赖)。可共享公式和文件记账必须检查完整依赖并分别验证；计算一致不等于镜头倍率、方向或传感器标定一致。


## 2. 公开契约与对齐

打开交互消费不可变的本次配置，返回成功选用、取消或失败。模式集合非空且不重复，顺序决定模式顺序及初始模式；照片质量、录像时长／码率、HDR、镜头和闪光只在对应能力适用。显式请求必须由真实 SDK 或处理兑现，不能悄悄忽略；未支持时如实说明，默认值和数值边界按 RN 契约核对，不另造一套。

`retention` 的 clear／retain 只管理本轮切换模式的媒体；clear 有待保留媒体时先取得丢弃确认，未确认保持模式与文件。单拍 clear 的结果进入确认预览；拍到照片、处理结束、关闭页面均不等于选用成功。水印使用调用方文字和位置，空文字不生成，玻璃装饰不进入成片。

成功只表示用户选用了本次可交付媒体。交付稳定媒体身份、可读 URI、实际模式／镜头／类型／尺寸，以及确实取得的时长；不以请求值伪造实际捕获，不增加同义 path 或业务照片 ID。URI 和文件访问方式按鸿蒙权限核实，在应用适配交接，不能机械拼出 RN 路径。


## 3. 状态、资源与结束

打开交互拥有配置、选择和单次结果；捕获／录像操作拥有真实设备与在途工作；本轮文件单元登记创建、替换、交付和丢弃。UI 从操作状态取得可用性，不再推进一份拍摄事实。

| 触发 | 必须保持的交接 |
|---|---|
| 非法新输入 | 明确失败，不结束已有有效交互 |
| 输入有效但取消已发生 | 直接取消，不启动设备或接替已有交互 |
| 合法有效的新打开 | 按同一宿主契约接替旧交互，旧调用取消；旧 signal 和回调不能关闭新调用 |
| 用户退出／所属取消／宿主真实结束 | 原调用只结算一次；区分暂时不可见和销毁，设备后台行为按 SDK 核实 |
| 局部捕获／处理失败 | 展示真实错误并保留既有媒体，等待明确重试；不自动重拍、不交付未满足要求的原图 |
| 成功选用 | 选中文件的后续使用与释放责任交给消费者；以后取消不能改写成功或删除已交付文件 |
| 迟到落盘／清理失败 | 仍归原调用，清理仅限本轮拥有且可释放资源；等待真实在途操作收尾，失败可诊断，不扫描其他缓存 |

相机权限随明确打开意图处理，麦克风仅在实际录像需要时申请；仅提供 video 模式不提前申请录音。权限拒绝、无设备、不支持及不可维持交互分别保留真实原因；SDK 忙碌与资源独占按实际能力处理，不偷偷开后台队列。

取景暗色、材质和正常应用字号分别适配。快门、镜头、闪光、模式、预览、删除和选用可访问且有名称；录制状态有非颜色提示，装饰不抢触摸／读屏。沉浸布局不能遮住退出和选用。


## 4. 验证与采用

自动化使用可控制完成时序的设备边界验证上表，覆盖旧操作迟到、非法／已取消新调用、clear 拒绝、局部失败、交付后关页和释放失败；几何与水印验证方向、裁切边界和尺寸，不只看 Promise 结束。

HAR 与真实 ArkUI 宿主构建检查公开入口、资源及权限接线。真机分别核对前后镜头／闪光／变焦、单拍／连拍／录像、权限及设置返回、中断／前后台、预览选用、水印、原图质量和交付后可读文件；记录实际设备、方向与 SDK。上传和业务保存另验。图片扫码、Mock、未签名 HAP 都不能覆盖这些拍摄验收。
