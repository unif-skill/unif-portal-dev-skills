# 工程技能入口

Portal 目标工程可在已有 AGENTS.md 中合入以下入口，并随工程所选技能版本维护：

```markdown
## 技能使用

本插件承载企业工程规范，相关步骤必须加载并应用对应入口。阶段技能读取本插件的架构与客户端规范，将要求用于同一次工作；通用工作流不能替代企业规则。

- 开发、测试、审查或交付客户端代码时，使用 code-development 取得相关文件、依赖与验收规则。
- 模块职责、公共契约、状态归属或场景组合变化使用 architecture-design；内部等价修改沿用有效设计。
- 设计、编写或执行测试使用 code-testing。
- 代码审查使用 code-review。
- 提交、推送、PR/MR、合并、发布与清理使用 code-delivery，按任务授权执行。

规范版本采用本工程指定的来源或锁定的技能快照，任务明确指定版本时以该版本为准。检查命令、CI 门禁和发布约定由本工程维护。
```

项目可在现有依赖或交付约定中锁定插件版本或 Git 提交；不在 AGENTS.md 复制类型、常量、命名和目录规则。code-development 的完整目录包含两份文件开发快照，可单独分发；平台原则由 architecture-design 提供，或采用目标工程的规范，不依赖其他技能的私有文件路径。规范源及 spec 仍由 `unif-platform-architecture` 项目维护。

code-testing、code-review 与 code-delivery 只维护阶段所需的规范入口，与 architecture-design、code-development 一同分发。测试质量、文件规则和验证责任由规范源维护，具体命令、门禁及版本发布约定由目标工程维护；不另写通用 TDD、审查或 Git 流程。

没有既定流程时仍按企业技能完成对应工作，不要求另装流程插件。复用已有结果前核对其是否覆盖当前变更和企业要求；有遗漏时补齐对应工作，不能因通用流程已经运行而跳过企业规范。

技能仓默认校验覆盖技能格式、包内引用、市场入口和生成资料；本地评测摘要可按[仓库验证说明](../README.md#验证)选择检查。同步工具及其测试验证快照生成与来源检查。这些检查没有扫描目标 Portal 的 TS/TSX，也没有启用其文件角色或导入门禁。

目标工程接入时，在其已有 TypeScript、ESLint 和静态分析配置中落实可确定的类型、命名、导入方向、私有深路径、循环依赖与角色文件检查。需要区分固定值和运行期内容时使用 AST 与作用域信息；业务含义、资源归属和副作用仍按契约审查。测试按实际消费者、宿主和协议影响选择。这些是待目标工程接入的检查，不随技能安装自动生效。
