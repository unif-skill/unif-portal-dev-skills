# 六库能力技能升级验证

本地候选基于技能仓 7dbd2c8eea2fcf98e62d2784bca9a592f3d12f11（原 0.3.17）。新增六个库能力入口，与原六个研发阶段入口共同分发。插件身份和发布版本规则保持；本记录不表示已发布或已安装新包。

## 变更

- Design、Chat 的专项资料迁到各自技能，删除 code-development 下的旧副本并迁移调用入口。
- Camera、HMS Scan、Umeng、Icons 增加公开资料路由与任务指引；按实际包版本核对公开接口，使用与源码维护分开。
- 组织 AGENTS 模板渲染本库能力名，Icons 纳入 Agent/llms 同步；六库入口、开发资料和网站技能页同步。
- 继续复用各库的公开类型、站点和 llms 生成链。没有更改库运行时、公共 API、依赖或发布配置。

## 独立模型样本

原始输入见 evals/library-skills/cases.md。两个基线上下文与两个候选上下文分别处理相同六类请求；另一个独立上下文只取得名称和描述，处理 12 个发现/排除请求。候选材料在执行前冻结。

基线和候选都能定位 Design 字号、Chat 草稿/附件、Icons 源生成、Camera 媒体交付、Scan 图片借用与 Umeng 分享回执的有效依据，未观察到这些题目的明确行为修复。候选能直接选择对应库能力入口；发现样本没有将未使用 Unif 的 Expo、ArkUI 或普通聊天分享归入 Unif 能力。

组合题同时选取架构资料入口，只能证明其发现选择，不能推断必须重启设计流程；实际使用仍遵循已确认契约和任务边界。各题输出与读取清单保留原文，没有按关键词打分。

一次候选 UI 评测最初无法读取额度并停止；主会话重新确认正常额度，评测者重查通过后继续。没有使用额外积分、付费 API 或额度重置。

完整原始回答、版本、材料摘要和工具日志仅在本地 evals/library-skills/runs/2026-10-26-upgrade/ 保存，按已有 manifest 格式校验；不纳入默认上下文和发布包。
