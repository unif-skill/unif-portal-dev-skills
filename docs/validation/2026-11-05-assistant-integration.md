# 助手接入边界技能验证

本次规则将对接领域助手的工程中 assistants 设为与 services 同层的职责目录。各助手维护能力声明、已有资料装配、协议及通信；通用服务保留执行、附件与记忆机制，领域业务判断与任务 Skill 留在所属助手工程。来源为平台 ARCHITECTURE.md 和 PYTHON_DEVELOPMENT.md，按现有生成器同步阶段资料及五个插件。

## 规则与验证范围

- 更新 unif-python-dev、unif-python-test、unif-python-review 与 unif-architecture-design 的资料入口；交付技能的后端验证及各阶段共用职责资料同源同步。当前 Portal 已采用的公共类型入口、独立运行校验与本机恢复职责，随现行规范同步到 RN 依赖资料；没有改写其业务规则。
- 新增[开发、测试、审查场景](../../evals/independent-skills/assistant-integration-cases.md)与[独立判据](../../evals/independent-skills/assistant-integration-rubric.md)，与现有独立行为组关联。
- 无指导对照将助手放在 services 下并建议维护另一份公共交接契约；旧技能对照按固定六层将声明、装配和通信继续分散。更新后以全新上下文执行三类场景：开发答案采用同层 assistants 并保留装配／契约必要关联；审查拒绝自动选品、Host 决定拜访完成及复制 DTO，同时保留领域接入认知；测试答案覆盖真实入口、异构助手替身、来源、身份、取消恢复、许可和用量，明确真实业务未验证。
- 上述为各一次独立书面应用样本，保留实际资料读取证据；不代表统计准确率、自动触发效果、应用实现或真实财务／人资接入。题库自动校验与这些独立场景分别计数。
