# 状态权威、业务唯一性与生命周期交接规则验证（2026-10-27）

## 范围与失败依据

仅补开发技能中的状态权威、记录唯一性与生命周期交接规则，按持久化、恢复、跨设备同步、业务记录创建，以及异步处理、状态交接或资源收尾触发。规则集中维护在规范源 `ARCHITECTURE.md` 第 4.1、4.2 节，按既有脚本生成 architecture-design 的状态主题；客户端、后端与测试入口只提供条件路由。未改全局 AGENTS、业务实现、版本或安装缓存。

实际失败来自 Portal：会话正文已有服务端同步，但日期到默认会话 ID 的关联仅存设备本地，另一客户端仍能生成新 ID。已核对 Portal 修订 `59999765` 的 `src/app/chat/runtime/createChatRuntime.ts` 与 `src/domains/marketing/visitConversation/createVisitConversationLinks.ts`，以及所属工程的 `docs/reviews/2026-10-27-visit-chat-regressions.md`。这里只保留机制，不复制客户、会话标识或业务数据。这是已有真实失败证据，不是本次新跑的无规则模型控制组。

## 生命周期交接增量

追加规则针对另一项真实失败机制：接收方已采用内容，但发送方仍在等待后续回执；关闭或中断等待时统一重写历史条目，混淆业务事实与控制状态。已只读核对 Portal 修订 `59999765` 的 `src/domains/marketing/orderInput/createOrderInput.ts`，以及当前 `__tests__/domains/marketing/orderInput/continuedInput.test.ts` 的关闭／恢复组合。该回归仍由业务修复任务执行，本技能任务没有运行或宣称真实业务修复完成。规则与匿名题设均未依赖该业务名称或具体函数。

增量后重新执行 78 项工具测试、四个修改入口的 quick_validate、12 技能包校验、同源检查和两仓差异检查，均通过。新增一名全新上下文子代理只读完成 E 题，未取得判据、首轮输出或真实工程材料：

| 判据 | 输出中的实际决策 |
|---|---|
| L1 | 分开接收事实与发送方等待，保护已采用但 Promise 未完成的条目；采用前中断不冒充成功，只释放本方资源 |
| L2 | 接收模块沿原补全和回执流程继续；删除关闭时批量失败与自动回退；拒绝、明确撤销分别依据权威结果 |
| L3 | 控制采用／中断先后，检查迟到回执、重新打开、混合历史条目与撤销成功／失败；断言事实、接线、副作用及资源，能发现仅保护已结束等待的错误实现 |

本次 L1–L3 均满足，属于单个限定场景的判断证据。原始任务、完整输出及所读文件快照另存 `evals/architecture-design/runs/2026-10-27-lifecycle-handoff/`；首轮 A–D 冻结档案未改写，普通 UI／纯设备状态的排除规则保留。此处不宣称跨模型稳定性、自动发现或真实业务验收。
