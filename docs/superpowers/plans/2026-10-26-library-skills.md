**目标：** 按本会话“全改一步到位”的授权，一次完成六个自有库的技能入口、资料迁移、工程接入和本地验证。

**设计依据：** 已确认采用“共享研发规范＋库能力技能＋版本化文档与工具”。保留六个研发阶段技能与现有插件身份；新增 unif-design、unif-chat、unif-camera、unif-hms-scan、unif-umeng、unif-icons。单次任务按需要组合入口。

**实现：** 本会话直接实施；独立上下文只负责行为对照与最终审查。使用 Markdown、现有 Python 校验器、组织同步脚本和各库 llms 生成链。

## 范围

- 技能仓：六个能力目录、共用开发/测试入口、README/接入说明、评测及分发验证。
- 组织标准仓：短 AGENTS 模板、能力名称替换、Icons 的 Agent/llms 同步名单及相关回归。
- 六个库：受管 AGENTS 区块、开发资料与站点技能入口；生成文档从所属源重新生成。
- 架构、业务实现、公共 API、依赖和发布配置保持本次已确认边界；已有并行修改保留。
- 不复制整份 API，不维护安装机器的绝对路径，不将工作区目标契约当已发布接口。
- 不提交、推送、发布或替换已安装插件；版本与发布仍沿现有交付规则。

## 特别核对

- 应用仅使用库时可直接取得公开资料，不要求先拥有架构仓。
- 库源码维护仍取得共同开发、测试、审查或交付依据，不重复启动流程。
- 临时文件、权限、SDK 初始化、分享回执、可访问性和生成资源保护不因迁移丢失。
- Icons 仅调整技能与文档维护接线；不在应用消费中运行生成器。
- 静态校验、模型对照、宿主自动发现、设备验收与发布分别报告。
