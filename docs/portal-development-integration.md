# 工程技能入口

Portal 目标工程可在已有 AGENTS.md 中合入以下入口，并随工程所选技能版本维护：

```markdown
## 技能使用

- 文件变更与接线使用 portal-development，按本次代码类别读取规则。
- 模块职责、公共契约、状态归属或场景组合变化使用 architecture-design；内部等价修改沿用有效设计。
- 审查代码变更、提交或 PR/MR 使用 code-review。
- 开发任务的分支与工作区安排，以及提交、推送、合并、发布或清理使用 code-delivery，按本任务授权阶段执行。

规范版本采用本工程指定的来源或锁定的技能快照，任务明确指定版本时以该版本为准。检查命令、CI 门禁和发布约定由本工程维护。
```

项目可在现有依赖或交付约定中锁定插件版本或 Git 提交；不在 AGENTS.md 复制类型、常量、命名和目录规则。portal-development 的完整目录包含两份文件开发快照，可单独分发；平台原则由 architecture-design 提供，或采用目标工程的规范，不依赖其他技能的私有文件路径。规范源及 spec 仍由 `unif-platform-architecture` 项目维护。

code-review 与 code-delivery 的操作要求直接维护在各自 SKILL.md，不复制架构规范或工程门禁，也不依赖其他插件的审查与 Git 技能。缺少实际项目规则时明确交付缺口，不能借用另一工程的命令或发布惯例。

技能仓默认校验覆盖技能格式、包内引用、市场入口和生成资料；本地评测摘要可按[仓库验证说明](../README.md#验证)选择检查。同步工具及其测试验证快照生成与来源检查。这些检查没有扫描目标 Portal 的 TS/TSX，也没有启用其文件角色或导入门禁。

目标工程接入时，在其已有 TypeScript、ESLint 和静态分析配置中落实可确定的类型、命名、导入方向、私有深路径、循环依赖与角色文件检查。需要区分固定值和运行期内容时使用 AST 与作用域信息；业务含义、资源归属和副作用仍按契约审查。测试按实际消费者、宿主和协议影响选择。这些是待目标工程接入的检查，不随技能安装自动生效。
