# Portal 工程调用入口

Portal 目标工程可在已有 AGENTS.md 中合入以下入口，并随工程所选技能版本维护：

```markdown
## Portal 文件变更

新增、修改、移动、重命名或删除 Portal 源码及配套文件前，必须使用 portal-development，并按本次代码类别读取规则。规则版本采用本工程锁定的技能包快照（来源与摘要见包内 references/source.json）；任务另有明确版本时以指定版本为准。
新模块、公共契约、状态归属或场景职责变化时，同时使用 architecture-design 并沿用该规范版本；内部等价修改不重复完整设计。
```

项目可在现有依赖或交付约定中锁定插件版本或 Git 提交；不在 AGENTS.md 复制类型、常量、命名和目录规则。portal-development 的完整目录包含两份文件开发快照，可单独分发；平台原则由 architecture-design 提供，或采用目标工程的规范，不依赖其他技能的私有文件路径。规范源及 spec 仍由 `unif-platform-architecture` 项目维护。

技能仓现有校验已覆盖技能格式、包内引用、市场入口和评测摘要；同步工具及其测试验证快照生成与来源检查。它们没有扫描目标 Portal 的 TS/TSX，也没有启用其文件角色或导入门禁。

目标工程接入时，在其已有 TypeScript、ESLint 和静态分析配置中落实可确定的类型、命名、导入方向、私有深路径、循环依赖与角色文件检查。需要区分固定值和运行期内容时使用 AST 与作用域信息；业务含义、资源归属和副作用仍按契约审查。测试按实际消费者、宿主和协议影响选择。这些是待目标工程接入的检查，不随技能安装自动生效。
