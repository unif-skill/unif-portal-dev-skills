# Portal 文件开发

定位所属单元、已有公开入口、目标契约及实际消费者，按已确认范围修改文件。

## 依据

优先采用任务或工程指定的规则版本；未指定时按本次改动选读包内主题，已有依据足够时不扩读：

- 文件拆分、作用域、类型与命名：[文件规则](references/file-rules.md)。
- 组件、样式与 UI 复用：[UI 规则](references/ui.md)。
- 工具、配置及资源文件：[归属规则](references/utilities-config.md)。
- 公共入口、依赖、基础能力与宿主接线：[依赖规则](references/dependencies.md)。
- 代码类别、旧实现参考与重写范围：[开发范围](references/scope.md)。
- 初始化工程与代码归属：[目标目录](references/directory.md)。
- 分批重写、测试与变更影响：[定向验证](references/testing.md)。

调用触发、输入准备、结果复用或跨功能协调的设计与变更，使用 architecture-design 核对功能组合与交接；业务结果、状态和确认读取对应主题。新模块、公共契约或场景职责变更先完成必要设计。该技能不可用时采用目标工程的架构规范；缺少依据则列明缺口，继续其余文件工作。

领域契约和 SDK 接口按需从目标工程取得；包内主题溯源时读取 references/source.json。

## 实施与交付

按单元实际内容组织角色文件和公开出口，保持运行期值的调用或实例归属，类型与 Schema 遵循同一代码源。同步受影响的导入、消费者和宿主接线。

说明本次文件与出口变化、契约依据及定向验证结果，分别标明已执行检查、未验证项和待接入的工程规则。
