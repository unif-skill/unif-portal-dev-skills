# Portal 文件开发规则

本文规定采用新架构的 Portal 客户端在新增、修改、移动、重命名和删除工程文件时遵循的规则。目录归属见[工程组织](../SKILL.md)，能力边界见基础能力架构（规范源相对路径：`capabilities/portal-foundation.md`），业务契约与状态原则见平台架构（规范源相对路径：`ARCHITECTURE.md`）。

这些是客户端工程规则，不把 TypeScript 文件名或 React Native 目录套用到 Agent、Channel、CLI 的其他语言实现。新 Portal 按平台架构第 1.1 节（规范源相对路径：`ARCHITECTURE.md#11-设计依据与适用范围`）重写；旧源码用于核对行为与逻辑结果，不作为文件搬运来源。新工程已有代码的日常修改仍限定在本次功能及实际影响范围内，不自动全仓重排。


## 1. 文件变更入口

修改 Portal 源码及其配套类型、常量、样式、测试、配置、资源接线前，使用 `portal-development` 技能，按本次文件所属类别读取本文相关规则。新模块、公共契约、状态归属或场景职责需要设计时，同时使用 `architecture-design`；已有契约下的内部等价修改不重复开展完整架构设计。

开发前定位本次功能契约、所属单元、已有公开入口、实际消费者和对应测试。新增文件落在已确定的单元中；新增单元时说明其独立职责和使用方，不从页面名称或 SDK 包名直接推导一套业务模块。

用户已明确的需求和契约限定实现范围。重写实现和后续文件组织调整不增加重试、自动提交、缓存、恢复、确认或新接口调用。


## 2. 各类代码的开发规则

| 类别 | 必须维护的边界 | 变更时核对 |
|---|---|---|
| `components/` | props、必要展示类型和事件回调；组件自身的 UI 状态 | 复用组件库和新工程内已实现的共用组件；不读取领域 store 或发起业务请求；确认 UI 不承担场景确认规则；渲染和交互测试可使用轻量宿主 |
| `capabilities/` | 独立操作、输入输出、错误、副作用和资源生命周期 | SDK 或外部依赖可替换；调用、取消和释放归属于本次操作；宿主和平台实现按能力接线；一个能力修改只验证真实影响 |
| `domains/` | 领域功能、场景组合、业务交互与所属状态 | 功能入口、准备/确认/提交的责任明确；页面和对话复用同一链路；最终规则与业务事实仍由业务系统处理 |
| `integrations/` | 所属外部协议、原始 DTO、请求/回包转换和接入错误 | 契约与真实外部能力一致；按所属接口码表解释结果；不在转换中新增流程、补造身份或改写成功语义 |
| `app/` | 应用功能与入口；bootstrap 和导航负责真实组装 | 页面保持输入和展示适配；账号、设置、对话等各自维护状态；下层不反向读取启动代码或全应用状态对象 |
| `hooks/` | 与领域无关的通用 React 行为 | 功能专用 hook 留在功能内；不在公共 hook 中隐藏业务请求或设备操作 |
| `utils/` | 通用计算或格式处理 | 不访问网络、设备、持久存储和业务 store；模块私有辅助优先留所属模块，不因为函数短小就移入全局工具 |
| `config/` | 构建环境和应用配置的明确来源 | 应用组装向依赖传入必要字段；运行期状态、业务表结构和全部接口路径不汇入全局配置 |
| `types/` | 确需全局补充的环境、静态资源或第三方声明 | 业务模型、组件 props 和能力结果不放这里；不通过宽泛声明掩盖真实类型错误 |
| 测试、脚本、资源与原生配置 | 服务于明确功能或工程接入 | 测试按所属单元定位；脚本和平台配置遵循其工具要求，不机械套用 TypeScript 源码文件规则 |
