## 3. 工具、常量、类型及其他文件的归属

| 文件角色 | 默认归属 | 公开与共享规则 |
|---|---|---|
| 通用计算、日期解析、字符串或文件名处理 | `utils/` 下按实际用途命名的文件或小单元 | 不访问网络、设备、持久存储或业务 store；时间和随机行为在测试中可控制 |
| 功能内部的转换、整理、校验辅助函数 | 所属功能内部 | 先保留为普通函数；只有实际消费者需要才公开 |
| 通用 React 生命周期、倒计时等 hook | `hooks/` | 不嵌入业务请求、选择规则或全局业务状态 |
| 功能或组件专属 hook | 所属功能或组件内部 | 与它维护的状态和生命周期放在一起 |
| 设备操作、文件读写、键值存储、日志运行代码 | 对应 `capabilities/` 单元 | 明确副作用和可替换的外部依赖，不以“工具函数”名义绕过边界 |
| HTTP、流式协议、H5 桥接等适配 | 对应 `integrations/` 单元 | 协议差异在适配处收口 |
| 功能公开输入、输出、错误及必要状态 | 所属单元的 `types.ts`；可执行契约按开发规则保持单一源 | 消费者从功能公开入口取得，不移到全局 `types.ts` |
| 组件 props 和展示类型 | 对应组件的 `types.ts` | 只公开消费者需要的类型；私有子组件类型留在所属单元内部 |
| 外部接口原始 DTO、码表、字段映射 | 使用该接口的功能适配器内 | 原始协议和 Portal 功能契约分别表达各自语义，由适配代码连接 |
| 模块固定值、存储 key、文件用途标识 | 所属单元的 `constants.ts` | 同一含义只维护一份，通过所属模块的必要公开入口复用 |
| 数据库表结构、业务 SQL、表内数据含义 | 使用 SQLite 的功能模块 | SQLite 基础能力不维护全应用的业务表清单 |
| 构建环境和应用级配置 | `config/`；由应用组装读取并向具体依赖传入必要字段 | 功能不读取整份应用环境配置；接口路径留所属接入代码 |
| 可变偏好、草稿、选择和业务进度 | 所属功能或场景的状态代码 | 不作为常量或配置保存；持久化由该功能的已确认需求决定 |
| 样式、中文提示和静态资源 | 优先随所属组件或功能维护；应用共用资源放 `assets/` | 主题 token 仍取设计系统，领域文案不汇入全局提示字典 |
| 环境、静态资源或第三方模块的补充声明 | 确有编译需要时放 `types/*.d.ts` | 不存放客户、商品、设备结果等业务或能力契约；不以宽泛 `any` 掩盖契约缺口 |

角色文件按文件开发规则第 3 节维护：存在显式类型、命名固定值或样式定义时，分别放入所属单元的 types.ts、constants.ts、styles.ts；没有对应内容不创建空文件。运行期变量保持原函数或实例作用域，全应用共用内容仍按语义归属，不汇集成全局常量或类型总入口。

TypeScript 的 interface、type、同源派生与命名要求见文件开发规则，不另行维护一套写法。

类型、运行时校验和模型 Schema 的同源方式遵循平台架构第 6 节。设计中的代码契约在对应模块维护，实现后以所属代码为事实来源；本文不另建一份字段全集。
