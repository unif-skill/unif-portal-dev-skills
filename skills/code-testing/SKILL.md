# 测试规范

按本次测试问题取得企业验收依据。同一上下文已有且仍适用的规则与契约直接复用；缺失的部分优先从工程指定规范取得，未指定时按以下入口定位包内资料。取得共同规则不启动其他阶段：

- 共同测试责任与质量：architecture-design 的“独立验证”主题；涉及调用、状态、协议或模型语义时，补对应契约。
- 持久化、恢复、跨设备同步、业务记录创建，或异步处理、状态交接、资源收尾的验证：补 architecture-design 的“状态归属”主题，按权威来源、唯一性与生命周期要求选择受影响的用例。
- 客户端或库的测试组织、影响范围与平台验证：先确定 RN／原生鸿蒙及应用／库。RN 实现与库产物分别按 react-native-development、react-native-library 核对，同时从 code-development 的“测试与验收”和“RN 项目采用”取得企业要求；具体 RN 库按需取得 unif-* 能力技能；鸿蒙从“鸿蒙测试与验收”及本次相关的状态、UI、接入专题进入。共享源码验证每个采用目标的产物与消费者；工具、命令与设备条件来自实际工程。文档站或 H5 只补所需专题。
- Python 后端的目录、资源生命周期及验证边界：backend-development 的“契约与验证”主题；命令与消费者从实际工程取得。
- 涉及失败处理、降级或恢复的变更：按 architecture-design 的“独立验证”主题核对诊断覆盖；测试同时验证安全原因、关联、取消及迟到边界，以及日志失败不改变业务结果，不能只断言返回码。
- 测试预期来自所属模块契约；异步请求或身份、资源变化按测试责任推导有效更新与失效转换，核对消费者的反馈和副作用。命令、覆盖范围与超时配置来自实际工程，验证环境采用任务或工程指定的目标。

替换外部依赖时，替身应保留本次调用所依赖的接口、参数和必要前置条件；由依赖真实行为决定的结果，另以所采用版本的实际实现核对。

在当前测试过程中核对企业要求与消费者接线，不另起测试流程。缺少必需规范时明确缺口，不把通用测试通过当作企业验收完成。
