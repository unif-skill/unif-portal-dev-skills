# 测试规范

按本次测试问题取得企业验收依据。同一上下文已有且仍适用的规则与契约直接复用；缺失的部分优先从工程指定规范取得，未指定时按以下入口定位包内资料。取得共同规则不启动其他阶段：

- 共同测试责任与质量：architecture-design 的“独立验证”主题；涉及调用、状态、协议或模型语义时，补对应契约。
- 客户端或库的测试组织、影响范围与平台验证：code-development 的“测试与验收”或“库开发”主题；Chat、Design 或 H5 只补本次涉及的专题。其他工程采用自身的组织与工具约定。
- 测试预期来自所属模块契约；异步请求或身份、资源变化按测试责任推导有效更新与失效转换，核对消费者的反馈和副作用。命令、覆盖范围与超时配置来自实际工程，验证环境采用任务或工程指定的目标。

在当前测试过程中核对企业要求与消费者接线，不另起测试流程。缺少必需规范时明确缺口，不把通用测试通过当作企业验收完成。
