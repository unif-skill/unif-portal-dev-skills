# iOS 真机安装与调试

将当前 Portal 或库示例安装到 iOS 实体设备、验证当前 JS，或恢复已有设备调试连接时读取。设备自动化按本次任务需要使用；用户自行测试时，完成环境准备后交接。

## 复用现场依据

先读取仍有效的任务交接，确定工程与修订、指定设备、包标识、原生产物及依赖／编译配置、Metro 和已有自动化会话。复用已经核对且没有变化的事实，只复查失效或本次变更影响的部分。设备名称、UDID、端口、主机地址、签名、session 和产物路径都是现场参数，以当前任务及实际发现为准。

命令采用目标工程的 package.json、锁定 CLI 与当前工具帮助；沿用项目的环境注入约定。先辨别已有 Metro 属于哪个工程及端口，再决定是否启动。8081 是常见默认值，任务指定的其他有效端口同样可以使用。

## 按变化选择动作

| 当前证据 | 必要动作 |
|---|---|
| 只有 JS／样式变更，已安装原生包与当前依赖和编译配置兼容 | 复用原生包及有效 Metro，用 Fast Refresh 或重载取得当前 JS；核对手机实际加载结果 |
| 原生模块、Pods、签名、包标识或编译注入的环境值变化，且没有匹配产物 | 按工程入口完成需要的依赖同步和真机构建；使用本次产物安装、启动 |
| 已有与目标一致的签名 iphoneos `.app` | 复用产物；CLI 支持时用 `--binary-path` 跳过构建，或用当前安装工具定向安装，再核对启动 |
| 设备／端口转发／自动化 session 失效，但产物与安装证据仍有效 | 恢复失效的连接或会话，保留有效构建与安装结果 |

`.env` 文件名本身不决定是否原生重建：先确认变化是在原生编译时注入，还是由当前 JS／Metro 读取。Metro 配置或注入方式改变时，按实际加载方式恢复相应进程。

## 定向安装与启动

先核对工具发现的是指定实体设备。当前项目的 ios 脚本调用 React Native CLI、相应参数受支持，且有效 Metro 已运行时，复用产物的命令形状为：

```sh
npm run ios -- --device "$ios_device" --binary-path "$ios_app" --port "$metro_port" --no-packager
```

参数来自本次已核实的现场；没有匹配产物时走工程构建入口。不同 CLI 的 `--device`／`--udid` 发现与回退行为按所用版本核对。日志显示目标未发现或转到了其他设备／平台时，退出 0 不表示安装成功。

CLI 发现失败而 `devicectl` 已确认目标在线时，可按 `xcrun devicectl device install app --help` 和 `device process launch --help` 使用同一目标与产物完成安装、启动。分别保留安装回执、设备上的包／版本与进程结果。锁屏、信任或开发者模式要求在目标设备上处理；只限制依赖该条件的步骤。

Metro `/status` 只证明服务存活。当前 JS 是否被目标 App 加载，需要对应 bundle 请求／日志与设备实际界面证据；库示例或模拟器结果不能代替 Portal 真机接线。

## 自动化连接与交接

需要自动导航或截图时，优先使用当前可用工具及有效 WDA 会话。USB／网络重连后，按设备连接、端口转发、WDA 服务、session 的顺序定位失效层，仅恢复该层；动作采用当前工具支持的接口，例如 W3C actions，不照搬绑定旧设备和 session 的临时脚本或过时快捷端点。

交接沿用本会话或工程已有记录，说明工程／JS 修订、设备与包、原生产物、Metro／自动化连接状态、已验证层级及下一步。登录、权限与业务数据操作沿用本次仍有效的授权。用户明确“我自己来测”时交付可测试状态及尚缺证据，业务流程由用户执行。
