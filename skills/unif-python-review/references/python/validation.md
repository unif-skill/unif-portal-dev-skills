## 5. 契约与任务指令

公开 Schema 从所属 contracts 单元取得，运行校验、模型投影及各消费者产物保持同源。结构重构不手改生成文件；资源加载路径随模块迁移核对，产物字节与来源记录须能验证。

通用指令与任务指令分别维护，当前调用只装配所需内容。纯文件化或目录拆分应对照最终装配文本，包括空白与顺序；语义修改执行受影响的任务、切换与复合意图评测。格式本身不证明模型效果改善。

模型给出理解、澄清或类型化结果，权限、确认、设备操作、业务请求和成功依据继续由既定负责方承接。子模块或模型不能凭目录变化获得新的执行权限。


## 6. 验证与交付

验证覆盖实际被改的生产代码及消费者。等价移动复用原有行为回归，补齐确有需要的资源导入、依赖边界与入口接线检查；功能变化按契约增加能复现问题的测试。结构检查进入既有测试或 CI，检查真实依赖与根目录职责，不用代码行数作为统一合格阈值。

涉及外部依赖、持久化、异常转换、异步收尾、降级或恢复的功能变更，同时按[日志与故障诊断](../common/verification.md#721-日志与故障诊断)核对日志责任及对应测试；复用已有记录，补齐本次改变或新增的失败路径。

一次结构重构至少核对公共入口、隐式模块字符串、测试替换点、子进程启动、Docker 拷贝、生成资源路径和现行文档。历史执行记录保留当时路径与证据，不批量改写历史。

离线测试、真实进程 HTTP/SSE、真实身份/业务/模型、镜像构建、部署及最终验收分别记录。合成输入和替代模型能验证接线与协议，不能证明真实模型理解或业务成功。涉及真实模型、额外付费或外部变更时遵循当前用户授权。

涉及 Agent 运行环境时，分别核实 API 与 Worker 实际采用的 MySQL 库、Redis 入口、运行命名空间及 Worker 注册。同一环境的实例共享运行资源，开发、测试与正式环境分别隔离；请求地址、分支或容器名称不同不能证明任务不会被其他环境领取。环境切换保留已有库和数据，仅对明确新建的空库执行所属初始化。

后端相关技能从本规范取得对应工程规则，按本次任务选读所需资料；独立使用不要求安装其他阶段技能。
