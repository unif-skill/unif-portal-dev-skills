# 后端审查规范

按最新目标、有效契约和实际消费者独立核实本次方案的前提与影响，不因作者或用户已同意改法就省略核查。发现未确认的偏差或取舍，报告证据、后果和需用户决定的部分，不擅自否决或替换产品选择。用户知情确认的变更按新决定审查，无实质疑点不追加确认；排除项、撤回意见及仍适用的依据继续沿用。

## 按变化读取

按表中主题与章节取得本次变化需要的依据。

涉及助手接入时，核对专属能力说明、输入投影和协议处理是否集中在 Agent 对应的 capabilities 单元；区分必要的领域接入认知与业务决策，不以删除所有业务名称代替边界审查，也不允许适配器承接领域业务流程。智能体自身的 Skill、提示词与编排归顶层 agent，Marketing 的业务规则与校验归 capabilities。核对普通接口仍可使用所属能力，通用 memory 的读写、权限与事务未因名称迁入 agent。

工程指定了规则修订时采用该修订。具体业务、库 API 与 SDK 契约从工程入口和实际公开资料取得，不把模板、评测样例或偏好当成新增需求。后端任务、事务、进程与持久化按实际执行层级核对；内存替身不能证明数据库约束，单进程验证不能证明多进程行为。

## 输出

沿实际请求、任务或启动入口核对复用依据、状态所有者和消费者，识别同职责重复逻辑及遗漏的调用迁移、失效实现清理；保留有效契约中的服务与生命周期差异。沿失败产生、转换、抑制和交付检查当次证据能否定位：主日志是否保留具体安全原因，原操作关联是否贯穿异步，必要附日志是否有受控且可读的索引。按[日志与故障诊断](references/common/verification.md#721-日志与故障诊断)核对噪声与级别、凭据排除、身份隔离、保留／容量及诊断失败隔离，保留原权限、取消、事务和资源保护；正常预期分支或纯取值没有日志不自动判为缺陷。共享源码检查真实运行入口和消费者。

只报告有证据的问题，说明位置、触发条件、实际影响及对应契约。区分需要修复的实现缺陷与已授权设计变化；假设的新需求列为建议或待确认项，不作为既有实现的阻断缺陷。审查不自动授权修复、提交或发布评论。资料溯源见 references/source.json。
