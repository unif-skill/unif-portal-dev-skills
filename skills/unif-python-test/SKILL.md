# 后端测试规范

接续任务或进入新会话时，先核对最新已确认需求、明确排除项及已撤回结论，再按当前契约、实现与消费者选择验证范围。优先采用工程指定且当前有效的修订，同一上下文已有依据直接复用。

按表中主题与章节选读，保留本次测试所需的完整契约。

助手接入测试覆盖真实路由与交接，区分输入准备、协议校验和业务处理；不同助手的替身用于核对隔离与公共机制，不声明真实领域服务已接入。

只读取实际涉及的资料，不因取得共同规则进入其他阶段。服务接口、业务模块契约、命令和运行条件从目标工程取得。

## 应用

运行真实被测实现；涉及多个请求或任务入口复用时，验证受影响入口确实调用所属公共能力，并覆盖各自状态归属、输入及交接差异。替换外部边界，断言返回、状态、消费者交接及不应发生的副作用。替身保留所采用依赖的接口、参数和必要前置；依赖真实行为决定的结果，另以实际实现核对。

失败、降级或恢复变化按诊断责任验证安全原因、关联、取消、迟到及日志自身失败，保留原业务控制。测试预期来自有效契约，不能通过复制实现、排除源码或弱化断言获得绿色结果。

报告实际修订、命令和覆盖范围，按实际执行层级区分源码检查、替身测试、进程、持久化和真实业务证据；内存替身不能证明数据库或多进程约束成立。资料溯源见 references/source.json；读取资料不授权修改无关实现或执行外部操作。
