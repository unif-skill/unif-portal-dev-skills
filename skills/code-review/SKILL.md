# 代码审查

将工程要求应用到实际变更；已有审查流程时补充其中的判断依据，不另起审查轮次。

## 范围与依据

确定基线、目标版本和本次文件范围；工作区审查包含暂存、未暂存与新增文件，区分他人改动。按工程指定的需求、规范和模块契约判断，作者说明与旧实现只作为线索。

## 核对

- 沿实际调用链核对输入输出、副作用、状态、资源及协议语义；公共契约变化追踪生产方、消费者和部署兼容范围。
- 文件与复用归属按工程规范判断，等价整理沿用有效设计。测试应执行真实实现并覆盖相关交接，绿色结果不能代替语义审查。

## 结论

按严重程度列出有位置、触发条件和影响依据的问题，区分缺陷、疑问与可选改进；无发现时直接说明范围和证据限制。审查本身只读，修复或发布评论按任务授权执行。
