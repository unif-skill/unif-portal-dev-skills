# 代码交付

在任务采用的 Git 流程中核对工程要求与交付证据，以已授权阶段为终点。

## 工程依据

核对仓库、远端、目标分支、工作区和暂存状态。分支、提交、检查与发布规则取自工程的 AGENTS.md、贡献约定、脚本及 CI；GitLab 用 glab，GitHub 用 gh，本地用 git。跨仓契约变化核对实际消费者和部署兼容条件。

## 组织与验证

沿用已安排的工作方式，保护他人的改动与工作树；混合工作区只提交本次范围，核对完整暂存差异和新增文件。

本地按实际影响验证，合并与发布完成工程门禁。已有检查和审查仍覆盖当前内容与环境时复用；变更后补相应验证，定向测试不替代完整门禁。

## 远端交付

沿已授权阶段连续执行，不重复询问相同许可；提交、推送、PR/MR、合并和发布各自核对授权，超出范围时先完成可独立交付的准备。

推送后核对远端与 PR/MR 的实际提交；合并前确认最新 head 的审查与 required 检查，合并后核对目标分支及后续 CI。版本、tag 和 Release 按仓库规则处理，不从提交或合并自行推导发版。

清理先核对 tip、独有改动、未提交文件与工作树占用。普通合并检查祖先关系，squash/rebase 核对合并记录及补丁或内容等价证据；远端删除绑定已核实的 tip，保留未交付改动。

报告实际完成的阶段、提交或 PR/MR 链接、验证结果与剩余事项；区分已提交、已合并、已发布和安装生效。
