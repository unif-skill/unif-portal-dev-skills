# 交付规范

按工程约定核对本次交付授权与验收证据。同一上下文已读且仍适用的规范直接复用；提交或配置变化时核实证据是否仍有效。缺失规则优先从工程指定规范取得，未指定时按以下入口定位：

- 本工程的 AGENTS.md、贡献约定、检查脚本和 CI：分支、提交、门禁及版本发布规则。
- @unif RN 库首次／恢复发布，或缺少工程标准接入依据时：使用 react-native-library 核对包身份、历史占用、产物及发布前置，并从 code-development 的“RN 项目采用”取得组织标准与实际接线。原生鸿蒙 HAR 库采用“鸿蒙适用范围”和“鸿蒙测试与验收”，按实际 OHPM／HAR 标准核对产物与公开消费；不能套用 npm 的发布接线。现有脚手架配置不作为已采用标准的证明。
- 涉及客户端或库代码的验证范围与证据层级：RN 按 react-native-development、react-native-library 及项目测试约定核对，鸿蒙按 code-development 的原生测试／库专题核对，核对本次产物及实际消费者；共享源码分别核对 npm 与 OHPM／HAR 产物、采用版本和目标运行证据，不从单端构建推断三端完成。
- Python 后端的打包、资源路径、真实进程与验证证据：按 backend-development 的“契约与验证”及工程入口核对。
- 涉及跨仓公共契约时：architecture-design 的“独立验证”及相关契约，核对消费者和部署兼容范围；不因取得这些规范重新开展测试或架构设计。

证据应对应当前提交、配置和实际执行层级；定向验证不替代工程门禁。交付按工程约定与任务授权进行。
