## 5. 验证与交付

测试预期来自所属契约与实际消费者，平台命令和工具从当前工程取得。Unif 的验收按本次变化核对以下对象，不因规范或技能已发布就认定原生产品完成：

| 本次对象 | 必要验收依据 |
|---|---|
| 原生六库公开能力 | 所属库契约、实际 HAR 导出／资源／依赖、独立原生宿主公开消费及本次能力运行结果 |
| RN／鸿蒙共同能力与资源 | 相同的共同案例、各端采用修订与产物、真实消费者及平台差异；单端或纯算法通过不替代另一端 |
| 身份、状态与资源交接 | 身份／会话切换、失效与迟到结果、草稿／文件所有权及权限、取消和收尾；按所属场景选择相关案例 |
| 原生 SDK 与外部协议 | 权限、设备与厂商回执，HTTP／SSE／上传业务成功，以及 H5 来源、主框架、当前文档、授权和重复处理边界 |
| UI 与材质 | 已确认 RN 视觉和交互、对应原生载体及降效条件；在相同数据、窗口、主题、字体、键盘和系统条件下对照 |

源码检查、替身测试、HAR 产物与宿主构建、设备运行、厂商及真实业务回执分别登记；Jest／Node、空宿主或未签名 HAP 不能当作库能力已安装运行的证据。报告采用修订、命令、结果、警告与未验证项，提交、CI、发布和最终验收分开。无障碍、可点击范围与必要降效随相关场景验证，静态门禁是否生效以目标工程实际配置为准。
