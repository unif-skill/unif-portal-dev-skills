## 3. ArkUI 状态与生命周期

新建 UI 状态优先采用目标 SDK 支持的 ArkUI V2 能力；既有组件或 SDK 互操作有约束时按官方规则选择，不为统一机制重写无关消费者。输入、事件和组件自身状态分别表达，受控输入不复制成另一份业务状态；观测能力不改变所有权。

账号、角色、会话、草稿、页面和操作各自拥有状态。应用组装提供明确依赖，库不读取 Portal 私有 store、账号、路由或服务凭据。UIContext／Ability 上下文、订阅、计时器和原生句柄属于实际宿主或操作，按目标平台生命周期取得、使用与释放，不藏入进程全局工具。

等待期间身份、会话、页面或资源可能失效。消费者依据原操作和所属生命周期决定能否接收返回，支持必要取消与收尾；同名账号重新出现不证明旧操作重新有效。页面关闭、前后台切换和异步终态分别按契约处理，不把所有离开页面都解释为删除业务草稿或已交付文件。

临时媒体、借用文件、上传中的资源和交付后的文件分别记录所有者；回收只能操作当前流程拥有且已可释放的资源。释放失败、重复关闭和迟到回调保留可观察的真实结果；不因重构删除错误、权限、并发或无障碍保护。
