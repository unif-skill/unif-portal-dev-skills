## 3. 工具、常量、类型及其他文件的归属

通用工具、hook、角色文件和资源组织遵循 `code-organization` 的“目录与职责”及“文件角色与命名”。Portal 在这些规则上的具体归属如下：

| 内容 | Portal 归属 |
|---|---|
| 设备、本地存取与日志 | 所属 capabilities 单元，按能力契约处理副作用与资源 |
| HTTP、流式协议与 H5 | 所属 integrations 单元；原始 DTO 与 Portal 功能契约由适配连接 |
| 存储 key 与文件用途 | 所属功能，KV 按记录归属与身份前缀（规范源相对路径：`capabilities/key-value.md#31-记录归属与身份前缀`）构造实际 key |
| SQLite 表、SQL 与业务数据 | 使用数据库的功能，基础能力不持有全应用业务表清单 |
| 构建与应用配置 | config，由 app 组装读取并传入必要字段；接口路径留所属接入 |
| 业务草稿、选择与进度 | 所属功能的状态实现，持久化按已确认需求接入 |
| 主题、领域文案与资源 | 主题取 Design，领域文案随所属功能；共用静态资源在 assets |

类型、运行时校验和模型 Schema 的同源方式同时遵循平台架构（规范源相对路径：`ARCHITECTURE.md#6-跨边界交接与业务结果`），接口字段以所属契约和实现为源，不在本表重复维护。
