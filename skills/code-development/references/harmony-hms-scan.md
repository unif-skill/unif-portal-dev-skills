# @unif/harmony-hms-scan 实施规范

本文是 API 26 原生扫码的目标契约；采用版本的 ArkTS 出口和 Scan Kit 签名必须实际核对。行为以 RN Scan（规范源相对路径：`libraries/react-native-hms-scan.md`） 为对照，不移植 Fabric、React 宿主或 RN 权限接口。


## 1. 职责与依赖

库负责实时预览识别、图片解码、权限读取／申请、码制与结果转换、手电及扫码选用交互。预览、解码和权限可独立消费，低层不反向依赖完整扫码 UI；控件消费 [Design](harmony-design.md#1-职责与依赖) 和实际 [Icons](harmony-icons.md#1-职责与依赖)。相册选择由外部提供，不因图片解码打开相机或另建选择器。

客户／商品含义、URL 打开、查询、业务确认和导航归消费者。扫码 Kit 的业务示例不授权这些动作；Scan Kit 不意味着采用华为地图或系统分享。


## 2. 公开契约与对齐

保留原始码值、码制、实际可取得的内容类型与角点，以及原请求的过滤语义。未知码制和无效 SDK 响应分别处理，不把无法解析的返回变成有效空结果；不能为接入方便省略请求的格式过滤。字段、默认值和错误分类来自 RN 行为契约，平台映射来自实际 SDK。

权限读取不弹授权；明确扫码意图才申请所需权限。手电状态由实际设备回报，不以按钮切换代替成功。图片解码输入必须实际可读；无结果、用户取消和技术错误分别交接，借用资源不能成为库的文件所有权。

默认识别后暂停并展示原文与码制，人工选用再交付一次；只有场景明确配置自动交付时才省略选用卡，这仍不是业务提交确认。重扫结束原结果采用，开始新一轮；相册取消恢复可扫描状态且不解码。回调异常不自动重扫或重复交付。


## 3. 状态、资源与结束

相机、选图和解码属于同次交互但各自管理在途边界。关闭、取消、格式过滤改变或新一轮开始后，旧结果不得进入新轮；停止 UI 采用不证明 SDK 已停止读文件。主题、字号、提示文字和材质变化只改外观，不重开相机、重新解码、重复交付或释放读取占用。

图片由提供方拥有：SDK 真实读取结束后才通知提供方释放本次读取占用一次；迟到选图已确定不再开始读取时也交回原提供方。页面关闭不能提前交回仍在读取的文件，库不能删除借用原文件；若 SDK 需要自己的临时副本，仅释放自己创建的副本。释放／读取异常保留诊断，旧释放不得指向新文件。

致命相机错误停止本轮设备，明确重试或设置返回时重新读取权限，不重放旧任务。设备、订阅和读取句柄按实际宿主及 SDK 生命周期关闭；不存在“取消即底层已停止”的假定。

保留返回、手电、相册、重扫和选用的名称与触摸区域，结果长文可滚动、读屏，状态不只用颜色表达。取景与浮动操作材质分开，安全区由实际窗口计算，不为制造玻璃遮住预览或操作。
