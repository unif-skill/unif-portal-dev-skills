# H5 桥接开发与接入

修改 Portal 的 H5 容器、设备消息、来源与授权检查、文档收发或结果映射时读取。H5 业务页面维护自己的业务流程；设备库本身的 API 以所属库契约为准。

## 按变化定位契约

先读规范源中的 `integrations/h5/bridge.md` 相应章节：容器与打开目标、公开信封、处理器、文档／授权生命周期和实际原生接线。消息级工作再读取同目录对应的 `camera.md`、`scan.md`、`map.md`、`files.md`、`sqlite.md`、`oss.md`、`share.md`、`system.md`、`location-cache.md` 或 `log-report.md`，并沿该契约读取实际调用的公共能力。

原 H5 消费方式和 SDK 接入差异按契约引用的依据核实。目录相对于工程采用的规范根，不表示这些完整协议已经随技能提供；找不到本次必需契约时明确缺口，不从旧技能或相近消息补造规则。

## 责任与交接

应用交付打开目标，容器管理展示与导航，通道管理来源、文档、授权和分派，处理器转换本条协议并调用公共能力。实现归 `integrations/h5/` 及实际应用接线，桥接不执行业务或智能体流程，也不复制相机、文件、地图等能力实现。

application 与 external 按已定义目标模式处理；普通外部链接不因使用同一 WebView 自动获得身份或设备桥。公开消息信封、字段和各消息结果码来自对应协议，不把通道成功、HTTP 成功或 SDK 调用完成统一解释为业务成功。

容器、文档调用周期与授权生命周期分别核对。相同 URL 或身份值不证明仍是原调用；凭据刷新、授权结束、重载、内部导航与历史恢复各按所属契约处理。处理器使用通道已绑定的上下文，不自行重建归属或另取当前页面替代原文档。

入站依据实际发送文档核实，结果交还原调用；投递等待期间发生的失效也要覆盖到实际脚本执行时刻。旧结果不进入新文档，失效回包不撤销已完成操作或触发处理器重跑。注入被 SDK 接受不等于 H5 已收到；没有协议依据时不新增送达状态、公共请求 ID、重发或全局串行队列。

确认由所属用途维护：H5 业务确认、设备选用和系统权限各有边界。桥接转换已确认的调用与结果，不对全部消息再加一层确认。脚本按协议进行序列化；诊断保留必要阶段与结果，不记录完整消息、令牌或带参数 URL。

## 验证

单条消息运行真实转换、结果映射和分派，替换外部能力；通道改动核对原文档、授权变化、迟到入站及投递、历史恢复和并行结果归属。原生文档来源、早期调用、脚本实际执行和真实 H5 收发另做平台接线验证，手工触发事件或生成脚本正确不能代替这些证据。
