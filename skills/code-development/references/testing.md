## 5. 规则执行与定向验证

技能负责读取依据和指导判断，工程检查负责能确定执行的规则。采用本规则的目标项目在 AGENTS.md 中维护简短入口：开发、测试、审查及交付时使用 code-development 取得相关规范，并指明所用版本；提供状态表时指明其位置及契约来源。详细规则通过技能或规范引用读取，不在 AGENTS.md 再复制一份。

工程接入时用现有 TypeScript、ESLint 和必要的静态分析检查类型、命名、导入方向、私有深路径、循环依赖及角色文件组织。使用 AST 区分类型声明、固定值、局部变量和资源，不用“遇到 const 全部搬走”的文本规则。固定值的业务含义、状态归属和副作用是否必要仍需依据契约审查。

新增单元同时具备可使用的公开入口、真实依赖接线及相应验证；不以有目录或编译成功作为功能完成依据。调整类型、常量或文件位置时按静态引用核对消费者，补充宿主、H5 协议与跨仓契约等非静态关系。

涉及外部依赖、持久化、异常转换、异步收尾、降级或恢复的功能变更，同时按日志与故障诊断（规范源相对路径：`ARCHITECTURE.md#721-日志与故障诊断`）核对日志责任及对应测试；复用已有记录，补齐本次改变或新增的失败路径。

本地优先运行该功能、适配及实际受影响组合的测试；系统合并和发布按工程既定 CI 验证。文件组织变化不要求默认重跑整个领域 Jest，也不能以只改类型或常量为由跳过实际语义影响。

测试质量遵循平台测试责任（规范源相对路径：`ARCHITECTURE.md#72-测试责任`），客户端测试组织与平台接线验证见[工程组织第 6 节](testing.md#6-分批重写与定向验证)。

验收证据对应本次提交、配置和实际检查层级。旧提交、测试替身或局部检查的结果不能代替当前合并、发布及真实环境所要求的验证。

技能本体、规范快照和模型评测在 `unif-portal-dev-skills` 仓库维护。规范快照由本项目的源文件生成，使用时按变更类别读取相应章节；源码阅读记录和 evals 不进入默认开发上下文。

## 6. 分批重写与定向验证

新实现按可独立使用的单元分批完成：根据目标契约编写代码、必要类型和常量、样式、定向测试及宿主接线，并接入实际需要的资源。旧 Portal 的组件、工具、适配和测试用于理解行为、逻辑结果及依赖约束，不通过复制后局部修补形成新实现。新测试按目标契约编写，旧测试仅提供行为样本与核对线索，不整套搬入旧用例、mock 和目录依赖。

现状行为与目标职责对照用于定位证据和检查依赖，不是文件复制清单，也不替代目标契约。具体执行批次说明实现哪些单元、依赖接到哪里、相关消费者怎样验证；所需契约齐备的单元可独立推进，无需等待无关领域或服务端契约完成。

测试按 `src` 中的归属在 `__tests__/` 下组织，文件名能定位被测能力或行为。一个功能存在多项独立能力时，分别运行实际受影响的测试文件；不把“所属模块相同”当作全部重跑的唯一理由。仅本测试使用的 fixture 与该测试放在一起，`_helpers/` 只收实际共用辅助。

| 改动 | 本地优先验证 | 必要的补充验证 |
|---|---|---|
| 普通工具或通用 hook | 对应输入输出、边界或生命周期测试 | 返回语义变化时验证实际消费者 |
| 基础组件 | 组件 props、展示、交互与中文提示 | 受影响的实际组合；布局、键盘、手势等补界面或设备验证 |
| 单个能力内部实现 | 该能力在替代外部依赖下的行为 | 受影响的适配、场景、H5 消费者与宿主接线 |
| 公共类型或常量 | 类型检查及生产方、消费者的相关用例 | 类型检查识别不了的码值、单位、默认值等语义需对应断言 |
| 宿主、初始化、共享 UI 状态 | 状态读写者与入口接线测试 | 多实例、切换、卸载及实际平台行为 |
| 原生 SDK 或平台适配 | 适配契约和相关上层调用 | 相应平台构建、真机；受影响的 Web 预览接入 |

通过明确测试路径和静态引用定位消费者。Jest 的相关测试选择可以辅助缩小范围，H5 协议、宿主注册、跨仓契约等关系另按对应设计补齐。发现选择范围不完整时扩大到相关组合或领域，并修正缺失关系；不能仅凭一个静态命令宣称影响已经覆盖。

引用外部组件库时，Portal 编写证明自身使用方式、组合及宿主接线的测试；组件库内部行为由其所属工程验证，Portal 不另行维护一套库内部测试。系统合并与发布继续执行实际工程配置要求的完整检查。

开发一个单元时，按本次变更选读相关代码归属规则、该单元契约、实现、直接依赖与对应测试。现状行为与目标职责对照、其他领域文档及模型评测仅在当前变化确实涉及它们时读取。目录和测试组织的收益在实际变更中按平台架构第 8 节（规范源相对路径：`ARCHITECTURE.md#8-成本与效果验证`）测量。
