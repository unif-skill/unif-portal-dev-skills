## 4. 原生能力与协议接入

先核对已采用的库与公开 SDK，再补真实缺口。摄像头、扫码、音频、权限和厂商分享由对应原生层实现；设备校准、系统设置和厂商回执分别核实，SDK 名称相同不代表能力一致。不存在的渠道或回执明确记录，不用系统分享或伪成功替代。

地图／POI 采用高德，统计与分享采用友盟；平台示例不改变提供方。分别依据[高德鸿蒙地图 SDK](https://lbs.amap.com/api/harmonyosnext-map3d-sdk/summary)及其搜索资料、[友盟鸿蒙 U-Share](https://devs.umeng.com/docs/128606/detail/2938160)与实际 SDK 核对。分享位置等业务输入由应用准备，不因此让 Camera／Chat／Umeng 新增地图调用。

HTTP、SSE、上传、业务结果与 H5 的字段及成功条件来自所属协议。协议转换保留业务码、原输入和结果语义，不补造身份或额外流程。H5 容器保持来源、主框架、当前文档、授权及重复消息保护；既有 H5 业务继续由原页面负责，迁移容器不自动授权改写 H5。

同一共同功能先确认行为契约，再识别 RN、鸿蒙和必要后端的真实消费者；实现可以先 RN 后鸿蒙，使用同一组验收案例并分别登记版本与差异。平台专属或局部修复只修改授权入口，不因代码同属一个库而扩大另一端行为。

SDK 文档及 Matrix 专项资料按所采用版本读取，它们提供 API 依据，不替代 Unif 的模块、身份、资源和业务契约，不自动授权安装工具、增加权限或接入外部服务。

外部技能与 Unif 规范独立维护；以工程采用清单及锁定记录确定可用资料，不自动恢复已归档技能。知识库快照、工具帮助或示例不能证明覆盖 API 26；缺少专项技能时直接查目标 SDK 与官方资料，已有有效依据的工作继续。


## 3. 契约与资源归属

共同输入含义、结果、事件、默认行为、取消、错误和资源所有权由所属契约定义。React 组件／Hooks 与 ArkUI 组件／控制器／Builder 分别表达，接口语法不强求一致；原生名称尚未定义时记录待定，不把 RN API 当鸿蒙 API。

共享纯逻辑和素材保持单一维护源。图标清单、SVG、颜色数据可从已有资产源生成两端产物；主题缩放、平台颜色处理、资源解析和设备适配留在所属平台。生成过程保留必要 SVG 校验、源修订与资源映射检查，不能在两端手改生成文件或各维护一份看似同名的源。

已有 Schema 或代码生成的业务契约继续使用其代码源，不另写字段全集。共享源码与共享运行期状态是两件事：账号、草稿、队列、媒体、设备会话和缓存仍归各实际拥有者。跨设备延续依赖现有明确服务契约，不通过公共包建立全局状态。

每次共同功能变更登记采用契约、RN 修订、对应鸿蒙库／应用入口、共同案例和两端证据；受影响消费者通过真实公开入口验证。没有消费者或独立职责时不提前新建公共包，必要的新包只承接已明确的能力，不能顺带搬走业务流程。
