## 3. ArkUI 状态与生命周期

Unif 新建 UI 优先采用目标 SDK 支持的 ArkUI V2 能力；既有组件或 SDK 互操作有约束时按官方规则选择，不为统一机制重写无关消费者。这是本项目采用方式，不扩大其他工程的版本与状态管理要求。

账号、角色、会话、草稿及操作的权威来源按[平台状态归属](../common/state.md#4-状态归属)确定。应用组装提供明确依赖，库不读取 Portal 私有 store、账号、路由或服务凭据。Chat 的受控输入不复制为库内业务状态，Camera／Scan／Umeng 的宿主与原生会话不保存为跨页面复用的全局默认实例。

异步结果按原操作、身份与宿主有效期接收，同名账号重新出现不证明旧操作重新有效。登录切换、会话切换、页面重建与前后台恢复遵守所属业务契约；页面离开不自动删除业务草稿、上传资源或已交付文件。

Camera 输出、Scan 借用图片、Chat 附件、Umeng 分享输入及应用上传按六库契约分别交接所有权。取消与 UI 关闭不等于底层停止读取；只回收当前流程拥有且已可释放的资源。释放失败、重复关闭与迟到回调保留真实结果及可诊断依据，原错误、权限、并发和无障碍保护继续有效。
