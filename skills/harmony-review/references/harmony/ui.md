## 2. 组件、主题与玻璃材质

Design 提供基础 UI、主题及平台材质适配，Icons 提供同源图标，应用通过公开入口组合并复用完整交互。颜色、字体层次、间距与图标来自已采用的 Unif 设计源；原生资源和缩放映射由所属库维护，应用不另建一份主题或重复缩放。

Unif 原生鸿蒙保持已确认的 RN 布局、内容、颜色体系、页面入口、操作及业务结果；玻璃效果使用目标平台适用的材质能力，视觉差异在可比条件下确认。局部材质修复不重排页面或改交互。

以下记录 Unif 在 API 26 的沉浸光感采用边界，受设备能力、系统设置及组件支持范围影响。系统材质、普通模糊和透明背景分别处理；未支持表面以可读性、可操作性和已确认视觉为准，不伪称系统效果，也不自动引入新权限或运行框架。

采用时先核对以下官方约束，再在目标 SDK 与真实宿主验证；规则不授权将现有页面改造成系统模板：

| 核对项 | 实施要求 |
|---|---|
| SDK 与开启层 | target 至少为 26.0.0；应用级元数据只在 entry 模块生效，HAR 文档说明接线但不能替消费应用作全局选择；组件级入口按实际组件核对 |
| 组件所在区域 | 指定弹窗／菜单等接口及 Slider、Toggle、Select 可在全页面生效；其他组件限官方列明的 Navigation／NavDestination 标题栏、横向 Tabs 底部 TabBar 等区域，不能将普通自定义卡片视为受支持载体 |
| 材质与系统状态 | 区分应用配置、设备支持、材质等级和系统效果设置；以所用 SDK 实际提供的 uiMaterial 查询及组件接口为准，不以配置已开启证明运行有效 |
| 效果取舍 | 保留 Unif 内容、尺寸、圆角和操作；不支持的位置记录真实降效与差异，不能移动控件、改变导航或添加权限来获得效果 |

每个采用表面记录“Unif 控件／场景 → 原生载体和位置 → SDK 入口及支持条件 → 降效处理 → 设备证据”。Design 维护材质适配，Camera／Scan／Umeng 消费其公开能力，不各建一份材质检测和主题状态；平台载体确有不同限制时按该表面分别处理。

Unif 已确认的内容和操作在深色、大字号、无障碍、键盘及系统降低材质条件下仍须有效；亮色静态截图不能替代相关验收。各组件负责自身短暂交互，业务状态与请求由应用拥有者负责。
