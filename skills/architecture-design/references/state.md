## 4. 状态归属

| 状态或数据 | 维护方 | 使用原则 |
|---|---|---|
| 客户端草稿 | Portal 对应业务交互 | 入口读取和修改同一份草稿；模型只能基于必要片段提出类型化理解结果 |
| 选择、待确认内容和提交交互状态 | Portal 对应场景 | 状态推进由场景代码处理，入口展示其结果 |
| 当前任务线索与必要实体引用 | Portal 当前交互 | 用于选择任务内容及理解用户指代，不作为全局业务事实 |
| 会话原文、语言上下文和模型轮次 | Agent 会话 | 保存历史不等于每次模型调用加载全部历史 |
| 跨会话记忆 | 公用记忆服务 | 按归属、访问权限和适用范围读写；领域维护内容语义，调用方只持有所需快照 |
| 查询结果 | 业务系统提供事实，Portal 持有查询快照 | 页面、场景和必要的模型数据投影共同消费同一查询功能 |
| 最终业务事实 | 现有业务系统 | Portal 展示业务回执或查询结果；Agent 会话不能作为业务状态的判定依据 |
| 设备产物 | 交付前由设备功能管理，交付后由接收方管理 | 保留、转存和释放责任由使用场景明确 |

客户端交互状态与业务状态分别表达。请求已发送、界面关闭或模型声称成功，都不能代替业务事实。业务响应应接收至所属请求和交互，不能因入口切换而更新其他任务。

实体引用的范围和传递责任由领域或场景明确。需要跨任务承接时，使用类型化输入显式传递必要引用；其他交互的变化不能通过共享对象自动改写已有草稿或业务记录。候选数据、明确的交互选择与最终业务事实不能混为一份状态。

记忆不保存另一份权威草稿、当前选择或业务状态，也不将任务指令变成可由历史内容覆盖的规则。当前明确输入与交互引用按所属契约处理，历史记忆只提供有来源的线索；涉及业务实体时，仍须按当前业务契约核实。

### 4.1 持久化、恢复与业务唯一性

修改持久化、恢复、跨设备同步或业务记录创建时，按本次涉及的状态核对以下约束：

- 修改前逐项确认内容、标识、索引和关联的权威来源、唯一性范围及全部创建入口。按契约区分设备状态、客户端快照与服务端记录；纯设备状态继续由设备维护，不因持久化而上移服务端。
- 本地缓存缺失、过期或丢失不能证明服务端记录不存在。恢复既有业务目标须核实其权威标识和关联；内容已同步不证明决定复用或创建的索引、关联已同步，也不能据此宣称跨设备行为完整。
- 有服务端业务唯一性要求的记录，由所属服务端按完整身份和业务键原子查找或创建，并以数据库约束保护唯一性；所有相关创建入口共用该契约。客户端缓存和进程内锁不能承担跨客户端唯一性，查询或创建失败不得自行生成替代记录。
- 验证按实际影响分层：客户端用例覆盖缓存缺失、旧值、重启后的恢复及身份切换；服务端验证并发和数据库唯一性。涉及跨客户端唯一性时，用两个不共享本地状态的独立客户端检查各入口返回的标识、关联与记录数，并覆盖失败不创建和身份隔离。仅内容恢复或单客户端通过不足以证明跨设备唯一性；未影响这些行为的普通 UI 修改不触发整套验证。

### 4.2 异步控制与状态交接

修改异步处理、状态交接或资源收尾时，区分已确认／已采用的业务事实、执行与等待控制、资源生命周期及界面投影，核对各自所有者和有效转换。

- 暂停、取消或销毁只收尾本方仍拥有的执行与资源，不能因调用仍在等待回执而撤销已确认或已交接的事实。等待结束不单独证明业务成功，等待中断也不单独证明业务撤销。
- 交接后的未完成项由接收方的既有流程承接，发送方不另造一套失败状态。真正的业务撤销或回退由明确业务动作及权威结果决定，控制状态与界面按该结果更新。
- 验证真实状态所有者与消费者在中断和完成／交接交错、迟到回执、关闭及恢复时的不变量，不能只断言等待已结束。按实际影响检查事实、执行与资源；普通 UI 或纯设备状态修改不扩大到无关业务链路或跨设备测试。
