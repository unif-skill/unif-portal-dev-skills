## 2. 目录与文件归属

服务代码包根目录保留包标识和应用入口，例如 `__init__.py` 与 `main.py`，既有部署入口 `app.py` 可以沿用。配置、错误和其他实现按职责进入目录。仓库根的 README、AGENTS、公开契约、依赖锁及部署配置保持各自工程角色。

| 目录 | 承担内容 |
|---|---|
| api | 路由、认证交接、请求校验、HTTP/SSE 编解码和传输错误映射 |
| config | 服务配置的读取及校验；配置不成为业务状态 |
| errors | 异常类别、安全诊断、稳定错误码及面向调用方的错误表达 |
| runtime / execution | 运行协调、预算、取消、结果采用和资源收尾；按所属服务选用 |
| understanding | 任务选择、来源和动作关系校验、类型化结果整理 |
| prompts | 通用与任务指令，以及当前任务的确定性装配 |
| context | 模型输入投影、多模态消息和输入预算计算 |
| model | 模型供应商请求、技术 Schema 适配和响应解析 |
| integrations | OSS、解析服务、领域服务等外部接入 |
| attachments / memory 等能力目录 | 所属能力的规则、投影与操作；有真实需要时设置 |
| persistence | 连接、事务和所属数据操作 |
| contracts | 已生成契约的加载和校验、必要的 JSON 值处理 |
| generated | 按同源契约生成并锁定来源的产物 |

上述目录按已有职责选用，不要求每个服务具备全部目录。公共定义按语义归入所属模块，不建立收纳无关代码的通用工具目录。单个提示词可以独立成文件；普通辅助函数留在其所属职责文件内。


## 3. 公共入口与依赖

应用入口组装具体依赖并管理启动和关闭，路由挂载接收所需应用、配置与执行对象。能力、模型及持久化实现不反向导入应用入口。底层模块不依赖 HTTP 路由或上层执行器。

跨模块使用稳定公共入口；包的 `__init__.py` 只导出需要的接口，不创建连接、运行任务或安装路由。包内使用明确的具体模块，避免同包公共入口反向加载正在初始化的模块。公开对象的定义仍由一个文件持有。

模型供应商适配只负责技术请求和响应，不包含下单、拜访等领域流程。任务选择和结果校验不依赖模型客户端。提示词模块维护文字和装配，不承担任务路由、外部调用或副作用。记忆检索需要的任务线索复用独立的任务选择代码。

消费者通过参数提供外部依赖，测试可替换相同边界。目录归组不引入动态扫描、通用注册中心或只为转发而存在的执行层；实际需要多实现时，再明确选择和组装接口。
