## 6. 验证与交付

验证覆盖实际被改的生产代码及消费者。等价移动复用原有行为回归，补齐确有需要的资源导入、依赖边界与入口接线检查；功能变化按契约增加能复现问题的测试。结构检查进入既有测试或 CI，检查真实依赖与根目录职责，不用代码行数作为统一合格阈值。

涉及外部依赖、持久化、异常转换、异步收尾、降级或恢复的功能变更，同时按[日志与故障诊断](../common/verification.md#721-日志与故障诊断)核对日志责任及对应测试；复用已有记录，补齐本次改变或新增的失败路径。

一次结构重构至少核对公共入口、隐式模块字符串、测试替换点、子进程启动、Docker 拷贝、生成资源路径和现行文档。历史执行记录保留当时路径与证据，不批量改写历史。

离线测试、真实进程 HTTP/SSE、真实身份/业务/模型、镜像构建、部署及最终验收分别记录。合成输入和替代模型能验证接线与协议，不能证明真实模型理解或业务成功。涉及真实模型、额外付费或外部变更时遵循当前用户授权。

后端相关技能从本规范取得对应工程规则，按本次任务选读所需资料；独立使用不要求安装其他阶段技能。技能正文、来源同步、静态校验、行为评测、发布与安装各自保留实际证据。自有库常规版本保持首位不变，大版本变更需明确授权。
