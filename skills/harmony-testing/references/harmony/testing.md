## 5. 验证与交付

测试预期来自当前契约。纯逻辑验证输入、输出和边界；组件验证公开输入、事件、主题与实际消费者；涉及平台的验证采用当前工程真实的 Hvigor、Hypium／设备测试或等效工具，不把 Jest 和 Node 运行结果当作原生运行结果。命令从所采用工程核实，不在规范中编造通用任务名。

| 证据层 | 可以证明的范围 |
|---|---|
| 源码、类型及依赖检查 | 公开入口、静态依赖和可检查的约束 |
| 纯逻辑与替身测试 | 测试实际覆盖的算法、状态交接及副作用 |
| HAR 产物检查与宿主构建 | 导出、包内容、资源、依赖和被真实消费工程编译接入 |
| 模拟器／真机运行 | 对应环境实际执行的交互与原生行为；硬件、权限、厂商 SDK 依证据另验 |
| 真实业务与最终验收 | 指定场景的请求、权限、业务回执与用户确认 |

共享核心需验证每个采用目标的类型边界、产物和运行语义；共享算法测试不替代设备标定、资源释放或应用接线。HAR 不能单独安装，空工程或一个成功构建不代表库功能完成。未签名 HAP 不作为已安装运行证据。

界面在相同数据、窗口尺寸、主题、字体、键盘与系统材质条件下对照；无障碍、可点击范围和必要降效表现同样验证。报告采用修订、命令、结果、警告及未验证项；提交、CI、安装、发布、设备和业务验收分开，不由技能文字宣称静态门禁已在目标工程生效。
