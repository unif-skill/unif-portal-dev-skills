# Design 系统开发与接入

使用或修改 @unif/react-native-design 的基础 UI、主题字体、组件族或 UI 宿主时读取。源码维护采用库内 docs/DEVELOPMENT.md 指定的工程规范。单个组件的使用先核对其当前公开类型和文档。

## 按变化定位契约

以下路径相对于工程采用的规范根目录，不是其他技能的私有文件，也未随本技能分发。规范入口为 `libraries/react-native-design.md`，下列文件均位于 `libraries/react-native-design/`：

| 本次变化 | 文件 |
|---|---|
| 定位已有公开组件与函数 | `units.md` |
| 主题、字体、图标与显示基础 | `theme.md` |
| 输入、Textarea 与 Chat Composer 接线 | `input.md` |
| Thumbnail、图片及头像内部共享 | `media.md` |
| 进度、百分比文字与反馈动效 | `feedback.md` |
| 按钮、选择及通用组合 | `interaction.md` |
| Confirm、Toast、Modal 接管与释放 | `hosts.md` |
| 库内依赖、验证与消费交付 | `verification.md` |

目录是定位入口，不要求一次读取全部组件。目标扩展与已发布 API 分别核对；完整参数、类型和依赖版本由采用的库源码及生成文档维护。

## 开发边界

Design 提供通用基础 UI、显示基础及真实共用的组件族支撑。聊天消息和输入组合归 Chat，业务值、路由、确认有效性与提交归 Portal 场景；通用组合组件不因原目录名称含 business 就具有领域职责。

消费者使用包的公开入口；库内部复用明确的组件族支撑，不深读其他单元的私有样式或状态，也不回读包根造成循环。内部共享不强制公共导出，不因契约独立而复制已有实现或拆成多个包。

主题和字体由实际 Provider 及公开读取接口交接，应用负责设置与持久化。应用字体系数在所属出口缩放一次；文字 metric、布局尺寸与系统文字缩放保持各自语义，不重复乘倍数或将控件、图标整体等比放大。

受控输入将值交回调用方，组件只管理必要焦点、展开或显示状态。ref 只提供已有或明确需要的 UI 操作。图片加载和组件卸载不接管业务附件生命周期；Confirm 返回用户选择，不表示业务提交成功。

样式、固定值和类型按本单元及所采用库契约组织，构建与生成文件沿用工具约定。新功能先核对现有组件和公开接口是否足够，不以统一导入为由再包一套同名组件。

## 验证

单元变化验证组件及已识别消费者，主题、共享支撑或公共类型变化再扩大到实际使用者。覆盖中文、大字号、主题、可访问交互以及确有影响的原生／Web／宿主接线；纯数值或 mock 测试不代替真实文字测量、键盘和图片行为。
