## 5. 自然语言任务与上下文

### 5.1 通用指令与任务模块

接入自然语言入口的领域，以任务模块维护专属指令、代码定义的输入输出契约及独立评测样本；领域身份、共同术语和职责边界放在通用指令中。具体任务清单由领域文档维护。

| 内容 | 范围 |
|---|---|
| 通用指令 | 所属领域身份、共同术语、职责边界、引用和未知信息的处理原则 |
| 任务专属指令 | 当前任务的意图、参数、指代、修改含义及必要澄清 |
| 任务契约 | 本任务能够接收和输出的类型化内容 |
| 任务评测 | 本任务的意图理解、参数提取、引用、澄清和输出正确性 |

任务指令负责语义理解。用户选择、设备操作、流程推进、确认和业务提交由 Portal 代码完成。业务规则和最终权限判定不重复写入任务指令。

### 5.2 上下文装配

一次模型调用按需装配：

```text
通用指令
+ 当前任务指令
+ 当前任务需要的契约
+ 必要用户输入和会话上下文
+ 本次确有需要的记忆资料（覆盖范围与字段按所属契约）
```

运行代码按已确认的任务选择规则装配同源指令与契约；认证、来源、附件、轮次与取消由统一入口承接。普通聊天、显式任务与输入补充的选择和交接见运行契约的领域和任务选择（规范源相对路径：`runtime/agent-runtime.md#4-领域和任务选择`），具体准备及续推理入口由所属场景契约维护，不在平台正文另定供数流程。

超级智能体选择助手、领域助手识别业务，分别按当前有效契约执行。选择依据完整语义与已有上下文，不按关键词分派；助手归属不明由超级智能体澄清，领域业务缺项由对应助手澄清。内部目录整理不新增模型调用或改变提示词语义。正常轮次不设固定总时长或调用次数上限，保留输入范围、网络故障等待和实际用量记录，不自动重试或增加回答润色调用。

单一任务与组合任务的指令范围由所属契约分别维护，当前调用按该范围装配。营销的任务集合、候选绑定、有限分析和仅回复边界见营销任务装配（规范源相对路径：`domains/marketing/agent-runtime.md#2-任务装配`）。用户明确表达的先后关系可以被提取，实际执行顺序、交互和确认由 Portal 已定义的场景组合承担，模型不能自行决定未明确的执行关系。

模型只取得原请求所需的实体引用、草稿、原文与历史投影；目录和记忆的覆盖范围、字段与输入预算按所属任务契约确定。不得静默截断契约要求的完整候选，也不加载无关历史、领域工具或业务凭据。超级智能体仅向模型提供当前已接入且允许调用的助手委派能力；领域助手按所属契约交付结果，不因被接入而获得业务 CRUD 权限。

记忆读取由所属场景契约明确调用方和时机，先执行身份、访问与适用范围校验，再按该契约的覆盖要求和字段投影交接。完整集合、分页及子集如实标识，不能用平台通用条目限制替代具体契约或把截断结果冒充完整。记忆作为用户资料，不作为系统指令；本节不默认增加查询、每轮全量读取或额外模型回合。详细交接见记忆能力（规范源相对路径：`capabilities/memory.md`）及领域专题。

### 5.3 查询与模型续推理

普通业务查询由 Portal 发起并直接展示。用户选择、确认和确定性的结果展示由代码完成。

后续推理需要查询资料时，先由所属场景契约明确请求、调用方、来源、取消和采用边界，并核对已有接线；平台不默认由 Agent 索取数据或由 Portal 供数回交。尚未接线的设计不能作为现行入口，已退役的协议也不能因本节的通用说明恢复。资料准备复用所属查询能力，投影、覆盖范围和输入预算按该场景契约处理，有限候选不作为全部数据。

Portal 可以通过普通代码记录必要的结构化交互或业务结果，不要求模型再生成一轮确认或总结。

本节的业务数据查询与记忆读取分别遵循各自边界：取得所属场景授权的调用方通过公用记忆 API 读取，不因此获得直接访问业务系统的职责。Portal 使用记忆时复用同一记忆服务，不能在客户端维护另一套存取规则。

### 5.4 契约与评测同源

模型使用的 Schema 从代码契约取得。类型、运行时校验与模型 Schema 的语义保持同源，不在提示词中另行维护字段定义。具体技术实现由后续模块设计确定。

各任务分别维护评测样本，另保留必要的任务识别、任务切换和复合意图样本。评测数据用于开发验证；只有必要的少量示例进入任务指令。

修改单个任务指令时，验证该任务及相关共享样本。通用指令、共同术语、共享契约或装配方式变化时，扩大到受影响任务。结构合法、语义准确和业务合法性分别验证，不能互相替代。
