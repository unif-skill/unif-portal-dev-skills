## 3. 常量、类型、变量与文件拆分

文件角色、命名与拆分遵循工程已采用的通用规范。以下入口保留 Portal 特有约束，供现有组件库契约引用；库构建、原生接线和生成文件继续遵循各自工具约定。

### 3.1 应用配置与环境文件

Portal 的应用配置入口保留 env.ts、brand.ts 等实际用途，不因文件整理改变配置来源或读写责任。

Portal 的既有环境按目标分工：`.env.unif.debug` 用于本机开发服务（如本机 Docker Agent），`.env.unif.beta` 用于测试服务，`.env.unif.prod` 用于正式服务。同一用途复用对应入口，不按操作者或设备名称另建完整环境副本；新增独立环境须有本次需求或有效契约依据。构建目标由实际环境选择决定，不因采用 Release 构建就切换为正式服务；`ENV` 等参与签名或运行分支的字段按实际消费者支持的值填写，不从文件后缀推导。

使用 `.env` 作为 SDK 默认加载文件时，它承接本次选定的环境配置，保持文件中的变量和值一致，不另作独立环境维护。已有启动入口支持临时覆盖时，另外核对覆盖来源和实际生效值。核对 `ENVFILE`、SDK 临时选择和原生构建入口的实际加载结果；临时设备参数由已有启动入口或仓库外个人配置承接，个人地址和凭据不写入技能或公共规范。
