# 图标消费与源码维护

## 使用已有图标

先按采用版本的导出与图标目录确认名称，再选择包根命名导入或已声明的正式子路径。构建器决定命名导入的最终包体积；不要把子路径或 tree shaking 当成未经验证的体积保证。

宿主安装和原生接线按 react-native-svg 与实际 RN/Expo 版本核对；普通图标使用不引入 Design 运行时。颜色、尺寸、描边及透明度按公开类型传入，样式修正不重画整个图标或增加同义包装。

## 新增或修改图形

1. 查 docs/DEVELOPMENT.md 和 website/docs/contributing.md，确认唯一 SVG 源、命名清单、已有风格与消费者；从当前库文档取得生成目标和命令。
2. SVG 几何、绘制属性、名称或生成规则变化时，核对采用该源的 RN 与鸿蒙产物。只改 RN 组件行为时，判断鸿蒙契约是否受影响，不将生成命令当作行为迁移。
3. 修改所属源和清单，保留既有严格校验；由生成器更新组件、公开出口和消费者清单，不直接编辑派生文件，也不复制第二份手维 SVG。
4. 在授权范围内同步受影响目标，执行只读一致性检查。目标仓或生成依据缺失时明确列为待同步／未验证；用户限定单端修改时保留该边界，报告另一端影响，不自行扩展修改范围。
5. 同步实际受影响的网站分类和示例，检查各端公开消费。提交、推送及发布按交付授权推进；生成器执行不包含这些操作。

## 验证

check:icons 核对 RN 源与产物一致；跨端维护还须按当前库文档检查鸿蒙仓的实际生成产物。临时生成成功不能代替目标仓无漂移。生成器、公开组件、属性透传、颜色/几何及可访问性各用现有测试。公共出口变更验证类型、打包与真实消费者。读到开发命令后按当前脚本执行，不冻结旧依赖或命令参数。

原生宿主、Web 渲染及设备展示分别取证；纯 JS 不代表所有 RN/SVG 组合都已验证。目标架构按工程采用的 libraries/react-native-icons.md 或本库明确指定契约取得，不能把目标设计当已发布 API。
