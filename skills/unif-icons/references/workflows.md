# 图标消费与源码维护

## 使用已有图标

先按采用版本的导出与图标目录确认名称，再选择包根命名导入或已声明的正式子路径。构建器决定命名导入的最终包体积；不要把子路径或 tree shaking 当成未经验证的体积保证。

宿主安装和原生接线按 react-native-svg 与实际 RN/Expo 版本核对；普通图标使用不引入 Design 运行时。颜色、尺寸、描边及透明度按公开类型传入，样式修正不重画整个图标或增加同义包装。

## 新增或修改图形

1. 查 docs/DEVELOPMENT.md 和 website/docs/contributing.md。当前源位于 src/svg，名称清单为 scripts/icon-manifest.json；先核对同义图形、现有风格与消费者。
2. 修改所属 SVG 和清单，沿用现有严格校验。禁止脚本/外部资源、名称冲突与非法几何输入的保护保留。
3. 执行 package.json 中的 generate，从源重新生成 src/icons、公开出口及已有消费者清单；不手改派生文件。
4. 同步实际受到影响的网站分类和示例，检查新增图标在 example 与 Website 的公开消费。发布与安装按交付授权推进。

## 验证

check:icons 核对源与产物一致；生成器、公开组件、属性透传、颜色/几何及可访问性各用现有测试。公共出口变更验证类型、打包与真实消费者。读到开发命令后按当前脚本执行，不冻结旧依赖或命令参数。

原生宿主、Web 渲染及设备展示分别取证；纯 JS 不代表所有 RN/SVG 组合都已验证。目标架构按工程采用的 libraries/react-native-icons.md 或本库明确指定契约取得，不能把目标设计当已发布 API。
